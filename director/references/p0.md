# P0：节目策划

## 读取时机

在 `status --workspace <节目目录> --program <program-id> --stage p0` 返回 `stageId: p0` 时完整读取本文件；P0 普通继续、`--revise-program` 修订、恢复和候选接纳都使用本文件。只使用当前工作单和 `programForm / planningBasis` 直接需要的现行输入。

## 参考节目

显式`historical-explainer / video-led`按plan-program的video-led方法整体阅读、拆合分集，形成完整故事策划、可参考的叙事方法与材料定位；原始底稿交给P1取材，P1自主组织讲述。不默认执行整套书目反推；实际补充材料与NotebookLM的使用由plan-program按需要决定；单集与系列共用同一方法。接纳及修订仍走原P0入口。

## 普通流程

- P0 按 `programForm` 只签发一个人工智能工作单：综合解说（`historical-explainer`）用 `plan-program`，历史纪录片用 `plan-historical-documentary`；具体策划与材料闭环只服从被选责任包 Skill。
- 综合解说在P0确定`explainerType`：用户指定时在同一`request.yaml`记录`general`（通用）或`current-affairs`（时政），未指定时由plan-program按任务与材料判断。最终值写入`program.yaml`，Engine投影到单集任务供P1使用；P1不重新分类。该类型独立于策划材料入口、视觉、封面与片头，纪录片不使用。
- 每个节目必须在`program.yaml#openerTemplate`保存一个片头选择，独立于`programForm`。首次未指定时使用目录标记的默认片头；两类节目都可按用户要求选择其它片头。
- 当前作者在原委托和`planningBasis`内完成方向取舍，再按被选包取得最小充分材料。综合解说可用公开正文、本地材料、参考节目或NotebookLM；纪录片保留原书目反推和NotebookLM方法。关键材料缺失时保留同一候选，继续独立可做的搜集；确需用户提供的书交清具体需求。目录、书评、摘要或来源ready不能代替实际正文。使用NotebookLM时保留真实编号并等待必要来源就绪；远端未知只恢复原对象。入口无效或指定书源框架站不住时按原边界停止。
- 不从自由文本猜入口，只按工作单 `outputContract` 提交唯一节目候选，不提交调查过程、材料说明、确认记录或第二份策划。`program.yaml` 是唯一真源；接纳后只以其中列出的剧集建立或更新单集任务，未列入的旧剧集目录保留但退出当前节目。

## P0 修订

用户明确要求调整现行 P0 时，使用一次：

```text
next --stage p0 --revise-program
```

已经接纳时，该入口把当前 `program.yaml` 交给现行 `programForm / planningBasis` 选中的 P0 作者，只重做用户修改真正影响的策划与材料判断；新候选接纳前当前节目和单集任务继续有效，接纳时重新投影现行单集任务，退出节目的旧目录保留但不得继续生产。已有修订请求沿同一对象恢复；修订接纳后停止在 P0，不自动进入 P1。

P0尚未接纳或正在修订时，用户中途改要求，先结束当前P0写入，把明确的新要求更新到同一节目`request.yaml`，再执行上述`--revise-program`。同节目、同形式的新委托替换旧工作单输入；原候选在同一路径保留为待修订草稿，底稿、来源及远端编号保留。Engine在原`_work`保存被替换的旧单和草稿供恢复，不把它们作为另一份生产输入。换单中断时重复同一显式命令续完；要求未变时保留当前单与候选。作者必须读取新工作单及当前草稿，按新要求修正实际受影响部分，再按原合同提交，换单本身不代表新要求已经完成。没有正式`program.yaml`时从当前草稿继续，不要求先接纳旧方案；普通next不自动换单。

用户要求改解说类型时，先更新同节目`request.yaml#explainerType`，再沿上述P0修订入口接纳最终选择；只修正实际受影响的内容与材料，不在P1临时改选。旧策划缺少类型且需要新写正文时，也由该入口补齐。已完成节目不因新增类型字段自动重做。

用户随时要求换片头时，同样使用现有`--revise-program`入口，仅更换节目配置里的`openerTemplate`，不重做未受影响的策划或材料；未明确更换时保留现行选择。P1和P4随后读取同一选择，现有片头文字不适合新模板时通过P1 `--revise-opener`只修片头，不重写正文，也不因换片头清除配音和正文素材。接纳配置后仍停在P0，不自动生产下游。

## 交互与完成

- P0方案和包内步骤不另设审批点；向用户交付具体找书需求、等待关键书籍是正常材料协作，不能以连续执行为由跳过。执行中简要汇报实质进展，阶段完成后区分材料正文已核对与机器来源已就绪，不把接纳通过称为逐集成稿质量已证明。
- 委托使用 `schemaVersion: 3.0` 并必须显式选择 `programForm` 与 `planningBasis`。历史解说为 7.3 版、历史纪录片为 8.1 版；两种形式都分别选择正片Visual和封面Cover，单集任务只是 Engine 投影。
- 返回 `stage-complete` 后停止，不自动进入 P1。
