# P0：节目策划

## 读取时机

首次创建节目委托，或 `status --workspace <节目目录> --program <program-id> --stage p0` 返回 `stageId: p0` 时完整读取本文件；P0 普通继续、`--revise-program` 修订、恢复和候选接纳都使用本文件。只使用用户本次明确的委托，以及当前工作单和 `programForm / planningBasis` 直接需要的现行输入。

## 首次委托

用户已明确要求创建节目并开始P0，且指定的仓库外节目目录尚无`request.yaml`与`program.yaml`时，由Director建立目录，读取`scripts/request.example.yaml`和`contracts/program-request.schema.json`，将本次选题、约束及明确选择写入同一`request.yaml`；不要求用户手工编辑JSON。节目编号使用合法英文短名，不替用户预写策划结果。节目形式须来自用户明确表达，不从题材猜测。综合解说只走先检索节目这一条路线：只有主题或视频URL时，委托用`topic-led`，URL及用户要求写入idea/constraints，由P0取得材料；已有本地参考清单才用`video-led`，指定书用`book-led`登记原件身份，均不让用户另选创作路线。纪录片仍按原规则明确策划起点。实际文件及摘要不能用占位值。已有委托或节目直接复用，修改沿下文修订入口；准备委托后立即回到原`status → next`，P0完成后仍停止，不扩展到P1。

## 综合解说统一取材

所有选题先由plan-program检索同题或相近节目，有合适节目就下载、完整理解并融合二创，以文献补足；无合适节目才独立策划。用户给的视频和书是初始材料，不绕开此顺序。原始底稿沿实际采用的材料交给P1取材，AGY按完整策划自主讲述；不另设流程、书单或NotebookLM义务。检索与获取失败不冒充无节目。

## 普通流程

- P0 按 `programForm` 只签发一个人工智能工作单：综合解说（`historical-explainer`）用 `plan-program`，历史纪录片用 `plan-historical-documentary`；具体策划与材料闭环只服从被选责任包 Skill。
- 综合解说在P0确定`explainerType`：用户指定时在同一`request.yaml`记录`general`（通用）或`current-affairs`（时政），未指定时由plan-program按任务与材料判断。最终值写入`program.yaml`，Engine投影到单集任务供P1使用；P1不重新分类。该类型独立于策划材料入口、视觉、封面与片头，纪录片不使用。
- 每个节目必须在`program.yaml#openerTemplate`保存一个片头选择，独立于`programForm`。首次未指定时使用目录标记的默认片头；两类节目都可按用户要求选择其它片头。
- 当前作者在原委托目标与限制内完成方向取舍，再按被选包取得最小充分材料。综合解说可用公开正文、本地材料、参考节目或NotebookLM；纪录片保留原书目反推和NotebookLM方法。关键材料缺失时保留同一候选，继续独立可做的搜集；确需用户提供的书交清具体需求。目录、书评、摘要或来源ready不能代替实际正文。使用NotebookLM时保留真实编号并等待必要来源就绪；远端未知只恢复原对象。实际输入无效时按原边界处理；纪录片的指定书源框架责任不变。
- 不从自由文本猜入口，只按工作单 `outputContract` 提交唯一节目候选，调查日志、找书过程和确认记录不作为额外成果；本集故事、材料定位和适用的用户要求仍须写入正式策划，不另立第二份。`program.yaml` 是唯一真源；接纳后只以其中列出的剧集建立或更新单集任务，未列入的旧剧集目录保留但退出当前节目。

## P0 修订

用户明确要求调整现行 P0 时，使用一次：

```text
next --stage p0 --revise-program
```

已经接纳时，该入口把当前 `program.yaml` 交给现行 `programForm` 选中的 P0 作者，只重做用户修改真正影响的策划与材料判断；新候选接纳前当前节目和单集任务继续有效，接纳时重新投影现行单集任务，退出节目的旧目录保留但不得继续生产。已有修订请求沿同一对象恢复；修订接纳后停止在 P0，不自动进入 P1。

P0尚未接纳或正在修订时，用户中途改要求，先结束当前P0写入，把明确的新要求更新到同一节目`request.yaml`，再执行上述`--revise-program`。同节目、同形式的新委托替换旧工作单输入；原候选在同一路径保留为待修订草稿，底稿、来源及远端编号保留。Engine在原`_work`保存被替换的旧单和草稿供恢复，不把它们作为另一份生产输入。换单中断时重复同一显式命令续完；要求未变时保留当前单与候选。作者必须读取新工作单及当前草稿，按新要求修正实际受影响部分，再按原合同提交，换单本身不代表新要求已经完成。没有正式`program.yaml`时从当前草稿继续，不要求先接纳旧方案；普通next不自动换单。

用户要求改解说类型时，先更新同节目`request.yaml#explainerType`，再沿上述P0修订入口接纳最终选择；只修正实际受影响的内容与材料，不在P1临时改选。旧策划缺少类型且需要新写正文时，也由该入口补齐。已完成节目不因新增类型字段自动重做。

用户随时要求换片头时，同样使用现有`--revise-program`入口，仅更换节目配置里的`openerTemplate`，不重做未受影响的策划或材料；未明确更换时保留现行选择。P1和P4随后读取同一选择，现有片头文字不适合新模板时通过P1 `--revise-opener`只修片头，不重写正文，也不因换片头清除配音和正文素材。接纳配置后仍停在P0，不自动生产下游。

## 交互与完成

- P0方案和包内步骤不另设审批点；向用户交付具体找书需求、等待关键书籍是正常材料协作，不能以连续执行为由跳过。执行中简要汇报实质进展，阶段完成后区分材料正文已核对与机器来源已就绪，不把接纳通过称为逐集成稿质量已证明。
- 委托使用 `schemaVersion: 3.0` 并必须显式选择 `programForm` 与 `planningBasis`。历史解说为 7.3 版、历史纪录片为 8.1 版；两种形式都分别选择正片Visual和封面Cover，单集任务只是 Engine 投影。
- 返回 `stage-complete` 后停止，不自动进入 P1。
