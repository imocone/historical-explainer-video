# P3：视觉创作

正文统一按章节组织，分为讲解章节和全画幅章节，沿用`templateRun`（TR）身份。导演方案整集接纳；后续正文按章节派工、提交、接纳和统计进度。导演切全画幅镜头并交接讲解章界与观看任务。讲解作者在同一工程的全章粗排中决定章内切镜。

## 读取时机

在 `status --workspace <节目目录> --episode <epNN> --stage p3` 返回 `stageId: p3` 时完整读取本入口。普通创作、返工、恢复和接纳都从这里进入；再按当前动作与首个消费点，完整读取下表点名的章节，不默认通读其它模式。

| 当前动作／消费点 | 按需完整读取 |
|---|---|
| 普通整集创作：导演初稿与模板归属形成后、正文Author之前 | [切分审计与一次集中修正](p3-actions.md#独立步骤切分审计与一次集中修正) |
| 本次讲解初制全部交回后 | [讲解逐段精修](#讲解逐段精修) |
| 已接纳导演计划的局部修订或明确撤销该修订 | [导演局部修订](p3-actions.md#导演局部修订) |
| 明确重做现行P3正文 | [正文重设计](p3-actions.md#正文重设计) |
| 明确只重作已接纳的部分历史引文 | [已接纳历史引文定点重作](p3-actions.md#已接纳历史引文定点重作) |
| 同次任务恢复 | 本入口及原动作的方法；按当前工作单、原请求和已完成进度续接，不改模式或补开一轮 |

已在当前上下文完整读取且未变化的方法不重复加载；首次使用、变化或上下文缺失时完整补读对应章节。逐单位创作只读当前工作单投递的正式资源；本表只路由既有动作，不新增步骤或扩大委托范围。

## 执行进度与恢复

沿用总入口的会话计划，用原生`update_plan`显示`status.queue`顶层节点；`author.units`为`null`时显示“数量待确定”。整集生产另列“切分审计与一次集中修正”：全画幅分镜和讲解章级交接形成并核对时窗后、正文Author之前，执行`direct-episode`第五步。

首次计划将该项列为待办；恢复时继承实际进度。进入切分审计时将其标为进行中，完整审阅后在当前会话留下实际范围、结论和具体意见，零问题也明确范围与结论。原修正动作读取这些意见，沿同一会话计划续接，不另写审计文件或节目状态。

审阅结束与修正完成分别说明，满足该方法的结束条件才将整个条目标为完成。未审完、未列齐问题或修正未完成时，留在本步骤继续或报告真实阻塞。导演方案接纳后，本次有讲解创作时在原会话计划显示初制与逐段精修的交回数，区分B2交回、精修交回与正式接纳。其它重复单位沿用正常循环的状态与回执；真实步骤变化时简短反馈。正文完成后沿下文历史引文收口与正式状态结束P3。

授权维修规则后，保留工作单签发身份，按正式`next.currentRuleSources`读取现行文件。Director与Author视图均投递现行规则与结果合同的路径和摘要，按各自Skill在首次、变化或上下文缺失时完整读取。现行规则替代快照中的旧正文，不改工单摘要、候选绑定或步骤锁；保留已完成内容，只按当前校验结果修正实际失效部分。

## 画面创作前播报

Director完成全画幅分镜、讲解章级交接和接纳后，在开始正文Author画面创作前，用过程消息（commentary）按以下格式播报一次。用只读程序从已接纳故事板的`beats / templateRuns`统计：总章节数取`templateRuns.length`，各类按`templateId`计章节数，全画幅镜头数取全画幅B记录数。讲解按TR统计。

> 导演方案已完成：全片划为 **{总章节数}个章节**。
>
> - 全画幅：**{全画幅章节数}个章节，共{全画幅镜头数}个镜头**
> - 讲解：**{讲解章节数}个章节**
>
> 接下来开始画面创作。

播报后立即按下述分工领取正文章节，不等待用户回复或确认，不以最终答复结束当前执行。同一方案恢复续跑不重复播报，播报只留在会话中。

## 正文按章节并行

主代理完成共享理解、全画幅分镜、讲解章级交接和导演审计后负责调度与接纳。初制按一章（TR）一位原生子代理派工，最多三章并行；待办不足或并发受限时按实际数量启动。每章新建独立上下文作者，沿所选模板完成本章创作与自查。全画幅同章全部成员由一位作者完成。讲解初制交回后进入逐段精修的待办范围。

主代理从当前整集`status.authorSegments`按播放顺序找首个`pending`章节，按其模板选择下列一种claim，在一个并行空位内领取并立即派出新作者。等待预演、写入或修正的作者仍占名额；讲解作者交回有效B2并停止写入后立即释放名额，供后续章节使用。候选仍保留为`in-progress`，因此不能按status中`in-progress`的总数判断并发。领取类型由待办决定：

```text
node engine/cli.mjs next --workspace <节目目录> --episode <epNN> --stage p3 --claim fullframe
node engine/cli.mjs next --workspace <节目目录> --episode <epNN> --stage p3 --claim explainer
```

`fullframe`和`explainer`各自只领取对应类型。以命令实际返回的章节及工作单派发。定点返工按本次请求选择章节，用`next --segment <TR编号>`领取或续接对应单。`author-queue-empty`时核对其它类型、在途作者与待精修候选，继续当前阶段。

用原生`spawn_agent`新建作者，显式设置`fork_turns: "none"`。每个讲解初制作者额外显式设置`model: "gpt-6.1-sol"`和`reasoning_effort: "max"`，包括需要换人续作原单时。指定模型无法启动时保留工作单并报告实际阻塞。派工仅交系统根目录、节目目录、集数、章节编号、返回的工作单路径、本次创作或修订意见、授权范围及必要用户约束（含当前模型看图传输预算）。新作者从正式工作单和任务视图读取完整业务输入、Module、所选Template及Feature方法；全画幅仍须完整理解正式全片口播与导演安排。

派工直接点明`packages/modules/author-beat/SKILL.md`入口和`node packages/p3-task-view.mjs <workOrderPath>`业务读取命令，说明本次是执行已分配正文单；新作者从这两个既有入口进入本章，不先打印整份工作单，也不重做主代理的共享理解、分镜、剪辑设计或领单调度。作者对口播和导演方向的理解照常完成；正文方法的按需读取、终端包装精简和截断补读沿author-beat入口执行。

每位新作者首次读取自己尚未掌握的现行规则与材料；规则、案例和配图仍按原消费点加载，读取本单所选责任包及其方法明确引用的共享组件、来源资料和教材，不加载未选Template。同章已完整持有且未变的规则及材料沿用，截断只补缺失部分。新作者首次取得完整视图前，不沿用其它作者的`referenceDigests`请求省略原文。不得为节省Token删掉必要方法、改用摘要或额外建立跨章规则副本。

讲解作者沿author-beat进入[vox-explainer](../../packages/templates/vox-explainer/AUTHOR.md)，完成整段动效、必要实图、Cue、自查及已装配功能，再通过B2交回可播放的完整初制候选，保留本单设计稿、源码和素材供后续精修接手。仅补Feature的章节沿原局部交付接纳。

领取在原写入锁内完成，已有工作单或候选的章节保持原分配。恢复原单用`next --segment <TR编号>`。恢复会话时先确认现有作者、工作单与候选；作者变更在原写入者停止后接续原单及有效成果。已在创作中的章节保留当前候选、素材、外部身份和步骤锁，新分工通过原单续接。

初制子代理只写本单唯一候选、临时目录和所属素材。B2完成后返回工作单、候选路径、B2结果、完成范围与具体未解决问题；素材和预演留在原工作区。主代理在会话内维护章节、作者与交回进度。初制失败或外部调用需恢复时仍由当前章节作者沿原单处理；交给精修者后由精修者独占该单写入，初制作者退出。下一章重新`spawn_agent`。

全画幅B2交回即由主代理串行运行同集`accept --stage p3 --segment <TR编号>`，随后读取整集`status`并在成功后结束本章作者。讲解逐段精修交齐后使用同一接纳链。接纳失败把具体问题交回当前负责该候选的执行者沿原单修正，其它无依赖作者继续。正式正文进度只取`status`的章节计数，`completed / total`为已接纳章节数与总章节数，`beatCount`另报全画幅Beat数。主代理负责交接与接纳，观看及实际修改由创作和精修子代理执行。

讲解初制与精修各自按[Vox复看方法](../../packages/templates/vox-explainer/references/creative/review.md#复看与修正)复核本章的同版预演。主代理按[现有Studio规则](../../README.md#studio预览)协调共用标签；作者无法播放时，按上述方法协助补看并把具体问题交回作者。交回说明实际复看范围。正式相邻镜头的联看沿原入口。

全画幅只读取本章的已成画面、动作、道具与相机参考；章首独立起镜，章外只保留正式语义和导演方向。讲解不等待前章作者；讲解预演尚缺真实前章底板时只检查本章内容，成片由原消费者接入已完成底板。相邻全画幅按导演接法，讲解进出沿原模板专用推移，由原渲染消费者执行，创作内复核按各模板既定范围完成。

失败或未知调用留在原工作单恢复，保留已成素材；其它无依赖章节可继续。遇到需要返回Director的范围问题，主代理先暂停受影响作者，再按原退回入口处理；不靠子代理修改系统或扩大章节边界。局部返工仍按原入口建立请求，再按章节领取，仅修实际失败成员；同章顺序保持，其它章节候选不受影响。

## 讲解逐段精修

1. **收齐初制。** 按整集`status.authorSegments`的播放顺序确定讲解范围。普通整集创作及整阶段重跑覆盖全部讲解章，定点返工覆盖本次实际制作或重设计的讲解章。主代理按本次实际交回确认各章完成[Vox作者的预演自查](../../packages/templates/vox-explainer/AUTHOR.md#复看与交回)、B2成功且作者停止写入，再派精修。一个讲解章也照做。普通续作沿用仍有效的已接纳成果，有明确修订需求时按现有定点入口处理。没有讲解创作时直接走原收口。
2. **一章一位新精修者。** 按待办顺序，在正文共用的三章并行名额内为每章单独调用`spawn_agent`，显式设置`fork_turns: "none"`、`model: "gpt-6.1-sol"`、`reasoning_effort: "max"`。每位精修者均未参与本集初制，只收到系统根目录、节目目录、集数、一个TR编号及其原工作单和候选路径、本章范围与用户约束。该精修者从[Author入口](../../packages/modules/author-beat/SKILL.md)进入本单，按[Vox精修方法](../../packages/templates/vox-explainer/AUTHOR.md#单段精修)看完本段并直接修订。每章只派一位精修者执行一轮，每位只负责一章。交回后释放名额，为下一章另建子代理。全画幅创作可在可用名额内继续。
3. **交付与接纳。** 精修者按Vox方法复看本章，交回实际复核范围、结果路径、尚待核实的段内画面或时窗，以及待正式联看的相邻接缝。主代理用既有预演协助核实仍影响本章理解或完成度的具体问题，交精修者在原单修正并复看。修改后重走原B2，完成复核且无需修改时沿用原B2。主代理收齐精修交回并确认停写后串行接纳，相邻接缝沿原入口联看。接纳失败交该章精修者沿原单修正。节目输入或导演职责无法在原单内解决时，按实际责任退回。付费、图片修正及未知调用沿现有授权。

恢复时先核对正式状态、原单、候选与本次会话的交回进度。仅有候选文件或`in-progress`不足以确认B2或精修已完成。初制交回未确认时，沿原单接续实际剩余的制作、自查与B2。精修中断优先续接该章精修者；确需换人时先确认原写入者停止，再按相同配置派新子代理接续该章尚未确认的部分。保留已确认的同版结果。接纳事务中断沿原命令恢复。进度与交回使用原会话，作品与修改保存在原单。

## 普通创作合同

P3的理解、视觉导演、切分审计和调度由主代理完成；各章独立初制，讲解按上述分工逐段精修，再由主代理统一接纳与历史引文收口。

- System Control 只读取本节点需要的口播交付、字幕与来源清单，不复核P2过程证据或摘要；来源使用与权利由实际使用方负责；它不是独立节点或人工智能责任包。
- Director一次提交 `{understanding, albumPlan, beats, templateRuns}`。先从整集口播形成共享理解并保存为同一候选的中间产物，再读它按[章节方法](../../packages/modules/direct-episode/references/template-selection-method.md)圈定讲解及其余全画幅章节，沿[考据组件](../../packages/modules/direct-episode/historical-context/README.md)交接确有需要的历史资料，再按[分镜与剪辑方法](../../packages/modules/direct-episode/references/beat-page-method.md)完成全画幅分镜、整集接法和讲解章级观看任务。在派工前完成整集审修与封存。章节沿用TR，新讲解章用一条B保存整章时窗和观看要求。
- 正文 Author 按所选 Template 提交结果。全画幅首次按章节联合设计与生图，多成员同一候选提交`{items:[{beatId,treatment,featureResults?}]}`；Beat仍独立保存、渲染和修改。单Beat章节、单Beat返工及讲解章节沿原`{treatment,featureResults?}`合同。全画幅正式画面、Cue绑定、运镜、`cameraRelation`和完整路线只由Codex按模板完成。不得用重复检测、配额、轮换或随机代替创作。正式投递的同章前序画面用于辨认重复与呼应；相机参考限同章紧邻上一镜，用于观感衔接、按需严格接镜和实际物理承接。本单联合成员共同创作，章外相邻摘要只交接语义与播放边界。
- 首次创作由当前工作单完成开放设计；局部返工使用工作单投递的当前正式设计，只修实际失效部分。旧剧集成果、旧P3、其它任务候选和历史会话归档都不属于输入；当前轮次前序镜头只使用工作单正式投递的`templateContext / previousTreatment`，不得另行搜索原文件或任务历史。

## P3—P4 全画幅交接

- P3 Author在同一候选完成联合画面设计、实际生图、实图上的最终`motion`及解说框／Cue。图片引用保存在对应请求的`asset`，不另交素材计划或图片清单；Studio／P4从原成果确定性推导取景。
- 全画幅按“联合创作 → 实图与最终运镜 → 解说框及Cue”三个真实步骤执行。生成前测量并复核设计；生成后直接导入，在原落镜步骤将已定表达、必要内容、实际取景及效果锚点一并落实。优先合看完整原图、路线与起中末取景，复用已看清且未变的内容与来源判断。落镜方法统一拥有表达核对、取景校准、修图和修设计的判断；动态片段按其使用条件查看。
- 全画幅新镜一镜一幅完整静态主画面，沿原画面方法、相机及效果实现导演的观看推进。讲解作者在原工程全章粗排中定章内切镜、运镜和动作卡点。章界、观看职责或影响整集的关键揭示时机有冲突时回导演，章内观看问题由讲解作者在原工程调整。

## 完成与交接

P3唯一作者真源是`epNN/制作/p3/storyboard.yaml`。正文单位全部接纳后，主代理用不带segment的`next`取得原Author节点的`inputs.authorPhase=quotes`收口单：从当前口播和材料识别线索，取得史料原文、查明真实出处，整体决定填入或取消，接纳为同一故事板的`authorQuotes`。没有待处理引文则无需该相位。

局部重切时，原组件识别仍有效的取消决议；已有决议齐备则不再查询。已签发但未使用的多余收尾单，按`status`提示用普通`next`清理，保留原记录。以正式`status`确认交付齐备，正文计数已满不代表P3完成。

片头设计与剧情视频归P4，发布文案与封面归P1。Studio／P4直接消费正文实图、最终运镜与P4交付。

讲解逐段精修、正文与必要历史引文接纳完成后，以正式`status`的`stage-complete`确认P3完成，报告产物与实际完成范围。单阶段授权到此停止，明确授权的连续范围进入后续阶段。
