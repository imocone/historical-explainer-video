# P3：视觉创作

正文统一按章节组织，分为讲解章节和全画幅章节，沿用`templateRun`（TR）身份。导演方案整集接纳；后续正文按章节派工、提交、接纳和统计进度。全画幅章内保留独立Beat，讲解章节不由导演切内部Beat。

## 读取时机

在 `status --workspace <节目目录> --episode <epNN> --stage p3` 返回 `stageId: p3` 时完整读取本入口。普通创作、返工、恢复和接纳都从这里进入；再按当前动作与首个消费点，完整读取下表点名的章节，不默认通读其它模式。

| 当前动作／消费点 | 按需完整读取 |
|---|---|
| 普通整集创作：导演初稿与模板归属形成后、正文Author之前 | [切分审计与一次集中修正](p3-actions.md#独立步骤切分审计与一次集中修正) |
| 已接纳导演计划的局部修订或明确撤销该修订 | [导演局部修订](p3-actions.md#导演局部修订) |
| 明确重做现行P3正文 | [正文重设计](p3-actions.md#正文重设计) |
| 明确只重作已接纳的部分历史引文 | [已接纳历史引文定点重作](p3-actions.md#已接纳历史引文定点重作) |
| 同次任务恢复 | 本入口及原动作的方法；按当前工作单、原请求和已完成进度续接，不改模式或补开一轮 |

已在当前上下文完整读取且未变化的方法不重复加载；首次使用、变化或上下文缺失时完整补读对应章节。逐单位创作只读当前工作单投递的正式资源；本表只路由既有动作，不新增步骤或扩大委托范围。

## 执行进度与恢复

沿用总入口的会话计划，用原生`update_plan`显示`status.queue`顶层节点；`author.units`为`null`时显示“数量待确定”。整集生产另列“切分审计与一次集中修正”：导演初稿与模板归属形成后、正文Author之前，执行`direct-episode`原第四步。

首次计划将该项列为待办；恢复时继承实际进度。进入切分审计时将其标为进行中，完整审阅后在当前会话留下实际范围、结论和具体意见，零问题也明确范围与结论。原修正动作读取这些意见，沿同一会话计划续接，不另写审计文件或节目状态。

审阅结束与修正完成分别说明，满足该方法的结束条件才将整个条目标为完成。未审完、未列齐问题或修正未完成时，留在本步骤继续或报告真实阻塞。其它重复单位沿用正常循环的状态与回执，不拆子任务，不为展示额外查询、轮询或调用模型；真实步骤变化时简短反馈。正文完成后沿下文历史引文收口与正式状态结束P3。

授权维修规则后，保留工作单签发身份，按正式`next.currentRuleSources`读取现行文件。Understanding、Director与Author视图均投递现行规则与结果合同的路径和摘要，按各自Skill在首次、变化或上下文缺失时完整读取。现行规则替代快照中的旧正文，不改工单摘要、候选绑定或步骤锁；保留已完成内容，只按当前校验结果修正实际失效部分。

## 画面创作前播报

Visual Director完成章节划分、全画幅切分、复核并正式接纳后，生产总导演在开始正文Author画面创作前，用过程消息（commentary）按以下格式播报一次。用只读程序从本次已接纳故事板的`beats / templateRuns`统计：总章节数取`templateRuns.length`，各类按`templateId`计章节数；仅统计`templateId=fullframe-narrative`的B记录为全画幅Beat数，未选类型报0。讲解B记录交接整章范围，不混计为观看Beat；有效旧章节仍按TR计数。不用作者单位数或图片数代替Beat数。

> 导演方案已完成：全片划为 **{总章节数}个章节**。
>
> - 全画幅：**{全画幅章节数}个章节，共{全画幅Beat数}个 Beat**
> - 讲解：**{讲解章节数}个章节**
>
> 接下来开始画面创作。

播报后立即按下述分工领取正文章节，不等待用户回复或确认，不以最终答复结束当前执行。同一方案恢复续跑不重复播报，播报只留在会话中。

## 正文按章节并行

主代理完成Understanding、Visual Director和切分审计后，专职调度与接纳，不承接逐章正文创作。正文一章（TR）一位原生子代理，最多三章并行；待办不足或并发受限时按实际数量启动。每章首次派工均新建独立上下文作者，不跨章复用。全画幅与讲解共用此分工，每位作者沿所选模板完成本章全部创作、素材、Cue、预演与既定复核；全画幅同章全部成员由一个作者完成，不逐Beat更换作者。

主代理从当前整集`status.authorSegments`按播放顺序找首个`pending`章节，按其模板选择下列一种claim，在一个并行空位内领取并立即新建作者派出；重复至三章在途或没有可领章节。等待预演标签、B2交回待接纳及接纳失败待修正的章节仍占原位，不额外启动第四章。领取类型由待办决定，不要求先全画幅后讲解：

```text
node engine/cli.mjs next --workspace <节目目录> --episode <epNN> --stage p3 --claim fullframe
node engine/cli.mjs next --workspace <节目目录> --episode <epNN> --stage p3 --claim explainer
```

`fullframe`和`explainer`各自只领取对应类型。以命令实际返回的章节及工作单派发，不预占或猜测下一章。`author-queue-empty`只表示该类型当前没有可领章节，主代理结合整集status继续其它已授权待办；已有作者在制作时等待其交回，不以空队列结束阶段。

用原生`spawn_agent`新建作者，显式设置`fork_turns: "none"`。派工仅交系统根目录、节目目录、集数、章节编号、返回的工作单路径、本次创作或修订意见、授权范围及必要用户约束（含当前模型看图传输预算）；不复制主会话历史、其它章节图片、整份工作单或规则正文。新作者从正式工作单和任务视图读取完整业务输入、Module、所选Template及Feature方法；全画幅仍须完整理解正式全片口播与导演安排，不以主代理聊天摘要替代。

派工直接点明`packages/modules/author-beat/SKILL.md`入口和`node packages/p3-task-view.mjs <workOrderPath>`业务读取命令，说明本次是执行已分配正文单；新作者从这两个既有入口进入本章，不先打印整份工作单，也不重跑主代理的Understanding、Visual Director或领单调度节点。作者对口播和导演方向的理解照常完成；正文方法的按需读取、终端包装精简和截断补读沿author-beat入口执行。

每位新作者首次读取自己尚未掌握的现行规则与材料；规则、案例和配图仍按原消费点加载，读取本单所选责任包及其方法明确引用的共享组件、来源资料和教材，不加载未选Template。同章已完整持有且未变的规则及材料沿用，截断只补缺失部分。新作者首次取得完整视图前，不沿用其它作者的`referenceDigests`请求省略原文。不得为节省Token删掉必要方法、改用摘要或额外建立跨章规则副本。

讲解作者同样以该章节正式工作单和任务视图为输入，沿author-beat进入vox-explainer，完成构思、画面、素材、动画、Cue、原声预演、手机尺寸复核和B2。主会话的理解与导演意图通过已接纳并由本单投递的正式内容交接，不以聊天摘要替代。

领取在原写入锁内完成，已有工作单或候选的章节保持原分配。恢复原单用`next --segment <TR编号>`。恢复会话时先确认现有作者、工作单与候选；作者变更在原写入者停止后接续原单及有效成果。已在创作中的章节保留当前候选、素材、外部身份和步骤锁，新分工通过原单续接。

子代理只写本单唯一候选、临时目录和所属素材，B2完成后只返回工作单、候选路径、完成范围与具体未解决问题，不回传原图、预演帧或候选全文。正式故事板写入、接纳与后续分配统一由主代理经原Engine完成。主代理只在会话内维护章节与作者的对应关系；本章成功接纳后结束使用该作者，下一章重新`spawn_agent`，不得用`followup_task`让旧作者接下一章。未接纳章节的修正、原调用恢复仍可交回本章原作者，不因B2交回就丢弃其上下文或重启创作。

主代理按交付到达顺序串行运行同集`accept --stage p3 --segment <TR编号>`，再读取不带segment的整集`status`；确认本章已接纳后结束使用本章作者，在释放的并行空位内按上述待办顺序为下一章新建作者，不等待其它作者一同结束。正文进度取正式`status`的章节计数：`completed / total`为完成章节数与总章节数，`currentUnitId`指当前章节，`beatCount`另报全画幅Beat数；全画幅成员全部有效交付后才计该章完成，讲解沿整章结果计数。接纳失败把具体问题交回本章原作者沿原单修正，不另派同章或越过失败接下一章；其它无依赖作者继续。章内观看和修正由原作者完成，主代理不在交回后重新创作或完整审片。单章`segment-complete`后，其它正文与历史引文继续按真实进度推进。

多个讲解作者需要预演时，沿[现有Studio规则](../../README.md#studio预览)共用一个浏览器标签。主代理协调使用时机，当前作者完成本次观看后再交给下一作者导航；观看仍由各章节作者完成，等待标签的作者可继续本章不依赖观看的工作。各章节使用自己的预演工程，不覆盖其它章节候选或同时操作同一标签。

全画幅只读取本章的已成画面、动作、道具与相机参考；章首独立起镜，章外只保留正式语义和导演方向。讲解不等待前章作者；讲解预演尚缺真实前章底板时只检查本章内容，成片由原消费者接入已完成底板。正常转场沿原作者设计和渲染消费者执行，创作内复核按各模板既定范围完成。

失败或未知调用留在原工作单恢复，保留已成素材；其它无依赖章节可继续。遇到需要返回Understanding或Director的范围问题，主代理先暂停受影响作者，再按原退回入口处理；不靠子代理修改系统或扩大章节边界。局部返工仍按原入口建立请求，再按章节领取，仅修实际失败成员；同章顺序保持，其它章节候选不受影响。

## 普通创作合同

P3的理解、视觉导演、切分审计和调度由主代理完成；各章独立正文子代理按上述分工执行所选模板的原作者方法，主代理统一接纳与历史引文收口。

- System Control 只读取本节点需要的口播交付、字幕与来源清单，不复核P2过程证据或摘要；来源使用与权利由实际使用方负责；它不是独立节点或人工智能责任包。
- Understand 只提交 `{understanding}`。
- Visual Director 一次提交 `{albumPlan, beats, templateRuns}`：先确定整集方向，按[正文章节划分方法](../../packages/modules/direct-episode/references/template-selection-method.md)从完整Cue选定讲解的必要连续范围，再按相对完整的叙述划定剩余全画幅章节并保存。接着沿[历史视觉考据组件](../../packages/modules/direct-episode/historical-context/README.md)形成并登记人物、衣装与环境依据，绑定到当前观看范围。随后仅按[全画幅Beat方法](../../packages/modules/direct-episode/references/beat-page-method.md)切分全画幅章节，按新Cue范围重新绑定已有依据，落实观看要求与真实时窗，完成章节与Beat两层的一次审修、封存和整集方案接纳。两类章节统一使用现有templateRun（TR）；只有全画幅章节切Beat。新讲解每章用一条B范围记录交接整章要求，不切内部Beat，章内讲法、画布、部件和Cue由原模板作者决定；有效旧多成员章节保留。各章节保存模板身份与连续成员；不形成正式逐图设计、构图、相机、生图提示词或 P4 动作。
- 正文 Author 按所选 Template 提交结果。全画幅首次按章节联合设计与生图，多成员同一候选提交`{items:[{beatId,treatment,featureResults?}]}`；Beat仍独立保存、渲染和修改。单Beat章节、单Beat返工及讲解章节沿原`{treatment,featureResults?}`合同。全画幅正式画面、Cue绑定、运镜、`cameraRelation`和完整路线只由Codex按模板完成。不得用重复检测、配额、轮换或随机代替创作。正式投递的同章前序画面用于辨认重复与呼应；相机参考限同章紧邻上一镜，用于观感衔接、按需严格接镜和实际物理承接。本单联合成员共同创作，章外相邻摘要只交接语义与播放边界。
- 首次创作由当前工作单完成开放设计；局部返工使用工作单投递的当前正式设计，只修实际失效部分。旧剧集成果、旧P3、其它任务候选和Codex／Claude会话归档都不属于输入；当前轮次前序镜头只使用工作单正式投递的`templateContext / previousTreatment`，不得另行搜索原文件或任务历史。

## P3—P4 全画幅交接

- P3 Author在同一候选完成联合画面设计、实际生图、实图上的最终`motion`及解说框／Cue。图片引用保存在对应请求的`asset`，不另交素材计划或图片清单；Studio／P4从原成果确定性推导取景。
- 全画幅按“联合创作 → 实图与最终运镜 → 解说框及Cue”三个真实步骤执行。生成前测量并复核设计；生成后直接导入，在原落镜步骤将已定表达、必要内容、实际取景及效果锚点一并落实。优先合看完整原图、路线与起中末取景，复用已看清且未变的内容与来源判断。落镜方法统一拥有表达核对、取景校准、修图和修设计的判断；动态片段按其使用条件查看。
- 全画幅画面与运镜由所选模板根按登记的画面方法、相机组件联合创作和复核；转场包括A/B和跨Beat相邻全画幅，由原作者结合完整全片语境与画面、运镜联合设计；A/B各用自己的实际运动时钟，持续运镜与速度变化沿原motion执行，下一Beat沿用既有接镜预进入和退出尾帧，原Beat总时长不增加。具体窗口、速度、路线及观看成立判据只见这些真源。P4只执行已接纳设计，设计失败返回真实P3责任方。

## 完成与交接

P3唯一作者真源是`epNN/制作/p3/storyboard.yaml`。正文单位全部接纳后，主代理用不带segment的`next`取得原Author节点的`inputs.authorPhase=quotes`收口单：从当前口播和材料识别线索，取得史料原文、查明真实出处，整体决定填入或取消，接纳为同一故事板的`authorQuotes`。没有待处理引文则无需该相位。

局部重切时，原组件识别仍有效的取消决议；已有决议齐备则不再查询。已签发但未使用的多余收尾单，按`status`提示用普通`next`清理，保留原记录。以正式`status`确认交付齐备，正文计数已满不代表P3完成。

片头设计与剧情视频归P4，发布文案与封面归P1。Studio／P4直接消费正文实图、最终运镜与P4交付。

正文与必要历史引文全部接纳后，以正式`status`的`stage-complete`确认P3完成，报告产物与实际完成范围。P3到此结束，不再进行交付后的整集检查或集中修正；单阶段授权到此停止，明确授权的连续范围才进入后续阶段。
