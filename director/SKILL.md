# 生产总导演

只通过正式控制程序推进，不直接改写作者成果。流程与责任以现场状态和工作单为准。

由Codex主代理按下述路线调度原生子代理与既有专业工具；图片统一使用Codex原生imagegen。

## 渐进披露

主入口只保留共同规则。首次进入阶段，或当前上下文缺少其规则时，按`stageId`完整读取对应阶段入口；P3再按入口的当前模式与首个消费点，完整读取点名的专项方法，不默认加载其它模式。已完整读取且未变化的内容不重复加载；专业方法首次使用、发生变化或上下文缺失时须完整补读。恢复时重新核对现场状态，接续现有有效成果；本阶段各动作均以对应入口及其明确引用的方法为准。

- `p0`（节目策划）：读取 [`references/p0.md`](references/p0.md)。
- `p1`（文字创作与封面）：读取 [`references/p1.md`](references/p1.md)。
- `p2`（音频）：读取 [`references/p2.md`](references/p2.md)。
- `p3`（创作）：读取 [`references/p3.md`](references/p3.md)；P3不得默认加载其它阶段细节。
- `p4`（片头、剧情视频、素材与最后压片）：读取 [`references/p4.md`](references/p4.md)。开源制作到此结束。

本入口只路由当前阶段；沿该阶段及工作单明确链接，按消费点读取当前任务所需方法和资源。不扫描目录、凭记忆补读或加载无关阶段；跨阶段只读当前消费者所需正式交接。

## 阶段选择与授权总则

先按用户要的交付物识别任务范围。“用某集的一段测试／迭代模板”属于指定片段的模板试做：先核对这段当前已有的口播、Cue及所需素材，再按模板现有案例／预览入口开展，保持试做范围。提到剧集名称不等于授权整集或整阶段生产；缺少其它正文、片头、剧情视频、发布文案等交付时，说明与本次试做直接有关的缺口，不为凑齐流程自动补做。需要写入正式节目成果时，仍沿用户已授权范围的原工作单执行；试做输出不冒充正式阶段接纳。用户明确要求正式阶段或连续阶段生产时，才按下列规则推进。

1. 按用户本次授权选择单阶段或P1—P4的连续范围；P0独立运行。P0覆盖委托至接纳；P1覆盖正文、片头、平台文案、封面构思与横竖两张封面首次必要的自带生图，原produce-covers节点同批制作双图，不单独询问封面授权；P2、P3、P4覆盖正常动作和首次必要付费；P4覆盖所选模板确需的片头TTS，`documentary-opener`无片头TTS，P4在素材交付后完成压片并交付最终MP4，开源版不执行发布。参数与闸门见对应reference，不逐节点询问。
2. 单阶段命令不代替上游；跨阶段只沿用户明确指定的连续范围执行。全局`check`只用于用户明确要求的项目审计或故障诊断，不是生产前置门。
3. 未授权不生产、付费或发布；完成后只响应明确修订。P1自带生图失败／结果未知后的重投，以及P2—P4付费失败／远端未知后重投或付费须有明确授权，且须满足阶段恢复限制；P3／P4不超过5张的图片修正及剧情视频同类提交超时，分别按AGENTS已有直接重生许可和一次重试许可执行，不重复询问。

## 连续执行、暂停与重跑

用户要求“P1做到P4”或指定其它连续范围时，用`run --workspace <节目目录> --episode <epNN> --from p1 --to p4`登记范围并推进当前节点。命令仍返回原工作单：按当前阶段reference执行，AI候选仍用同阶段`accept`接纳，然后继续同对象`run`。需要首次付费时，按已有范围授权传入该阶段原付费参数；P1封面包含在当前P1或连续范围授权内，沿原节点同批调用自带生图。

`run`返回`stage-closeout`时，完成本阶段本次尚未完成的收尾，再用`run --advance`推进并读取新阶段reference，直到`run-complete`。这是Director的正常连续执行，不让用户逐阶段确认。阶段reference中的“完成后停止”指单阶段授权；连续范围在完成收尾后继续。

`run --pause`保存暂停意图，不杀掉在途外部调用；在安全边界停下。用户要求继续时`run --resume`接回原工作单。

用户明确要求某阶段全部重做时，用`reset --workspace <节目目录> --episode <epNN> --stage <p1|p2|p3|p4>`，再用原`next`或`run`推进。它保留上游和旧正式成果，将未接纳工作记录归档，各节点交付本次新结果；新结果接纳时才替换原结果。范围内重置会把执行位置移回该阶段，暂停状态保持。远端未知或仍在执行时先恢复原对象，不能用reset抹去它。

“继续”不重置；“改某一处”使用已有定点入口；“整个阶段重做”才reset。查看某集或整个节目进度时使用不带`--stage`的`status`，节点细节仍由阶段status提供。

## 固定循环

1. 用户明确创建新节目、目录尚无`request.yaml`与`program.yaml`时，先按[P0入口](references/p0.md)把用户明确的委托写入原文件。随后运行当前对象的 `status` 并始终提供 `--workspace` 与`--stage`：P0 提供`--program`；P1—P4提供`--episode`；P1封面与P4同时提供`--target release-main`。
2. `status`只加载当前阶段责任包，只查看本节点直接交付是否到位；不递归重审上游、旧规则或制作摘要。`blocked-upstream`必须停止；`recovery-required`同参运行`next`补完原接纳，不重新创作；`stage-complete`转入本阶段reference规定的收尾；单阶段到此结束，范围执行按“连续执行、暂停与重跑”推进。`queue`由工作流与现场即时推导，不另建队列。

   **进度显示。** 获准阶段包含多个动作时，首次取得正式`status`后，使用`update_plan`建立UI计划列表；后续正式状态发生变化时同步更新，阶段收尾结束时标记完成。计划概括当前`queue`、工作单、回执及reference明确要求的收尾进度；重复单位显示“完成数／总数＋当前单位”，不猜未形成任务，也不写入工作区。
3. 使用相同对象参数运行当前阶段的`next`。`runner: program`由该命令直接执行并写正式程序产物；`runner: ai`返回工作单。P4按本阶段reference分派片头，以及用户明确启用的视频节点；各作者只处理自己的唯一`workOrderPath`。`scratchPath`、付费参数和连续动作以对应reference为准。
4. 人工智能节点按工作单和当前阶段reference形成唯一候选；程序节点只执行`next`投递的任务且没有候选。两者都不得替下游补写上游，或转移问题责任。
5. 只有`runner: ai`同参运行`accept`，P3正文由主代理带本段`--segment`串行接纳，P4另带本单`--node`以定位独立候选；程序核对当前对象、阶段、候选与写入范围，验证本节点的新产出后落位；同一候选的写入中断由`accept`或`next`补完剩余提交，不重新创作。`runner: program`没有`accept`。命令异常时用`status`核对正式成果，不凭退出结果判断，也不直接重做。
6. 每次人工智能`accept`或程序`next`后立刻同参`status`；P3分段接纳后读取整集status。到`stage-complete`后完成当前阶段本次尚未完成的收尾；单阶段停止，连续范围推进至指定终点。P4最后沿render-video压片并返回成片路径。只有正式完成、`blocked-upstream`、没有适用恢复路径的未知外部结果／再次付费需授权、硬系统故障或新权限缺口时停止。

   历史解说P1普通／full在author-narration的N04没有可选稿时，按P1 reference停止并报告未完成，不以队列仍有任务为由继续调用或接纳。

   当前阶段明确需要用户补充必要输入时，先完成不依赖该输入的工作，再说明具体缺口并等待；获得输入后恢复原任务，等待不等于完成。其余情况下，获准范围内仍有工作单、队列或未完成数就更新进度并继续，不得越界。

## 执行工作单

- **任务视图。** `understand-episode`、`direct-episode`与`author-beat`以`node packages/p3-task-view.mjs <workOrderPath>` stdout作为视图；当前单视图已完整返回时直接读取一次，不重复调用。完整单只供程序，其它单按字段读一次。已完整取得且未变的规则不重读。

  **工作单与候选读取。** 工作单和候选以JSON读取，不用require载入.yaml；路径、对象层级与ID取当前返回值，不猜文件名或套用另一节点结构。只用`resolvedAssembly`，文本按链接读。结果Schema是作者交付合同，按责任包入口读取；Validator与策略源码由程序执行，模型读取其结果。

  **维修后续跑。** 维修后继续原单时按`next.currentRuleSources`读取现行方法；原候选、临时目录和外部身份保留。
- `resolvedAssembly.slots[].implementations` 为空时不得自行补装；非空时只能使用其中列出的包与资源。Catalog（目录）插槽只用于当前节点选择，不授权调用未被实际选择的业务实现。
- `runner: ai`的语义、内容与设计字段，由当前责任包明确指定的人工智能作者按其流程为当前单位逐步形成；不据此新增、替换或委派作者。脚本和确定性程序只能读取固定输入、执行已登记策略或校验器，将完整结果原样序列化为候选；不得代替模型综合、补齐、改写、批量生成或建立跨工作单复用的语义生成器。创作单位未完成时留在本步；P3全画幅与讲解按本阶段reference一章一位全新独立上下文原生子代理，最多三章并行，成功接纳后结束使用本章作者，下一章另建，主代理完成理解与导演后专职调度、统一接纳；P4默认只派片头独立作者；明确启用剧情视频时，再按本阶段reference由片头、视频两位全新独立上下文子代理并行创作，主代理调度与串行接纳。P3正文作者按模板读取正式输入；全画幅作者先完整理解工作单视图中的全片口播与导演安排，再联合设计当前画面、运镜与转场，段内已有画面按工作单参考，段外只读正式语义与导演安排。
- 当前工作单没有列出的历史会话、归档会话、其它任务聊天、旧候选、旧P3、备份、废纸篓和模型记忆一律不是生产输入。不得检索、提取、改写或复用它们来完成当前人工智能任务；当前轮次已经接纳的前序结果也只能通过本工作单实际投递的投影读取。工作单输入不足时停止或返回真实上游，不能到任务历史中补答案。违反本条得到的候选即使Schema通过，也不属于当前工作单的有效创作结果。
- 只在工作单指定的 `candidatePath` 写入 JSON 文本；扩展名虽为 `.yaml`，但 `taskDigest:` 等普通 YAML 写法会被 Engine 拒绝。P1、P2 的 `scratchPath` 只按对应 reference 写入指定中间文件，不得自选、替换或扩张目录。
- 始终使用同一候选路径，按责任包当前步骤一次写全本步字段，后续在原路径局部补写或原子更新；首次写入范围由责任包规定，不提前填写后置步骤。不得另建候选或重复打印未变化的全文。

候选的最小外壳是：

```json
{"taskDigest":"当前工作单摘要","result":{}}
```

当前人工智能任务若发现真实上游缺口，且工作单规则允许退回，则从 `allowedReturnTargets` 选择与缺口责任一致的真实 `nodeId`，改写互斥的退回候选：

```json
{"taskDigest":"当前工作单摘要","returnTo":{"target":"<nodeId>","reason":"明确缺口","cueRefs":[]}}
```

提交前必须把 `<nodeId>` 替换为 `allowedReturnTargets` 中的实际值，不得原样提交占位符。Narration Workflow（口播工作流）的退回没有字幕定位，`cueRefs` 必须为空数组；Video Workflow（视频工作流）的按拍返工必须填写当前工作单允许的真实字幕编号，不得复制本例的空数组。

候选不得写 `_producer`、正式路径、状态、服务商或工作单未授权字段。各阶段的唯一候选字段、输出合同和确定性收口只见对应 reference。

`accept`拒绝时，先按当前责任包允许的范围处理错误；若工作单确认是上游缺口，只能从 `allowedReturnTargets` 选择一个 `returnTo` 节点，由 `accept` 写入正式控制请求并让 `status` 停靠到真实 owner（责任方）。列表为空或目标不在列表时停止并报告；后续返工以重新推导出的现场任务为准，不根据问题文字猜模块或责任方。

## 共同边界

- 来源资产必须已登记路径、来源、权利和哈希；生成素材不能冒充史料。
- 密钥、环境变量、旧默认和缓存不是授权。付费失败、远端未知或状态无法证明时，不擅自重提、付费、跨渠道续跑、跨阶段、改跑全局`check`、调用其它外部工具或修改系统；先按当前阶段恢复、查询或下载同一对象。P1免费Query的正式替换、P2字幕作者结束写入后的Codex接手，只按对应阶段已经明确的条件执行；不得将这些例外用于未知AGY重投、TTS/ASR重投、再次付费或发布。P4剧情视频同类提交超时符合AGENTS已有一次重试许可时，按P4 reference走原定点替换入口。没有适用恢复或获准替换路径时停止并报告。
- 工作单、候选、恢复缓存、派生渲染计划不是真源。旧合同、字段、流程不兼容；正式交付保留，仅处理实际失效部分及真实依赖，不由下游重新验收，不因成果较早或代码、规则、摘要变化本身重做。
- 不在节目或项目工作区生成工作单未要求的人工状态文件、审阅表或展示文件。机器链通过不等于视觉质量已经验收。
