# 历史纪录片节目策划

只处理`programRequest.programForm=historical-documentary`。`planningBasis`只决定骨架从主题调查形成，还是先从指定基础书提炼再纠错补全；不得用它改写纪录片形式。D02开始只在工作单现有`candidatePath`逐步更新同一候选，最终只提交这一份`program.yaml`候选，不建立研究报告、系列圣经、评分表或第二策划。

## 工作流程

### 短流程（Progress Checklist）

```text
- [ ] D02：确定并写入纪录片方法与逐集观看路径
  - 先完成内部准备D01：核对入口并形成可观察的生活世界
  - 系列方法、每集内容使命与故事骨架已写入candidatePath → D03
- [ ] D03：读取候选反推材料并完成唯一NotebookLM闭环
  - 必要来源有唯一编号且就绪，方向复核已写回同一候选 → D04
- [ ] D04：读取候选反向核对并提交
  - 当前候选满足分路合同与输出Schema → 提交

共同异常：本步内能修正的就地修正；指定基础书、必要材料或事实边界使节目无法成立时停止；远端未知只恢复同一对象，不重复上传。
```

## 步骤说明

D01是D02方案形成前的内部调查与理解，不是独立交付步骤；两者共同形成并保存同一候选。保留内部编号供定位，执行顺序和后续材料、提交责任不变。

### D01：核对入口并形成可观察的生活世界（D02内部准备）

先完整读取[`references/documentary-planning-method.md`](references/documentary-planning-method.md)。服从`idea / constraints`，核对显式形式、受众偏好、集数偏好、时长上限与视觉偏好。`topic-led`从可靠公开调查形成题材骨架；`book-led`先核对指定书的绝对路径和摘要，从书中提炼历史生活怎样运转，再以相同可信度要求纠错补全；调查深度由现有证据、争议和未解决问题决定，足以支持或修正策划决定时停止扩展。书源框架站不住且继续必须换书或换入口时停止。

当委托明确“节目就是为了呈现这本基础书”时，基础书不只是事实来源或策划起点，而是节目内容主体：P0必须从书中成群的场景、物件、动作、声音、名目和生活关系组织整季，补充材料只负责纠错、解释原文和补足必要连接，不能另换中心故事。某个选题若主要靠书外材料成立、基础书只剩时代背景，就不得作为这一节目的单集中心。

工作单含`inputs.programRevision / currentProgramPath`时，先读取路径指向的现行`program.yaml`，把它作为本次修订起点。保留未受用户修改影响且仍成立的节目决定，只重做真实受影响的D01—D04判断；修改需要新事实或材料时才补相应调查与来源，不得把局部故事调试扩大成整季从头重来。候选接纳后停止在P0，不自动进入P1。

把题材先还原成能够被观察的世界：谁在什么时间和空间里生活；哪些劳作、交易、出行、饮食、节庆、照料或制度过程真正推动日常；文献能证明什么，哪些只能合理推论，哪些画面需要明确艺术重构。不得因为资料里有城市、器物或风俗，就自动判定纪录片成立。

完成条件：D02将消费的第一受众、时空范围、核心生活关系、可持续场景来源和事实／推论／重构边界已经形成。

### D02：确定纪录片方法与逐集观看路径

节目层固定写`schemaVersion: 8.1`和`programForm: historical-documentary`，并形成：

- `documentaryContract`：向观众作出的非虚构承诺，明确事实、推论与艺术重构怎样区分；
- `seriesConcept`：这套片子最终让观众看见怎样一个历史生活世界；
- `artisticApproach`：人、物、空间、时间、声音和重构画面怎样形成统一观看经验；
- `seriesNarrativeStrategy`：整季怎样以场景和过程推进，怎样在不靠悬空预告的情况下让各集共享同一种观看理由。
- `storyWorld`：把节目共同生活世界写成P1能直接消费的正式故事合同，包括时空框架、会反复出现的人／地／物／时、跨集连续原则、每集共同叙事语法和艺术重构总边界。它是`program.yaml`的一部分，不另建系列圣经。

从工作单`openerTemplateCatalog`确定节目级`openerTemplate`：首次使用`programRequest.openerTemplate`，未指定则使用目录标记`defaultSelected`的片头。修订保留现行选择，只有用户明确要求才更换；纪录片不自动选回忆片头。只换片头时保持故事策划和材料原值。

从工作单`visualPackageCatalog`确定节目级`visualPackage`：首次优先使用委托中明确且仍在目录内的选择，否则按纪录片的内容使命、故事世界和受众选择；修订保留现行Visual，只有用户明确要求或节目方向变化使原选择不再成立时才更换。`coverPackage`使用`coverPackageCatalog`中的唯一type-first-editorial，不再按题材分选。Visual提供正片及封面人物器物的画法和各用途字体；Cover拥有文字材质、配色、层级、配套横竖排版及配图的视觉强弱，画法与字体接入所选Visual。封面跨题材使用亮字与暗色满幅配图的关系；本集可见文字和场面由P1独立设计，不强制系列名、集号或A/B/C。两项选择仍独立，不能用Cover替代Visual。

同时确定`seriesTitle / audience / editorialDirection / viewerBenefit / narrativeTone`和按委托存在的`maxDurationSeconds`。`seriesTitle`是全系列稳定使用的简洁展示名，封面确需系列识别时使用此正式名称，不强制上图；采用用户已确定的名称，不附加宣传副标题或单集看点，详细表达留在既有策划方向与观众收益中。修订时除非用户要求改名，否则保留现行值。D02必须在委托时长内选定每集核心收益、必要历史内容与最小生活过程，把取舍及集间范围落实到现有`episodeBenefit / episodeScope / episodeCreativeBrief`，再写`episodeThroughline / storyOutline`；不以安排完整路线代替容量判断，也不新增时间表或覆盖清单。字段写法、容量取舍、可观察动作、集间区分、四项观众结果及重构边界由方法集中规定。

在方案形成时核对每集历史内容和故事是否共同成立、各集是否实质重复、系列方法是否符合委托。内容失败按方法修订受影响部分，不把普通人生活使命变成知识目录或独立人物戏。

完成方案后，立即按工作单候选外壳把当前`taskDigest`和D02已经形成的`result`原子写入唯一`candidatePath`。尚未在D03取得的`researchLibrary`字段此时省略，不填写占位Notebook或来源编号；这只是供D03读取的当前阶段草稿，不得提前提交或接纳。D02因材料复核返回时，保留仍成立的节目字段并原子覆盖同一路径，不另建修订稿。

完成条件：D03将读取的唯一`candidatePath`已经存在，包含D02形成的全部节目字段、视觉与封面选择、`storyWorld`及逐集故事合同。每集都有明确历史内容使命、服务它的可观察动作链、重构边界和不可替代收益；基础书是节目主体时，原书生活细节仍承担内容中心。P1能从候选复述要呈现什么生活、故事怎样承载它及最终生活后果。尚不成立时留在D02修订，触及用户明确限定则请用户决定。

### D03：反推材料并完成唯一NotebookLM闭环

先完整读取D02写入的当前`candidatePath`，只从其中已定节目和所有单集反推一份全节目最小充分材料，不凭模型记忆另造一套节目。`book-led`的一本指定书不是唯一事实来源；书外的城市机制、制度关系、普通人处境、完整过程和跨材料判断必须由独立可靠来源纠错或补足。当基础书本身是节目主体时，这些补充只能解释、校正和连接原书内容，不能凭书外研究替换单集中心。不得把“基础书内容很多”当作材料充分，也不得用来源数量代替充分性。

创建或确认Notebook后，立即把真实`notebookId`写入同一候选的`researchLibrary`；取得本次必要来源编号后增量保存到`requiredSourceIds`，`book-led`确认基础书来源后同时保存`baseBookSourceId`。未取得的编号不填占位值；材料复核返回策划步骤时也保留仍有效的身份。编号只供恢复，不代表处理完成、正文合格或可以接纳；没有返回身份的远端操作仍按未知结果边界处理。

按每集已经确定的历史内容使命，再沿`storyOutline`动作链逐步反查它怎样被呈现：基础书直接记载能承担的保持由基础书承担；任何超出原文直陈的承重关系，都必须在同一Notebook中找到能够实际进入P1 Query的原典互校、权威综合研究、专题研究、机构藏品、地图或考古资料。综合来源可以承担多集，不要求一集一本书。合成人物、合成路线和必要连接动作本身是艺术组织，不因“文献没有记载同一个人走完整条线”而失败；但它所连接的地点、行业、制度、物件状态和生活后果若只能靠常识或尚无依据的机制推断成立，就按方法文件区分待取得材料与证据不足，补齐材料或修订受影响设计，不能把缺口推给P1。

材料以能够承担当前历史生活的书籍、学术专著与史料集为主，公开论文、档案、地图和机构藏品按实际需要补充。先按内容需要选材，再决定如何取得；`topic-led`不表示无需书籍，补书也不改变`planningBasis`。优先复用委托交付的书、Notebook与有效正文；委托未指定Notebook时复用修订基线或当前候选的Notebook，先核对其来源清单和相关正文再提出找书需求。不按书数或一集一本书验收。不同视角或争议确需独立互校时保留，不能只为减少来源而省略。

无法自行合法取得的重要书籍，在会话中集中交给用户找：准确书名、作者／编者、已核实版本或ISBN及书目链接、所需章节或内容范围、承担的生活细节／关系及缺失影响，区分必需、可替代与可选；替代项明确选一本即可。章名或页码未核实就说明待目录确认，不猜造。用户可提供可读电子书、相关章节扫描件或同一Notebook来源编号；书单是材料交接，不是方案审批，不写入节目字段或另建正式清单。材料需求每次都要反推；已经齐全则说明齐全，不强行让用户找书。关键书未取得时留在D03并保留同一候选与Notebook，继续不依赖缺书的公开搜集，不重复搜索已解决的问题；不能仅因暂时拿不到书自行收窄、删集或换方向。

公开全文由执行者继续检索取得。目录、摘要、书评、出版新闻和档案入口只用于定位，不能冒充正文；存在正文链接就继续取得。公开材料必须在实际内容深度、细节和视角上足以承担同一用途，才能替代重要书。收到用户材料后核对身份、版本及所需正文可读性；缺页、仅有目录或不完整扫描继续补齐。把这些书籍、用户补充材料和公开正文统一导入。每项必要材料取得唯一`sourceId`并写入`requiredSourceIds`，`book-led`还必须把基础书来源写入`baseBookSourceId`。`requiredSourceIds`必须同时覆盖基础原典、必要的独立校正以及节目实际使用的专题范围；不另建逐集来源表、研究报告或第二Notebook。处理中的同一来源持续查询，未知结果只恢复同一对象。

材料就绪后先核对Notebook实际导入的是需要的正文，导航、目录或抽取失败不能算材料到位；再读取与当前内容使命、动作链及承重关系直接相关的章节或原文，确认它们有内容可供P1使用，并检查是否推翻、收窄或实质改变候选中的D01—D02结果；在原委托内能修正时回D02修改受影响字段并覆盖同一候选，再从更新后的候选重做受影响的材料判断。已经确认仍有效的Notebook、来源编号和就绪回执继续使用，不重复上传；必须换书、换题或换节目形式才成立时停止。不得做整季覆盖Query或把材料状态写成第二套研究成果。

材料与方向复核全部关闭后，在当前候选的`researchLibrary`中整理最终必要来源集合，确认已保存的`notebookId / requiredSourceIds`和按需存在的`baseBookSourceId`准确，并把材料导致的节目修订一并原子覆盖到同一`candidatePath`。不得另写材料版候选或保留并行策划。

完成条件：D04会读取的同一`candidatePath`已经包含完整`result`；全部必要书籍或内容等价的来源正文已经取得，用户待提供的关键材料缺口已关闭，来源属于同一Notebook且明确就绪，逐集反查后每集主行动、承重关系、观众收益和事实边界都有可进入P1 Query的证据路径，节目合同与逐集路径已按材料复核。只有来源就绪、却没有完成上述内容覆盖，不能进入D04。

### D04：反向核对并提交唯一候选

先完整读取当前`candidatePath`，不得从模型记忆重组结果。本步核对候选完整性与委托一致性：仍服从显式形式、`planningBasis`与用户约束；节目与逐集必交字段齐全；视觉、封面与片头来自工作单当前目录；`researchLibrary`只包含本次必要来源身份且已就绪。D02已核对、D03材料复核后未变化的专业内容不重复完整编辑审查；发现变化或缺口时回到真实责任步骤修订。按工作单Schema提交同一路径的唯一候选，Engine仍实时核验最终合同、Notebook身份和必要来源就绪状态，再投影正式单集任务。接纳后停止在P0。
