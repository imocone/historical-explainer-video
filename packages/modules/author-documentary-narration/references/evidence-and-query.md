# 历史纪录片P1取材与Query规则

本文件只由`author-documentary-narration`消费，保留历史纪录片既有取材路线；不服务历史解说六项合同。它把P0纪录片创作骨架变成一次最小充分取材，并规定作者怎样使用引用原文，不负责正文写法或审读。

## 输入与权威

`episodeConcept / episodeBenefit / storyOutline.meaningReveals`规定本集必须让观众看见的历史生活，`episodeThroughline / episodeCreativeBrief / storyOutline`规定承载这些内容的故事骨架与场景—意义路径，`episodeScope`锁定外边界。P0创作字段是查询和构思的正式编辑输入，不是史实来源。

具体命题只认`references[].cited_text`。NotebookLM的`answer`只帮助定位；P0字段、`source_id`、`citation_number`和后续创作大纲都不是史实来源。主体、动作、对象、结果、先后、因果、程度、数量、对白和动机只能写到原文能承担的强度，不能把不同引文拼成原文没有写明的因果。

Codex保留完整Query回执用于材料核对与恢复；作者按DN03消费的[固定作者提示](documentary-author-prompt.md)分批展开完整引用原文和出处，不把回执的`question / answer`当作新委托或创作依据。提取保留全部有效文字引用的原文、出处与原顺序，不改回执、不另建材料文件，也不替作者决定哪条入稿；同一引用中的不同主体和适用条件仍由作者辨认。

## 唯一主Query

取材服从当前集的内容分工：P0明确留给其它集的完整解释或主过程，不因同处一章、同一地点或Query一并返回就成为本集可展开内容。理解本集所需背景可以取得并简短使用；声音、地点、称呼等自然重现不必另造新含义。

在`scratchPath/notebook-query.txt`写入下面模板，直接带入当前工作单的P0原值：历史生活使用`episodeConcept / episodeBenefit / storyOutline.meaningReveals`，故事骨架使用`episodeThroughline`，故事组织完整带入`storyOutline`，创作要求使用`episodeCreativeBrief`，本集边界使用`episodeScope`。取材问题可补充说明用途，不改写委托。已经提交的提示与回执原样保留；任务是否变化由工作单业务输入决定，不以提示是否逐字包含P0判断。

```text
请从当前笔记本中找出写好这一集历史纪录片所必需的事实。你只负责取材，不写口播，也不替作者虚构现场。

本集必须呈现的历史生活：……
承载这些内容的故事骨架：……
故事组织：完整带入当前storyOutline的观察视点、中心过程、动作链、承重关系、环境、结尾与重构边界。
创作要求：……
本集边界：……
节目时长与本次正文篇幅预算：……（按当前工作单已有委托填写；预算是估算，上限不要求写满。）

先寻找能承担本集历史生活使命的直接材料：人物群体、物件、劳动、空间、时间和制度过程怎样发生或变化，哪些具体细节能让更大的城市关系和普通人处境在故事行动中被看见。再只核实当前动作链真正承重的地点、行业、制度、物件状态和生活后果；故事组织提供理解用途的上下文，不是逐项搜满或逐项入稿的清单。优先取得能解释本集核心门道的用途、限制、变化及结果，材料足以承担必要关系即可；不得为撑足篇幅继续搜集名物、感官或背景，也不得把episodeScope、路线沿途地点或storyWorld出现的行业扩成待搜全的背景购物清单。P0授权的合成人物、合成路线和必要连接动作只是艺术组织，不要求证明同一个真实个体走过全程。分别标明材料直接说明的事实、只能谨慎推论的关系，以及没有证据不能写成现场的感官、心理、对白或历史动作。每项返回少量直接原文和NotebookLM引用；同一过程已有足够的动作、细节和关系即可停止，不为凑篇幅罗列背景。
```

只有问题本身属于竞争解释、跨时期比较或失败与替代路径时，才在同一主Query末尾加入对应的反证、共同尺度或真实备选材料要求；不增加Query次数，不由最终结果倒推动机。

## 读取、补充与停止

首次取材仍按下文完整读引用。此后核对一个具体命题、但不知道它在现有Query哪条原文时，运行 `node packages/modules/author-narration/scripts/find-evidence.mjs <原Query.json绝对路径> <命题文本文件绝对路径> <本单scratch绝对路径>`。命题文件只写本次正在核对的一句话，放本单临时目录；程序从原Query筛出source_id非空、citation_number非null且cited_text非空的文字引用，保留原数组位置对应的R编号、原文和来源；无效条目不阻断其它引用，整批无有效引用仍按原补缺或停止方法处理。不先由Codex重读或改写摘要。脚本沿同一TypeSafe选择与原缓存返回实际原引用，不复制SDK或凭据；用户提供进程环境`TYPESAFE_API_KEY`或原`~/.config/typesafe/api-key`。已知出处时直接读该条，不固定再调一次API。

入口从有效文字引用中直接选出一条完整支持该命题的出处，`selected.reference`原样保留原文和来源字段；没有完整支持时返回`decision: none`及`selected: null`。Codex直接使用所选出处继续原有事实核对，不再把整批引用重选一遍。`none`表示本批没有找到完整支持，不是史实为假，也不排除局部支持或相反证据；沿下文原有方法处理确实影响本集的材料缺口，不固定重扫全部引用、不自动补查。事实错误仍须有原文证据，不能仅凭`none`退稿。服务错误单独报错，由作者按原方法完成受影响的查找，不自动重投。首次完整阅读及交给作者的全部有效文字引用保持，不新增逐句调用、审稿轮次或事实表。

主Query成功后完整阅读每条有效文字引用的`cited_text`，不要只读NotebookLM总结。同一时间、主体、行动和结果的多条引文先按互证、异载或冲突处理；只有原文明确区分时才写成两个节点。只核对现行纪录片故事组织能否由这些引用承担，不按预设高潮或完整年表寻找缺项。

只有现行`storyOutline`已经确定某项关系承担核心任务、缺少它会阻断同一故事骨架完成本集使命，并且一条具体追问能够关闭缺口时，才允许在`notebook-query-supplement.txt`写一个定点补充提示并复用原`conversation_id`。不得为非承重事件、文学细节或背景百科补Query。

主Query或补充Query已经明确返回非空答案和可确认的同一会话身份、但没有可用`references[].cited_text`时，正式脚本原样重提同一提示，连同首次最多三次；任一次取得有效引用即继续，三次均无有效引用才停止。清理失败、远端结果未知、JSON无效、会话不一致或提示词变化不进入该重提路径，只恢复同一会话；仍不能取得可确认结果时停止，由导演入口按既有正式替换路线处理。补充后材料仍不足时停止。

继续创作必须同时成立：材料足以在`episodeScope`内建立`episodeConcept`与场景—意义推进线，引用足以支撑P0指定的承重事实，最终内容能够产生本集直接相关的具体观众收益。只有核心任务仍无法完成，或必须换题、越过边界时，报告最小缺口并停止；不建立事实表、材料卡或审计报告。
