# 节目策划

只接收工作单投递的`programRequest`、`visualPackageCatalog`、`coverPackageCatalog`与`openerTemplateCatalog`。本包只处理显式`programForm=historical-explainer`；形式不同立即停止，不得从`idea / constraints`猜测或改写入口。沿用`historical-explainer`作为综合解说的正式标识。`programRequest.planningBasis`只登记用户最初给的主题、书或本地视频清单，不选择创作路线；所有选题先检索节目。指定书只读取明确路径并核对摘要，不扫描其它私人文件。P02开始只在工作单现有`candidatePath`逐步更新同一候选，最终只提交这一份`program.yaml`候选，不另交调查报告或第二份策划。

## 交给P1什么

P0交付一份`program.yaml`，其中每集都包含三部分内容：

- **已经策划好的故事**：讲什么、为什么值得看、关键经过与解释怎样相接、结果是什么，按P02的共同方法写入原六项字段。通用解说采用视频时，围绕本集问题选取和组合材料，在同一创作任务中交清从起始局面到结果的关键经过、补足的解释和回查位置。
- **本集范围与明确要求**：讲到哪里、哪些不讲，以及用户锁定的标题、叙事要求、时长等；适用要求写入本集`episodeCreativeBrief / episodeScope`，不能只留在原始委托或会话。
- **能读到的依据**：采用视频的完整校正底稿、已核读的文献正文或实际使用的NotebookLM来源，交清位置、用途与判断边界；不能只有视频名、书单、搜索摘要或打不开的链接。

Engine把六项内容、受众及按需存在的最长时长投影成`episode-brief.yaml`，并向P1投递节目编辑方向、说话气质、实际材料及所选片头与封面资源。P1不会收到整份原始委托，须能仅凭这些输入理解本集，再读依据、整理作者任务并让AGY创作。具体开头、讲述顺序、详略、语言、正文、片头、SEO与封面构思由P1完成。

## 解说类型

P0统一确定节目级`explainerType`，与`programForm / planningBasis`分开：

- 用户明确指定的类型由Director记入委托；P0原样采用`programRequest.explainerType`：`general`为通用解说，`current-affairs`为时政解说。
- 未指定时，依据当前创作目标与实际材料判断。核心是讲评新闻、政策或公共争议，让观众理解事件并跟随分析形成判断，选`current-affairs`；其它解释与故事任务选`general`。出现政治人物或政治史，不自动成为时政讲评；参考频道、材料来源和封面皮肤也不能代替判断。

将最终选择写入同一`program.yaml`候选；无显式指定时，在既有`editorialDirection`中简短交清采用该类型的创作理由，不另建分类报告。修订保留未受新要求影响的现行类型；用户改类型时由Director更新同一委托，再走原P0修订入口。旧策划缺少该字段时由P0依据当前委托和材料补齐，不默认填通用。

P1通过正式单集任务接收此选择：通用路线沿用原方法，时政路线学习《王局拍案》的讲述与推理。两类都由P0交清完整故事策划和必要材料，不预写正文开头、段落顺序或逐段推理；类型也不绑定Visual、Cover、片头或P3模板。

## 唯一取材路线

先检索已有节目 → 有合适节目就下载、通读并融合二创，用文献补足 → 无合适节目才从文献独立策划。先完整读取[节目检索与取材方法](references/video-led.md)，无论自己命题、给视频URL、已有底稿或指定书，都按这条顺序执行；共同故事策划仍在P02完成。修订只处理真实受影响内容，已完成且仍适用的检索与材料直接复用。

## 工作流程

### 短流程（Progress Checklist）

```text
- [ ] P02：形成并写入当前唯一节目与逐集方案
  - 先完成内部准备P01：核对委托并形成节目骨架
  - 节目字段、逐集六项内容合同和材料范围已写入candidatePath → P03
- [ ] P03：读取候选，取得并交清最小充分材料
  - 必要正文可读、来源定位清楚；实际采用的NotebookLM来源就绪，材料复核已写回同一候选 → P04
- [ ] P04：读取候选反向核对并提交
  - 当前候选满足工作单输出合同 → 提交

共同异常：当前策划问题留在对应步骤修正；输入材料无效或必要正文无法取得时处理实际缺口；远端结果未知只恢复同一对象，不换入口、不重复上传，也不新增报告、评分或第二套策划。
```

## 步骤说明

P01是P02方案形成前的内部调查与理解，不是独立交付步骤；两者共同形成并保存同一候选。保留内部编号供定位，执行顺序和后续材料、提交责任不变。

### P01：核对委托并形成节目骨架（P02内部准备）

1. 服从`programRequest.idea / constraints`中的真实目标和限制；`audience / episodeCount / visualPackage / coverPackage`若存在只是优先考虑的偏好。节目层`maxDurationSeconds`按P02的字段说明承接。
   工作单含`inputs.programRevision / currentProgramPath`时，先读取路径指向的现行`program.yaml`，把它作为本次修订起点。保留未受用户修改影响且仍成立的节目决定，只重做真实受影响的P01—P04判断；修改需要新事实或材料时才补相应调查与来源，不得把局部调试扩大成整季从头重来。候选接纳后停止在P0，不自动进入P1。
2. 按已读的节目检索与取材方法，结合题目、用户提供的视频和书中主题，搜索同题或相近节目。取得并通读选中节目的底稿，弄清基本经过和各来源的贡献。只有实际检索后没有合适节目，才从可靠文献形成故事，不能预先选独立创作。
3. 结合委托、受众和已读内容，初步判断中心问题、推进关系、编辑角度、集数、集序、逐集边界与收益，为P02选择主线和形成大纲准备。热度只帮助理解受众，不裁决事实或内容质量。指定书与其它正文用于补足、校正或独立创作，不按书章节拆集，不另设书源路线。

完成条件：当前委托已核实，节目检索及必要的正文理解已完成，能够据此形成P02的节目骨架；检索或材料取得失败时处理实际缺口，不把失败记成无合适节目。

### P02：形成唯一节目与逐集方案

先完整读取[单集策划方法](references/explainer-planning-method.md)，按故事范围、委托时长、必要经过和已有依据确定逐集方案。

4. 确定节目层内容：
   - `schemaVersion / programForm`：固定写`7.3 / historical-explainer`；
   - `explainerType`：按上文“解说类型”保存P0最终选择；用户指定时与委托一致，不因初始材料不同而省略；
   - `visualPackage / coverPackage`：分别从工作单当前Visual和Cover目录选择实际ID与版本，不互相替代。首次采用用户指定且仍有效的Visual，未指定时选择`wet-watercolor`；修订优先采用用户指定且有效的Visual；未指定时沿用仍在目录内且适合当前方向的Visual ID，版本取当前目录；原包已下架时，按用户给出的修订要求从当前目录重新选择。Cover选当前唯一的`type-first-editorial`。Visual提供画法与字体，Cover提供横竖封面版式与外观；本集可见文字和场面由P1设计，P0不预写封面。
   - `openerTemplate`：从工作单`openerTemplateCatalog`选一个ID写入节目配置；首次使用`programRequest.openerTemplate`，未指定则使用目录标记`defaultSelected`的片头。修订时保留当前节目选择，只有用户明确要求才更换；不按纪录片或解说形式猜选。
   - `seriesTitle`：全系列稳定使用的简洁展示名，能够代表整套节目而不是某一集。封面确需系列识别时使用此正式名称，不强制上图；采用用户已确定的名称，不附加宣传副标题或单集看点，详细表达放在既有策划方向与观众收益中。修订时除非用户要求改名，否则保留现行值；
   - `audience`：第一受众为何会点进来、带着什么前置知识观看；文化兴趣、职业或圈层可以是进入渠道，但不能被误写成观看门槛。除非用户另有要求，熟悉题材的专家不是泛内容节目的默认第一受众；
   - `editorialDirection`：承接委托中的当前节目编辑方向，说明节目选择什么角度、为什么值得做、与常见内容有什么区别；修订工作单有现行`program.yaml`时，除非委托明确改变，保留仍符合当前目标与约束的编辑方向；
   - `viewerBenefit`：从真实受众需求反推观众看完整套节目具体多会理解或判断什么，不写“增长知识、获得启发”这类换成任何题材都成立的空收益；
   - `narrativeTone`：一句自然语言说明说话气质，不写形容词清单；
   - `seriesFramework`：用自然语言说明节目整体怎样成立、为什么拆成这些集、各集怎样分工或递进并共同兑现观众收益；策划时优先让喜欢其中一集的第一受众，能够基于同一种观看理由继续选择其它集，而不是靠上一集没讲完或下一集预告维持。交清整体逻辑和集间分工，具体单集故事写入`episodeCreativeBrief`，不在此重复抄写；
   - `maxDurationSeconds`：委托明确提供统一上限时原样填写，否则省略。P0据此定范围和拆集，Engine将它原样传给P1，作者据此安排包含片头的整集篇幅。
5. 按已读方法形成每集六项内容，把完整故事、委托要求和材料定位写进原有字段；材料入口不同不改变交付。实际采用视频时，按节目取材方法交清来源身份与可参考的讲法。
6. 按单集策划方法走一遍各集实际故事，确认没看过前集的观众也能理解关键经过和结果。核对集间分工及委托一致性，修正发现的具体缺口。
7. 在原委托目标与限制内裁定唯一方案，直接进入材料闭环；P0授权已包含这项编辑裁决，不另索确认。关键材料仍须按P03取得，不能以连续执行为由缺书提交。

   方案形成后，立即按工作单候选外壳把当前`taskDigest`和P02已经形成的`result`原子写入唯一`candidatePath`。尚未在P03取得的`researchLibrary`字段此时省略，不填写占位Notebook或来源编号；这只是供P03读取的当前阶段草稿，不得提前提交或接纳。P02因材料复核返回时，保留仍成立的节目字段并原子覆盖同一路径，不另建修订稿。

完成条件：P03将读取的唯一`candidatePath`已经存在；其中当前`result`包含P02能够形成的全部节目字段、视觉选择和逐集六项内容合同，且`audience / viewerBenefit / seriesFramework`均已写到能够改变下游决定，每集答案能够独立闭合，集间没有实质重复，材料范围能够承载。问题仍靠相邻集补足、单集合同内部不成立或材料范围无法承载时，留在P02修正；“同一批人是否还会点下一集”和“本集是否补齐整季独有一块”只作优化，不属于本完成条件。

### P03：由节目方案反推材料并闭环

先完整读取P02写入的当前`candidatePath`，只从其中的节目字段和逐集六项合同开始材料判断，不凭模型记忆另造一套方案。已有委托Notebook、修订基线或当前候选中的Notebook时，先读取其来源清单与相关正文，避免重复找书或导入。采用视频时先用已完整读过的参考正文核对故事和解释链是否有归属、材料是否足够；已经依据中心问题舍弃的内容不为覆盖来源补回。只补关键缺口，不从书目搜集重来；下列取得与恢复方法按实际采用的材料使用。

实际采用NotebookLM时，创建或确认Notebook后，立即把真实`notebookId`写入同一候选的`researchLibrary`；取得本次必要来源编号后增量保存到`requiredSourceIds`，`book-led`实际导入基础书后同时保存`baseBookSourceId`。未取得的编号不填占位值；材料复核返回策划步骤时也保留仍有效的身份。编号只供恢复，不代表处理完成、正文合格或可以接纳；没有返回身份的远端操作仍按未知结果边界处理。

8. 从候选的节目框架和逐集六项字段，按[共同材料方法](references/explainer-planning-method.md#材料是否足够)反推全节目最小充分需求，遵守[六项字段的创作边界](references/explainer-planning-method.md#写入六项字段)。先取共同背景和核心机制，再补不可替代的个案、制度、考古、图像或专题材料；历史可用书籍、专著与史料集，时事优先原始声明、公开数据、可靠报道和必要研究。先判断内容需要，不因网上容易找到而降低标准。复用已有有效正文，公开、本地与NotebookLM可组合；不强制找书或建库，不因补料改变委托目标。用户观点融入既有任务，未核实的保持待检验；时事交清资料截止日期，区分事实、来源判断与预测。
9. 每项材料先核对准确书名或篇名、作者或编者、版本、最需要的卷章或材料对象，以及它关闭的节目缺口，再据此取得真实来源；不另存报告。独立缺口可以跨集共享，不是分集来源映射；一项材料能关闭多个缺口时只取一次。同用途且内容重复的材料优先保留最准确、最能提供人物行动、机制、变化和具体情境的一项；争议、因果或不同当事人视角需要独立互校时可以选多项，互校本身就是必要用途。身份拿不准时先用公开目录、出版机构或论文数据库核对，不得猜造。不要写“找权威论文”“补史料”这类无法执行的任务，不按集平均配材料，也不为保险堆材料。

   重要书籍无法自行合法取得时，主动在会话中集中交给用户找：逐本给出准确书名、作者／编者、已核实的版本或ISBN及书目链接、需要的章节或内容范围、用途和缺失后哪项解释无法成立；标明必需、可替代或可选，替代书说明选一本即可。未核实的章名、版本或页码不猜写，可以先索取目录确认范围。说明可提供可读电子书、相关章节扫描件或已导入同一Notebook的来源编号。不要只说“请补权威材料”，也不要让用户重复找已取得的书。书单是给用户取得材料的会话交接，不写入节目字段，不新增正式书单或第二候选。

   同时自行检索公开全文和现有合法资料，不把常规网页、公开论文与档案搜集甩给用户。目录页、书评、摘要、出版新闻和馆藏入口只用于发现材料，不能冒充书或论文正文；有正文链接就继续取得正文。只有实际读到的公开内容确能承担相同细节、因果及视角时才能替代重要书；没有证据证明等价就保留找书需求，不能以书目页面已ready或某机构权威为由取消。材料需求每次都要反推；已经齐全则说明齐全，不强行让用户找书。关键书尚缺时留在P03，保留同一候选与Notebook并继续独立可做的搜集，不重复搜索已解决的问题，不提交、不自行删集或改方向来绕过等待。
10. 对实际采用的公开或本地正文，在本集`episodeCreativeBrief`交清标题、URL或可读取的绝对路径、必要页段及用途；用到指定书时保留书名、版本、原路径与摘要。易变、受限或无法直接读取的网页，保存本次核读的相关原文并交本地路径，同时保留原URL；已有可读原件或Notebook正文直接复用，不为交接另抄一份。P1须能读到关键经过与解释的上下文，位置不能代替正文取得，也不要求把原文塞进策划字段。各集可以引用同一来源，不另建来源映射或材料库；P1再按自己的取材方法保存本次使用的依据。

   需要集中查询或复用NotebookLM材料时，优先复用委托指定的Notebook；未指定时复用修订基线或当前候选中的Notebook，没有才建立一个。先读来源清单及相关正文，只补实际缺项，不把全库ready来源当必要材料。用户交书后核对版本及正文可读性，只有封面或目录不能计作取得。实际用于本次节目且已导入的材料须有唯一来源编号，写入`requiredSourceIds`；指定基础书若已导入，再写`baseBookSourceId`并包含在前者中，不为生成编号强制上传本地书。只使用一个节目Notebook。来源仍在处理时查询原编号至就绪或明确失败；加入结果未知只恢复同一对象，不重复上传、另建Notebook或换工具掩盖未知结果。未使用NotebookLM时省略`researchLibrary`，不填写虚构编号。

11. 材料缺口按方法区分尚未取得与证据不支持；后者只修订受影响部分，触及用户明确限定时等待决定。使用NotebookLM时，来源就绪后核对实际导入的是所需正文，而非目录、导航或抽取失败的空壳；缺页或不可读留在P03补齐同一材料。全部必要材料取得后，只读取这些材料中与候选`seriesFramework`、逐集六项合同或边界直接相关的必要章节或原文，确认它们能实际支撑所需行动、过程、承重解释与争议边界，再检查是否推翻、收窄或实质改变当前方向；不为此发起整季覆盖查询、分集覆盖查询、证据核验轮，也不另写第二套策划。没有实质变化就继续；有变化就回P02在原委托目标与限制内修订受影响字段并覆盖同一候选，再从更新后的候选重做受影响的材料判断。已经确认仍有效的Notebook、来源编号和就绪回执继续使用，不重复上传。`requiredSourceIds`只证明候选声明的本次必要来源属于该Notebook且接纳时已就绪，不证明逐集材料覆盖；P1按当前工作单的实际来源读取正文或查询引用。

   材料与方向复核全部关闭后，核对创作任务中的正文定位；实际使用NotebookLM时，再在当前候选的`researchLibrary`中整理最终必要来源集合，确认已保存的编号准确，并把材料导致的节目修订一并原子覆盖到同一`candidatePath`。不得另写材料版候选或保留并行策划。

完成条件：P04会读取的同一`candidatePath`已经包含完整`result`；必要正文已取得并核对，P1可用的来源定位已交清；实际声明的NotebookLM来源均有真实回执并全部就绪，用户待提供的关键材料缺口已关闭，材料带来的方向修订已经写回候选，未留下另一套策划或未处理的中心框架冲突。远端对象未终态时留在P03恢复同一对象。

### P04：提交唯一P0成果

12. 先完整读取当前`candidatePath`，核对P1将收到的故事、范围与要求、材料依据是否交全，并与委托一致；不得从模型记忆重组结果。P02已形成、P03已复核且未变化的内容不重复完整编辑审查。把其中策划与工作单`programRequest`逐项比较，确认仍服从显式目标、约束并保留用户实际提供的材料身份。实际采用NotebookLM时，再核对`requiredSourceIds`恰好是本次认定的最小充分材料来源回执而不是整个Notebook来源清单，并确认每项都已就绪。视觉包、封面包和片头必须分别来自工作单投递的当前目录；只换其中一项时保持内容策划与材料原值，不扩大为整季返工。
13. 严格按工作单`outputContract`反查并提交这个同一路径中的唯一`result`，不在Skill中复制第二份字段合同。未使用NotebookLM时省略`researchLibrary`；使用时，`topic-led`必须省略`baseBookSourceId`；`requiredSourceIds`只写本次全节目最小充分材料的来源编号，不写来源标题、书目卷章、缺口说明或逐集映射。候选不写策划入口、基础书关系说明、完整Notebook来源清单、平台调研、确认记录、NotebookLM查询报告、正式路径、`_producer`、过程状态或单集文件副本。Engine接纳时重新读取候选，实时拒绝任一`requiredSourceId`不存在或未就绪的结果；接纳后负责一次建齐每集`制作/input`、`制作/p0`至`制作/p4`和`output`目录，并从`program.yaml`投影唯一`episode-brief.yaml`；缺少任何一项时P0不成立。

完成条件：候选服从当前委托并如实交接实际采用材料，六项内容合同与材料回执恰好覆盖本次最小充分集合，视觉包与封面包选择来自工作单允许范围，并通过工作单当前输出合同；随后提交唯一候选。任何缺口回到其真实上游步骤，不在P04补第二份说明。
