# 节目策划

只接收工作单投递的`programRequest`、`visualPackageCatalog`、`coverPackageCatalog`与`openerTemplateCatalog`。本包只处理显式`programForm=historical-explainer`；形式不同立即停止，不得从`idea / constraints`猜测或改写入口。沿用`historical-explainer`作为综合解说的正式标识。`programRequest.planningBasis`只决定骨架来源，不决定取材工具；`book-led`只能读取指定且摘要匹配的基础书，不得顺手扫描其它私人文件。P02开始只在工作单现有`candidatePath`逐步更新同一候选，最终只提交这一份`program.yaml`候选；研究过程、基础书关系说明、书目卷章、缺口说明和确认记录都不是正式成果。

## 解说类型

三种策划入口都在P0确定节目级`explainerType`，与`programForm / planningBasis`分开：

- 用户明确指定的类型由Director记入委托；P0原样采用`programRequest.explainerType`：`general`为通用解说，`current-affairs`为时政解说。
- 未指定时，依据当前创作目标与实际材料判断。核心是讲评新闻、政策或公共争议，让观众理解事件并跟随分析形成判断，选`current-affairs`；其它解释与故事任务选`general`。出现政治人物或政治史，不自动成为时政讲评；参考频道、材料来源和封面皮肤也不能代替判断。

将最终选择写入同一`program.yaml`候选；无显式指定时，在既有`editorialDirection`中简短交清采用该类型的创作理由，不另建分类报告。修订保留未受新要求影响的现行类型；用户改类型时由Director更新同一委托，再走原P0修订入口。旧策划缺少该字段时由P0依据当前委托和材料补齐，不默认填通用。

P1通过正式单集任务接收此选择：通用路线沿用原方法，时政路线学习《王局拍案》的讲述与推理。P0仍只交清内容任务和必要材料，不因此预写正文开头、段落顺序或推理展开；类型也不绑定Visual、Cover、片头或P3模板。

## 单集篇幅

三种策划入口均按故事体量、内容完整性、事件或解释的连续关系和集间分工确定单集范围。较大的故事可按10—20分钟的常见展开空间考虑关键经过、必要解释与后果，避免把完整过程压成节点摘要；小故事按实际内容讲完整即可，不为达到10分钟扩写或拼接。这个区间是较大故事的规模参考，不是所有单集的最低长度、固定目标或硬上限，也不换算成统一字数。一个完整过程的起因、关键行动与结果应共同成立；相邻内容共同回答一个问题时可以合讲，独立故事各自成立时可以分集，不为时长拆散过程，也不为减少集数省掉关键经过。

在现有`episodeCreativeBrief`中结合本集内容简短交代展开意图与明确委托的时长要求，保留其弹性，不给每集编造分钟数或长短标签；具体篇幅由P1[作者任务方法](../author-narration/references/author-task-editing.md)交给作者按本集实际内容决定。用户或平台的明确时长要求优先；`maxDurationSeconds`仍只承接明确的最长时长，不能从上述参考区间自动填入1200秒。只有存在明确上限时，才据此调整无法容纳的范围与拆合。

## 参考节目入口

`planningBasis.kind=video-led`时先完整读取并执行[`references/video-led.md`](references/video-led.md)。该分支拥有整体理解、拆合集数、完整故事策划与叙事参考、取材依据交接；只复用下面P02的节目字段与目录选择、P04的唯一候选提交，不执行普通P01调研和整套P03材料反推；确需补充资料时按P03的取得、定位及远端恢复方法处理，不使用普通六项方法中的禁止故事骨架条款。修订已有正式节目时以工作单指定的现行节目为起点；尚未接纳而中途改要求时从新工作单及当前草稿继续。

以下P01—P04的研究方法仅用于topic-led和book-led。

## 工作流程

### 短流程（Progress Checklist）

```text
- [ ] P02：形成并写入当前唯一节目与逐集方案
  - 先完成内部准备P01：核对委托并形成节目骨架
  - 节目字段、逐集六项内容合同和材料范围已写入candidatePath → P03
- [ ] P03：读取候选，取得并交清最小充分材料
  - 必要正文可读、来源定位清楚；实际采用的NotebookLM来源就绪，材料复核已写回同一候选 → P04
- [ ] P04：读取候选反向核对并提交
  - 当前候选满足工作单输出合同 → 提交

共同异常：当前策划问题留在对应步骤修正；指定基础书或必要材料使原入口不能成立时按真实边界停止；远端结果未知只恢复同一对象，不换入口、不重复上传，也不新增报告、评分或第二套策划。
```

## 步骤说明

P01是P02方案形成前的内部调查与理解，不是独立交付步骤；两者共同形成并保存同一候选。保留内部编号供定位，执行顺序和后续材料、提交责任不变。

### P01：核对委托并形成节目骨架（P02内部准备）

1. 服从`programRequest.idea / constraints`中的真实目标和限制；`audience / episodeCount / visualPackage / coverPackage`若存在只是优先考虑的偏好。节目层`maxDurationSeconds`只承接用户或平台明确提出的统一规划上限；委托没有填写时P0省略字段。该字段只帮助P0判断题目范围和拆集，不成为P1正文接纳门。
   工作单含`inputs.programRevision / currentProgramPath`时，先读取路径指向的现行`program.yaml`，把它作为本次修订起点。保留未受用户修改影响且仍成立的节目决定，只重做真实受影响的P01—P04判断；修改需要新事实或材料时才补相应调查与来源，不得把局部调试扩大成整季从头重来。候选接纳后停止在P0，不自动进入P1。
2. 只按`planningBasis`决定节目框架怎样形成：
   - `topic-led`：以`idea`为起点，从公开调研和可靠资料形成对题材范围、关键关系、争议和候选内容的初始理解。
   - `book-led`：先核对指定绝对路径的文件摘要；文本可读就直接读，只有无法可靠读取时才按需OCR。从书中提炼所讲对象怎样展开、维持或变化的叙事框架；提炼的是内容，不是目录、章节、作者修辞或必须服从的作者结论，基础书也不限定节目只能使用书内事实和材料。
3. 两路采用相同的可信度要求；调查深度由现有证据、争议和未解决问题决定，并据此形成节目骨架：
   - 判断第一受众为什么会看、带着什么前置知识、零基础观众靠什么熟悉对象／矛盾／结果进入；
   - 抽样与题材和受众最相关的同类节目，不只看爆款；公开字段足以比较且对当前判断有用时，可比较同频道或同类、相近发布时间和形式的高于常态、接近常态与低于常态样本，不要求凑齐三类；据适用样本判断自然用词、熟悉锚点、陌生观众入口、标题承诺、单集利益、已经做滥的角度与讲法、内容空位和适合的拆集颗粒度；
   - 用可靠公共资料、出版目录或可核对书目校正题材范围、事实、关系、因果、争议和作者立场；`book-led`还要围绕书源框架补齐讲清同一段历史所必需的背景、机制、视角和材料；
   - 综合节目目标、受众需求和可靠研究，决定最终题材范围、核心问题、主要推进关系、产品角度、实际集数、集序、逐集边界、单集母标题和观众收益。`topic-led`在调查中形成节目骨架；`book-led`以经调查校正和补全的书源框架形成节目骨架，可以合并、拆分、重排和补充书中内容，但不能照章讲书。

   平台始终只是发现池，不是历史事实来源；播放与互动不能证明标题因果或内容质量。受众与平台调查可以改变节目角度、重点、拆集边界和集数，但不能替P1决定具体故事入口或事实呈现顺序，`book-led`也不能因此另换中心故事；平台热度本身不能裁决历史事实。调研足以支持或修正“做不做、给谁看、做什么角度和做几集”的决定就停止扩展，不保存平台报告、评分表或候选堆。

   `book-led`是书起骨架、调研校正补全，不是讲书，也不是只信这本书。补充材料不能另造一档节目；可靠研究若表明基础书框架本身站不住，或补全后最终可用的中心框架主要来自其它材料，就停止，请用户更换基础书或明确改走`topic-led`。不为保住标签弱化判断，也不新增身份评分、映射矩阵或第二套策划。

完成条件：`planningBasis`、指定基础书或主题入口、节目真实目标与限制已经核实；调查已经形成P02会使用的题材范围、第一受众、中心问题、主要推进关系、产品角度和候选拆集颗粒度。入口或基础书本身不成立时停止，P02不得开始。

### P02：形成唯一节目与逐集方案

先完整读取[`references/explainer-planning-method.md`](references/explainer-planning-method.md)。该文件是综合解说六项内容合同、观众旅程和材料边界的唯一策划方法；本Skill不复制第二套写法。

4. 确定节目层内容：
   - `schemaVersion / programForm`：固定写`7.3 / historical-explainer`；
   - `explainerType`：按上文“解说类型”保存P0最终选择；用户指定时与委托一致，三种材料入口均须填写；
   - `visualPackage / coverPackage`：Visual从工作单的视觉目录选择：首次优先使用委托中明确且仍在目录内的选择，否则根据节目题材和受众选择；修订保留现行Visual，只有用户明确要求或节目方向变化使原选择不再成立时才更换。Cover使用封面目录中的唯一type-first-editorial，不再按题材分选。Visual提供正片及封面人物器物的画法和各用途字体；Cover拥有文字材质、配色、层级、配套横竖排版及配图的视觉强弱，画法与字体接入所选Visual。封面跨题材使用亮字与暗色满幅配图的关系；本集可见文字和场面由P1独立设计，不强制系列名、集号或A/B/C。两项选择仍独立，不能用Cover替代Visual；
   - `openerTemplate`：从工作单`openerTemplateCatalog`选一个ID写入节目配置；首次使用`programRequest.openerTemplate`，未指定则使用目录标记`defaultSelected`的片头。修订时保留当前节目选择，只有用户明确要求才更换；不按纪录片或解说形式猜选。
   - `seriesTitle`：全系列稳定使用的简洁展示名，能够代表整套节目而不是某一集。封面确需系列识别时使用此正式名称，不强制上图；采用用户已确定的名称，不附加宣传副标题或单集看点，详细表达放在既有策划方向与观众收益中。修订时除非用户要求改名，否则保留现行值；
   - `audience`：第一受众为何会点进来、带着什么前置知识观看；文化兴趣、职业或圈层可以是进入渠道，但不能被误写成观看门槛。除非用户另有要求，熟悉题材的专家不是泛内容节目的默认第一受众；
   - `editorialDirection`：承接委托中的当前节目编辑方向，说明节目选择什么角度、为什么值得做、与常见内容有什么区别；修订工作单有现行`program.yaml`时，除非委托明确改变，保留仍符合当前目标与约束的编辑方向；
   - `viewerBenefit`：从真实受众需求反推观众看完整套节目具体多会理解或判断什么，不写“增长知识、获得启发”这类换成任何题材都成立的空收益；
   - `narrativeTone`：一句自然语言说明说话气质，不写形容词清单；
   - `seriesFramework`：用自然语言说明节目整体怎样成立、为什么拆成这些集、各集怎样分工或递进并共同兑现观众收益；策划时优先让喜欢其中一集的第一受众，能够基于同一种观看理由继续选择其它集，而不是靠上一集没讲完或下一集预告维持。`book-led`必须在这里落实经校正和补全的书源框架，而不是概述书的章节。它不是集数表、流程表或写作模板，也不写任一单集的人物事件清单、证据顺序、故事主线或主要内容；
   - `maxDurationSeconds`：仅在委托明确提供时原样承接为整套节目每集的规划上限；省略即没有该规划条件。若存在，Engine会把它投影进P1的`episode-brief`与作者入口；它不是正文接纳字数门。
5. 按已读方法形成每集唯一六项内容合同；字段写法、观众旅程、适用的专业判断和材料可信度要求由该方法集中规定，不另造故事大纲或第二套策划。
6. 在方案形成时核对内容是否成立：每集问题与答案独立闭合，六项互相兑现，集间没有实质重复，节目框架与委托一致。按方法修正受影响部分；不为同一内容重复进行完整编辑审查。
7. 在`programRequest`的目标、约束和显式`planningBasis`内确定唯一节目方案，包括节目层全部内容、实际集数、每集六项内容合同、按需存在的节目统一最长时长、最终视觉包与封面包，然后直接进入材料闭环。P0开始授权已经包含这项编辑裁决，不展示方案索要确认；材料取得与必要的用户找书交接在P03继续，不能把连续执行理解成缺书也必须提交。使用基础书方式时，仍在内部核对书源框架怎样被提炼、校正和补全，确保节目是在讲这段历史而不是讲书；不要求按章拆集，也不把这段说明写入正式结果。

   方案形成后，立即按工作单候选外壳把当前`taskDigest`和P02已经形成的`result`原子写入唯一`candidatePath`。尚未在P03取得的`researchLibrary`字段此时省略，不填写占位Notebook或来源编号；这只是供P03读取的当前阶段草稿，不得提前提交或接纳。P02因材料复核返回时，保留仍成立的节目字段并原子覆盖同一路径，不另建修订稿。

完成条件：P03将读取的唯一`candidatePath`已经存在；其中当前`result`包含P02能够形成的全部节目字段、视觉选择和逐集六项内容合同，且`audience / viewerBenefit / seriesFramework`均已写到能够改变下游决定，每集答案能够独立闭合，集间没有实质重复，材料范围能够承载。问题仍靠相邻集补足、单集合同内部不成立或材料范围无法承载时，留在P02修正；“同一批人是否还会点下一集”和“本集是否补齐整季独有一块”只作优化，不属于本完成条件。

### P03：由节目方案反推材料并闭环

先完整读取P02写入的当前`candidatePath`，只从其中的节目字段和逐集六项合同开始材料判断，不凭模型记忆另造一套方案。已有委托Notebook、修订基线或当前候选中的Notebook时，先读取其来源清单与相关正文，避免重复找书或导入。

实际采用NotebookLM时，创建或确认Notebook后，立即把真实`notebookId`写入同一候选的`researchLibrary`；取得本次必要来源编号后增量保存到`requiredSourceIds`，`book-led`实际导入基础书后同时保存`baseBookSourceId`。未取得的编号不填占位值；材料复核返回策划步骤时也保留仍有效的身份。编号只供恢复，不代表处理完成、正文合格或可以接纳；没有返回身份的远端操作仍按未知结果边界处理。

8. 按候选中的`seriesFramework`和全部单集母标题、问题、答案、创作任务、覆盖边界与单集收益反推全节目一份最小充分材料需求。沿每集创作任务中写明的对象、关系、矛盾、变化、比较、检验、区分与后果，检查历史主体、制度、数量、时序、因果、比较尺度和具体后果是否都有P1可读取的可靠正文；材料准备仍遵守[六项方法的创作边界](references/explainer-planning-method.md#六项合同共同成立)。`book-led`新增材料只关闭书源框架中的真实缺口，不借材料准备另换中心故事。材料需求保持一份，不按集分包，不建立某集到某几个来源的映射。先找能支撑全节目共同背景和核心机制的材料，再补真正不可替代的个案、制度、考古、图像或专题材料。按题材选材料：历史解释可用书籍、学术专著和史料集，时事优先用原始声明、公开数据、可靠报道和必要研究，地图及机构资料按实际用途补充；先判断需要什么，再判断如何取得，不按网上是否容易找到反过来降低材料标准。复用委托已交付的书和既有Notebook有效正文；`topic-led`只表示从主题起骨架，不强制找书，也不因补书改成`book-led`。网络正文、本地书稿和NotebookLM可单独使用或组合。用户观点融入现有问题、答案与创作任务；尚待核实的看法保持待检验性质。时事在创作任务或范围中写清资料截止日期，区分已发生事实、来源判断和未来预测。
9. 每项材料先核对准确书名或篇名、作者或编者、版本、最需要的卷章或材料对象，以及它关闭的节目缺口，再据此取得真实来源；不另存报告。独立缺口可以跨集共享，不是分集来源映射；一项材料能关闭多个缺口时只取一次。同用途且内容重复的材料优先保留最准确、最能提供人物行动、机制、变化和具体情境的一项；争议、因果或不同当事人视角需要独立互校时可以选多项，互校本身就是必要用途。身份拿不准时先用公开目录、出版机构或论文数据库核对，不得猜造。不要写“找权威论文”“补史料”这类无法执行的任务，不按集平均配材料，也不为保险堆材料。

   重要书籍无法自行合法取得时，主动在会话中集中交给用户找：逐本给出准确书名、作者／编者、已核实的版本或ISBN及书目链接、需要的章节或内容范围、用途和缺失后哪项解释无法成立；标明必需、可替代或可选，替代书说明选一本即可。未核实的章名、版本或页码不猜写，可以先索取目录确认范围。说明可提供可读电子书、相关章节扫描件或已导入同一Notebook的来源编号。不要只说“请补权威材料”，也不要让用户重复找已取得的书。书单是给用户取得材料的会话交接，不写入节目字段，不新增正式书单或第二候选。

   同时自行检索公开全文和现有合法资料，不把常规网页、公开论文与档案搜集甩给用户。目录页、书评、摘要、出版新闻和馆藏入口只用于发现材料，不能冒充书或论文正文；有正文链接就继续取得正文。只有实际读到的公开内容确能承担相同细节、因果及视角时才能替代重要书；没有证据证明等价就保留找书需求，不能以书目页面已ready或某机构权威为由取消。材料需求每次都要反推；已经齐全则说明齐全，不强行让用户找书。关键书尚缺时留在P03，保留同一候选与Notebook并继续独立可做的搜集，不重复搜索已解决的问题，不提交、不自行删集或改方向来绕过等待。
10. 对已读的公开正文和本地材料，在相关`episodeCreativeBrief`的材料定位段交清标题、实际URL或可读取的绝对路径、必要页段及用途；指定书须保留原指定书名、版本、路径与摘要，P1据此读取原书，不重新猜搜。材料定位可以跨集重复引用同一来源，不另建来源映射、事实卡或第二份材料库。P0交的是定位，P1仍须实际读取正文并保存本次使用的原文。

   需要集中查询或复用NotebookLM材料时，优先复用委托指定的Notebook；未指定时复用修订基线或当前候选中的Notebook，没有才建立一个。先读来源清单及相关正文，只补实际缺项，不把全库ready来源当必要材料。用户交书后核对版本及正文可读性，只有封面或目录不能计作取得。实际用于本次节目且已导入的材料须有唯一来源编号，写入`requiredSourceIds`；指定基础书若已导入，再写`baseBookSourceId`并包含在前者中，不为生成编号强制上传本地书。只使用一个节目Notebook。来源仍在处理时查询原编号至就绪或明确失败；加入结果未知只恢复同一对象，不重复上传、另建Notebook或换工具掩盖未知结果。未使用NotebookLM时省略`researchLibrary`，不填写虚构编号。

11. 材料缺口按方法区分尚未取得与证据不支持；后者只修订受影响部分，触及用户明确限定时等待决定。使用NotebookLM时，来源就绪后核对实际导入的是所需正文，而非目录、导航或抽取失败的空壳；缺页或不可读留在P03补齐同一材料。全部必要材料取得后，只读取这些材料中与候选`seriesFramework`、逐集六项合同或边界直接相关的必要章节或原文，确认它们能实际支撑所需行动、过程、承重解释与争议边界，再检查是否推翻、收窄或实质改变当前方向；不为此发起整季覆盖查询、分集覆盖查询、证据核验轮，也不另写第二套策划。没有实质变化就继续；有变化就回P02在原`programRequest`与原`planningBasis`内修订受影响字段并覆盖同一候选，再从更新后的候选重做受影响的材料判断。已经确认仍有效的Notebook、来源编号和就绪回执继续使用，不重复上传。如果材料使`book-led`中心框架不再成立，按第3步停止，不得静默换书或改走`topic-led`。`requiredSourceIds`只证明候选声明的本次必要来源属于该Notebook且接纳时已就绪，不证明逐集材料覆盖；P1按当前工作单的实际来源读取正文或查询引用。

   材料与方向复核全部关闭后，核对创作任务中的正文定位；实际使用NotebookLM时，再在当前候选的`researchLibrary`中整理最终必要来源集合，确认已保存的编号准确，并把材料导致的节目修订一并原子覆盖到同一`candidatePath`。不得另写材料版候选或保留并行策划。

完成条件：P04会读取的同一`candidatePath`已经包含完整`result`；必要正文已取得并核对，P1可用的来源定位已交清；实际声明的NotebookLM来源均有真实回执并全部就绪，用户待提供的关键材料缺口已关闭，材料带来的方向修订已经写回候选，未留下另一套策划或未处理的中心框架冲突。远端对象未终态时留在P03恢复同一对象。

### P04：提交唯一P0成果

12. 先完整读取当前`candidatePath`，不得从模型记忆重组结果。本步核对当前候选的完整性与委托一致性；P02已形成、P03已复核且未变化的内容不重复完整编辑审查。把其中策划与工作单`programRequest`逐项比较，确认仍服从显式目标、约束和`planningBasis`。实际采用NotebookLM时，再核对`requiredSourceIds`恰好是本次认定的最小充分材料来源回执而不是整个Notebook来源清单，并确认每项都已就绪。视觉包、封面包和片头必须分别来自工作单投递的当前目录；只换其中一项时保持内容策划与材料原值，不扩大为整季返工。
13. 严格按工作单`outputContract`反查并提交这个同一路径中的唯一`result`，不在Skill中复制第二份字段合同。未使用NotebookLM时省略`researchLibrary`；使用时，`topic-led`必须省略`baseBookSourceId`；`requiredSourceIds`只写本次全节目最小充分材料的来源编号，不写来源标题、书目卷章、缺口说明或逐集映射。候选不写策划入口、基础书关系说明、完整Notebook来源清单、平台调研、确认记录、NotebookLM查询报告、正式路径、`_producer`、过程状态或单集文件副本。Engine接纳时重新读取候选，实时拒绝任一`requiredSourceId`不存在或未就绪的结果；接纳后负责一次建齐每集`制作/input`、`制作/p0`至`制作/p4`（含`制作/p4`）和`output`目录，并从`program.yaml`投影唯一`episode-brief.yaml`；缺少任何一项时P0不成立。

完成条件：候选逐项服从当前`programRequest`与显式`planningBasis`，六项内容合同与材料回执恰好覆盖本次最小充分集合，视觉包与封面包选择来自工作单允许范围，并通过工作单当前输出合同；随后提交唯一候选。任何缺口回到其真实上游步骤，不在P04补第二份说明。
