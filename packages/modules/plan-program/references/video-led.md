# 从参考节目形成创作任务

只用于`historical-explainer / video-led`。P0完整读懂指定单集或系列，吸收选题和故事结构，决定我们做几集、每集讲什么，交出能直接用于重新创作的完整故事策划与取材依据。原节目叙事方法同时传下去供参考。原节目是本次材料基线，不默认反推书单或另建NotebookLM，不做无差别独立事实核查，不分析画面或剪辑。委托明确要求而原节目没有讲清，或本集主体所依赖的关键因果、专名、数字在原片中存疑时，针对实际缺口读可公开核对的原始文献或研究相关正文；区分补充来源与原节目各自承担的内容。需要已有NotebookLM材料时可按包根P03复用查询，工具由缺口决定，不改变视频策划入口。用户想法融入现有问题、答案与创作任务；与材料冲突或仍属推测的部分明确保留判断边界。时事写清资料截止日期，只补会影响本集结论的更新。找不到足以支撑的正文，就收窄判断或重定集界，不把主体缺口留给P1补。

## 取得并读懂材料

指定频道时先枚举公开视频与相关播放列表，以视频 ID 去重；用户排除短视频时核对 Shorts 栏目，不凭时长阈值误删较短的普通长视频。结合标题、简介、章节与系列关系识别题材，正文再确认本次题材相关段落；问答或跨朝代节目保留完整原材料，只选相关内容入策划。没有访问到的范围如实说明，不把标题检索称为正文穷尽。

已有完整底稿直接使用，不重新下载或转录。缺材料时统一通过 `uvx --from 'yt-dlp[default]' yt-dlp` 调用完整依赖版，不使用 PATH 中的裸 `yt-dlp` 或 Homebrew 旧版。按视频ID去重、保留原顺序，取得来源URL、标题、同源音频与字幕；单集与列表使用同一方法。P0取材默认只下载音频，无需为转录下载画面；命令使用 `--ignore-config`，避免旧全局配置隐式读取浏览器Cookie。

```bash
uvx --from 'yt-dlp[default]' yt-dlp --ignore-config --flat-playlist --dump-single-json '<视频或列表URL>'
# 先取可用中文字幕；live_chat 不是字幕，自动字幕仍需校正。
uvx --from 'yt-dlp[default]' yt-dlp --ignore-config --skip-download --write-info-json --write-subs --write-auto-subs --sub-langs 'zh.*,cmn.*' --sub-format json3 --no-progress -P '<材料目录>' -o '%(id)s/%(id)s.%(ext)s' '<视频或列表URL>'
# 缺字幕时，或校正具体疑点确需同源音频时再下载。
uvx --from 'yt-dlp[default]' yt-dlp --ignore-config -f bestaudio --write-info-json --no-progress -P '<材料目录>' -o '%(id)s/%(id)s.%(ext)s' '<视频URL>'
```

有字幕先取字幕，没有字幕时使用现有VideoCaptioner取得带时间底稿，不启动P2或字幕工作单。P0默认必剪；必剪明确失败、拒绝服务或提交前不可用，且没有待恢复远端对象时，直接用剪映补实际缺稿，不逐次询问。剪映也失败时保留已完成结果，说明实际失败阶段，不来回换服务或自动重新提交。两项服务的调用分别为：

```bash
node packages/runtime-config.mjs captioner transcribe '<同源音频绝对路径>' -o '<底稿.srt绝对路径>' --format srt --asr bijian --language zh --word-timestamps --quiet
# 明确失败后，仅对缺稿改用剪映；其它参数和同源材料保持。
node packages/runtime-config.mjs captioner transcribe '<同源音频绝对路径>' -o '<底稿.srt绝对路径>' --format srt --asr jianying --language zh --word-timestamps --quiet
```

查询失败、网络超时、412或打印窗口结束本身不等于远端任务失败。已有编号时，以相同音频和参数重入原服务，工具读取已保存编号只查询，不上传或创建新任务；剪映同时恢复提交时的设备身份。创建请求结果未知且没有编号时保留现场，不把重新运行命令当恢复。需要替换未知任务时仍须用户明确授权。上传、提交与查询均有网络超时；不通过无限等待或频繁重投掩盖平台故障。

转录前检查已存在的同源结果。分片任务由现有 VideoCaptioner 保存对应音频的远端编号；查询失败后优先恢复已知分片，原生结果与时间偏移保留。一个分片成功不等于整条视频完成，合并时按原偏移处理重叠，不能把片内时间当作全片时间。旧调用没有保存编号时不得猜测或把整片重提当成恢复，只在取得重试授权后补实际缺段。

下载 403 先核对实际 yt-dlp 入口与版本；转录查询 412 分开检查请求阶段、响应及原任务状态，不直接归因为代理或模型。国内服务的直联对照须核对环境代理、系统代理及 TUN 路由，清空环境代理不代表物理直联。只对同一已知任务做必要查询；单次恢复不能证明批量链稳定，不通过频繁重投或换服务掩盖故障。

新取得的机器底稿由AGY按同源字幕、识别结果和上下文校正识别错误，遵守当前外部CLI共同规则及AGY章节。一次只交明确底稿与可核对的同源输入，要求只读返回修订文本；不靠模型记忆补人名、引文、年代和因果。Codex保留机器原稿，将有依据的校正结果另存并更新本次清单；现有证据不能确认的地方明确保留缺口。校正识别错误与核实原作者史实分开：不得以常识把原话改成“正确历史”；重要专名、年代、数字和引文只能按同源证据修正。这里执行文字校正，不要求AI听取音频，也不以音频文件存在或转录成功声称完成听审。可读文字稿与带时底稿保持对应，不用摘要代替全文。已交付底稿只处理本次实际遇到的识别问题，不批量重跑。

AGY不可用、明确失败或无法完成校正时，由当前Codex直接按上述同源方法接手，不再等待作者服务或另开校正会话。原调用仍在本地执行时先等待同一进程；打印已结束但远端仍未知时保留会话编号与回执，不重投。原任务明确只读、没有写入材料能力的使用指令时，Codex可独立完成本地校正；原任务获准写入的，先确认它不再写入。迟到返回不自动覆盖已交付稿。接手完整读取机器稿及同源上下文，只修有明确依据的识别错误；不能确认的专名、数字、年代或引文保留原文并注明存疑，非核心存疑不阻止其余材料整理，影响核心故事判断的缺口须明确报告。原始`segments`及时间保持原值，校正全文写入`text`并更新清单摘要；未听审保持`audioReviewed: false`。这项备用只用于P0文字校正。

材料目录在仓库外。`planningBasis.referenceProgram.path`指向该目录的唯一JSON材料清单：

```json
{"videos":[{"id":"来源视频ID","title":"原题","url":"原视频URL","videoPath":"/绝对路径/视频.mp4","transcript":{"path":"/绝对路径/底稿.json","sha256":"实际文件摘要"},"quotes":[]}]}
```

底稿至少包含非空`text`，有时间的`segments`保持原值。`quotes`只保存原节目明确提供的真实引文、出处和视频位置；无则留空，不把主讲解释改成史料。清单只登记材料，不存第二份节目策划；节目绑定稳定路径，单集工作单绑定本次实际投递的来源内容。

策划时以底稿的校正全文`text`理解原片所说的内容；`segments`仍是未校正的原始识别，只用其时间帮助定位，不能用原始错字覆盖校正稿。对承重人名、年代、数字、引文与因果，同时看同一底稿的`uncertain`及`audioReviewed`：未听审就保留这一事实，存疑处按有依据的部分收窄表达，不能把推测或机器识别当成已经核实的原话。时间位置只是回查线索，切点以校正全文的完整语义为准。

只取得音频时，沿用清单示例中的 `videoPath` 保存该来源的实际音频绝对路径，不伪造视频文件或新增另一套清单。

音视频只作为转录和同源核对的临时材料。本次转录、校正完成且文字稿可正常读取后，删除本次下载的参考音视频、切片、重复格式稿件、调用日志和临时结果；长期只保留原始带时稿、校正稿及必要来源信息，不因可能以后回听而保留媒体。任务未完成时保留恢复所需的媒体和回执。清理不涉及节目生成素材或发布成片；已有清单中的`videoPath`只记录采集时位置，不表示媒体仍留存，也不要求下游读取媒体，不为清理改写已签发下游工作单的文字输入。

## 从原结构到我们的分集

1. 完整阅读全部指定底稿。长系列按原顺序把每份校正全文分成可消化的连续段落，逐段读到末尾；沿每条故事弄清当时的处境、各方行动、局面怎样改变、接着如何回应及最终结果，再与前后视频连起来理解。对本集中心问题所依赖的原因和转折，辨清原文提供了实际经过、解释依据，还是仅有结论或推测；有缺口时按本文件开头的取材方法解决，不能把完整故事任务当作充分证据。另看原作者如何让观众进入、用哪些行动或证据逐步改判、怎样把战场与制度／外交／个人处境接起来及收束。故事骨架、讲述方法和未经核实的推断分清后，跨视频比较独立故事与重复铺垫，在同一候选里决定归宿和集界；不另存摘要策划，不用标题、抽样或人物履历替代通读与理解。
2. 连续几期共同解释一个问题的，先合起来理解再分集；独立人物或视角可保留。一个视频回答一个完整问题通常仍为一集，多个能独立讲完整的问题才拆。不能仅按原视频数量、时长或人物数量拆集。逐段辨认材料中有独立处境、行动、转折和结果的故事，以及能解释结果的制度或人群关系；决定它们在本集、相邻集或独立集的具体归宿。重要故事即使与另一场大事发生在同一视频，也不能只留下人物名字或一句对照；补充分析不能只留结论而丢掉其解释链。把这一集实际讲的故事拆清楚，不只总结一个主题、观点或抽象内核；不为显得原创强行换成另一件事或制造反转。
3. 先依据本次委托和已读故事决定这档节目要回答的中心问题、从何处进入、经由哪些逐渐变化的局面抵达结局，再确定最终集数、集序和每集边界。中心问题要使整季成为我们自己的观看路径，不能只把原片按海战、陆战、人物和战场外重新归类；原作者已经有效的因果和对照仍须保留。用户没有固定集数时，不把原视频数或临时设想当成硬约束。重组保留原节目有效的事件关系、对照与因果，去掉重复铺垫；共享事件在不同集承担不同解释任务时明确分工。跨频道以同一事件、关系和解释任务去重，不靠词句相似度直接删稿；相同背景合并，独有经过和有效视角保留。相互冲突的解释注明各自来源，不以出现次数裁决，也不拼成双方都未提出的确定因果。材料不能支撑的强判断收窄到可支持的认识，不用虚构补足骨架。
4. 按实际故事线逐集写入同一候选，交清人物事件、处境与起因、关键行动如何改变局面、必要关系与转折、结果及几件事共同回答什么。写完一集便回到对应原文的完整语义段，看主要变化由哪些实际行动和条件支撑，关键原因是否有可读依据，下一集是否接走本集尚未讲完的转折；据此修正任务、取材或集界后再写相邻集。制度与治理分析也交代谁采取了什么办法、改变谁的处境、产生什么直接后果。保留有效故事和策划逻辑，故事任务与取材依据各司其职，不把转录换词缩写成半成品口播。历史先后和因果保持准确，跨线回到较早年份时交代时间关系，正文呈现顺序留给P1。
5. P1继承本集故事实质、必要关系与范围，独立构思叙事大纲，决定开头、呈现顺序、详略、节奏、语言和收束方式。P0不锁定原节目的逐段结构、指定开场、逐项覆盖或必须全部展开的细节。原节目叙事方法提炼为可借鉴的具体办法与作用，明确供作者参考，不预写句子、比喻、过渡或模仿示例。

## 唯一候选怎样写

先按包根“解说类型”采用用户指定或依据当前任务判断`explainerType`；参考频道或主讲者不直接决定类型。仍用本包P02的节目字段、视觉/封面/片头目录与原六项单集字段；本路线不读取普通`explainer-planning-method.md`，其中不交具体故事策划的限制、书目反推和研究义务不适用。工作单有`currentProgramPath`时先读现行节目；尚未接纳而中途改要求时读取新工作单及同一路径保留的当前草稿，按新要求调整。两种情况都保留未受影响的决定与材料，不重新取得已有底稿。

参考节目是内部取材对象，不是默认的对外叙述对象。频道、主讲者、视频ID及仅属原作者的评论留在材料定位和证据边界供P1回查；完整故事交给P1的是有据的历史行动、关系与结果。某项解释若去掉原作者归属就会变成我们无据的确定判断，先看本次材料能否支持，不能支持就收窄或不采用，不把“参考了谁”安排成口播段落。只有本集题目本来就是评述该创作者或节目时，创作者身份才属于故事内容。

- `seriesFramework`：写出本节目的中心问题、观看路径、拆合理由和集间分工，说明不同战场或人物线怎样共同推进同一个理解，单集无需人为增加层级。
- `episodeTitle / episodeQuestion / episodeAnswer`：题目承诺、本集问题、材料能支持的认识。
- `episodeCreativeBrief`：用自然段分开“完整故事与策划逻辑”“叙事方法参考”“材料定位”。故事写出本集具体人物、关键行动、关系、转折、结果及有据的必要解释，让P1知道完整讲什么、重点理解哪些变化；若换掉这些内容后仍可用于另一集，就继续交清真实经过，不用“选取能说明的内容”把策划责任留给P1。叙事参考点名原片的具体讲述办法及作用，供作者选择，不定开头、段落或顺序，不复用原句。材料定位用来源ID、时间或原文起止锚点，指到这些关键经过的完整语义段及必要上下文，说明实际疑点和原作者独有推断的证据边界；推断不因列入策划就成为必须证明的结论。采用公开补充正文时，在同一定位交清标题、可访问URL、实际读过的页码或章节、它补足哪项过程或原因及适用边界。定位让P1能读到依据，不能只列视频名或未读取链接。
- `episodeScope / episodeBenefit`：本集范围、停止点、相邻集边界，以及听完理解什么。
- `referenceVideoIds`：本集实际使用的视频ID，可多源合一、同源拆分。全文由系统交给P1的取材执行者，用于整理事实和回查；不复制进策划字段或直接交给文字作者。

每集形成一个完整、值得讲清的故事任务，不按原节目时长、转录长度或统一字数安排分集。先看相邻内容是否属于同一行动过程、解释链或有意义的对照：合讲能让起因、选择与后果连续成立时，合并重复铺垫并保留各部分的关键经过；几条故事各有独立问题与结果、放在一起只剩并列专题时，保留独立分集。不能因材料多就拆，也不能为减少集数把独立故事压成一句结论。按包入口的单集篇幅原则，在`episodeCreativeBrief`的故事任务中交代本集展开意图；较大故事的规模参考不成为小故事的最低长度，也不照搬源节目时长。具体篇幅由P1作者按实际内容决定，P0不指定目标字数。用户明确最长时长时才承接`maxDurationSeconds`；故事确实无法在该业务上限内成立时，在P0调整范围或拆合。

节目层原样承接`referenceProgram`；只有实际采用NotebookLM时才同时声明`researchLibrary`，沿P03保存真实来源编号并核对就绪，只写当前`candidatePath`。在同一方案中从已读来源反看每个重要故事和解释链是否有明确的单集归宿：若只在`referenceVideoIds`中被引用、或在别集仅作一句对照，就补足对应故事任务或重新拆合；同时确认各集问题闭合、关键经过有材料、集间分工成立，再沿P04提交。这是作者完善同一策划的动作，不另建来源映射或校验表。接纳读取本地材料，Engine投影单集任务。完成P0停止，不自动开始P1。
