# 节目检索与取材

所有`historical-explainer`的P01都读取本方法。先找已有节目，再决定材料基础；已有主题、指定书、视频URL或本地底稿都不能跳过同题检索。完成后回包根P02，使用共同故事策划方法，不另立视频与文献两套流程。

## 先找有没有人讲过

围绕本集核心对象与问题，检索通行名称、别名、事件或关键关系，按题材补常见英文名。优先检索YouTube、B站及题材相关的公开节目，不要求每次搜遍全部平台；用户指定视频或频道是起始线索，仍找能补关键经过或提供互补解释的节目。使用当前宿主的公开搜索或已可用的平台检索，标题与简介用于发现，字幕或正文用于判断，不把网页检索当作站内穷尽。

选择真正讲到同一件事、关键经过或解释关系的节目，确认内容相干、实质信息够用且正文可取得。通用解说通常从两三个能互补的节目起步。优先以主要经过最完整的一支为基础，其它节目用来补缺失的行动、另一方的处境、具体细节或不同解释。几支节目各自讲足一部分时，可以共同撑起一集；只有一支合适就用现有基础继续。不同语言、频道或立场均可，按实际贡献取舍，不按播放量、原时长或固定数量决定。

有合适节目就按下节取得完整底稿并通读，先弄清基本经过和各片能补什么，再按共同策划方法选主线、搭大纲。保留有效的故事内容和讲法，把多源共同的经过合并，把互补内容接入它所说明的变化或关系。沿初步大纲找关键缺口，再用可靠正文补经过、原因、反证、争议和必要更新。用户想法融入现有任务，保持事实与推测的区别。

初搜无结果时，换用别名、关键事件或关系、常见语言及另一相关平台检索，再判断是否有合适节目。实际没有合适内容时，才从已给书或可靠文献独立策划；无需证明全网从没人做过。在会话中简短交代检索范围及未采用原因，不另写搜索报告或策划字段。检索服务失败、访问受限、视频下载或转录失败都不等于没人做过；先用当前可用入口和同源字幕处理实际缺口，仍无法取得关键内容时说明阻塞，不静默改成独立创作。

## 取得并读懂材料

指定频道时先枚举公开视频与相关播放列表，以视频 ID 去重；用户排除短视频时核对 Shorts 栏目，不凭时长阈值误删较短的普通长视频。结合标题、简介、章节与系列关系识别题材，正文再确认本次题材相关段落；问答或跨朝代节目保留完整原材料，只选相关内容入策划。没有访问到的范围如实说明，不把标题检索称为正文穷尽。

用户已交付的完整底稿直接使用，不重复下载或转录。对新选中的节目，统一通过 `uvx --from 'yt-dlp[default]' yt-dlp` 调用完整依赖版，不使用 PATH 中的裸 `yt-dlp` 或 Homebrew 旧版。按视频ID去重、保留原顺序，取得来源URL、标题、视频及字幕；单集与列表使用同一方法。故事理解以完整正文为主；通用解说遇到字幕无法解释的地图、示范或比较，按时间定点对照同源画面，弄清它实际说明的关系。原片画面中的复原、示意和主张仍按实际证据判断。命令使用 `--ignore-config`，避免旧全局配置隐式读取浏览器Cookie。

```bash
uvx --from 'yt-dlp[default]' yt-dlp --ignore-config --flat-playlist --dump-single-json '<视频或列表URL>'
# 下载选中的视频并取得可用中英文字幕；live_chat不是字幕，自动字幕仍须校正。
uvx --from 'yt-dlp[default]' yt-dlp --ignore-config -f 'bv*+ba/b' --merge-output-format mkv --write-info-json --write-subs --write-auto-subs --sub-langs 'zh.*,cmn.*,en.*' --sub-format json3 --no-progress -P '<材料目录>' -o '%(id)s/%(id)s.%(ext)s' '<视频或列表URL>'
# 无字幕、确需转录时，从已下载视频提取音频，不重复下载。
ffmpeg -i '<已下载视频绝对路径>' -vn -ac 1 -ar 16000 '<转录音频绝对路径.wav>'
```

有字幕先取字幕，没有字幕时使用现有VideoCaptioner按原节目语言取得带时间底稿，不启动P2或字幕工作单。必剪、剪映只支持中英文；其它语言先取同源可用字幕，仍缺稿时说明缺口，不自动改用付费转录。P0默认必剪；必剪明确失败、拒绝服务或提交前不可用，且没有待恢复远端对象时，直接用剪映补实际缺稿，不逐次询问。剪映也失败时保留已完成结果，说明实际失败阶段，不来回换服务或自动重新提交。两项服务的调用分别为：

```bash
node packages/runtime-config.mjs captioner transcribe '<同源音频绝对路径>' -o '<底稿.srt绝对路径>' --format srt --asr bijian --language '<原节目语言代码>' --word-timestamps --quiet
# 明确失败后，仅对缺稿改用剪映；其它参数和同源材料保持。
node packages/runtime-config.mjs captioner transcribe '<同源音频绝对路径>' -o '<底稿.srt绝对路径>' --format srt --asr jianying --language '<原节目语言代码>' --word-timestamps --quiet
```

查询失败、网络超时、412或打印窗口结束本身不等于远端任务失败。已有编号时，以相同音频和参数重入原服务，工具读取已保存编号只查询，不上传或创建新任务；剪映同时恢复提交时的设备身份。创建请求结果未知且没有编号时保留现场，不把重新运行命令当恢复。需要替换未知任务时仍须用户明确授权。上传、提交与查询均有网络超时；不通过无限等待或频繁重投掩盖平台故障。

转录前检查已存在的同源结果。分片任务由现有 VideoCaptioner 保存对应音频的远端编号；查询失败后优先恢复已知分片，原生结果与时间偏移保留。一个分片成功不等于整条视频完成，合并时按原偏移处理重叠，不能把片内时间当作全片时间。旧调用没有保存编号时不得猜测或把整片重提当成恢复，只在取得重试授权后补实际缺段。

下载 403 先核对实际 yt-dlp 入口与版本；转录查询 412 分开检查请求阶段、响应及原任务状态，不直接归因为代理或模型。国内服务的直联对照须核对环境代理、系统代理及 TUN 路由，清空环境代理不代表物理直联。只对同一已知任务做必要查询；单次恢复不能证明批量链稳定，不通过频繁重投或换服务掩盖故障。

下载字幕或转录返回后，先运行已登记的本地格式转换入口，把SRT、JSON3或VideoCaptioner原生JSON转成后续实际读取的底稿；它只提取原字、保留时间，不摘要、不推断、不改写。原始输入保留，新输出不得覆盖已有底稿：

```bash
node packages/modules/plan-program/scripts/prepare-reference-transcript.mjs '<原始字幕绝对路径>' '<新机器底稿.json绝对路径>'
```

输出的路径与摘要指向机器底稿。完成下述校正后，另存校正JSON，保留原始`segments`，只按有据校正更新`text`及真实疑点，未听审保持`audioReviewed: false`；材料清单必须登记最终校正JSON的路径与重新计算的SHA-256，不能沿用机器稿摘要。已有合格底稿直接复用，不重复转换。

当前Codex直接完整校读新取得的机器底稿，结合同源字幕、识别结果和上下文修正有明确依据的识别错误。保留机器原稿，校正全文与带时底稿保持对应。专名、年代、数字和引文以同源证据为准，无法确认时保留原字并注明疑点。原片所讲的史实在策划时另行核实，校读保留原作者实际表达。这里按文字校读，音频文件存在或转录成功均不代表已经听审。

非核心疑点随材料保留，影响主线选择或解释的缺口在策划时核查并说明。已有底稿只校正本次用到且有明确依据的问题，复用其余有效成果。

材料目录在仓库外。P0将实际取得的节目登记在该目录的一份JSON材料清单，最终`program.yaml#referenceProgram.path`指向它。用户已给清单时先读取；需要并入新节目时在本次材料目录形成合并清单，保留原视频记录与底稿身份，不改用户原件或委托，也不要求用户重新选择路线：

```json
{"videos":[{"id":"来源视频ID","title":"原题","url":"原视频URL","videoPath":"/绝对路径/视频.mp4","transcript":{"path":"/绝对路径/底稿.json","sha256":"实际文件摘要"},"quotes":[]}]}
```

底稿至少包含非空`text`，有时间的`segments`保持原值。`quotes`只保存原节目明确提供的真实引文、出处和视频位置；无则留空，不把主讲解释改成史料。清单只登记材料，不存第二份节目策划；节目绑定稳定路径，单集工作单绑定本次实际投递的来源内容。

策划时以底稿的校正全文`text`理解原片所说的内容；`segments`仍是未校正的原始识别，只用其时间帮助定位，不能用原始错字覆盖校正稿。对承重人名、年代、数字、引文与因果，同时看同一底稿的`uncertain`及`audioReviewed`：未听审就保留这一事实，存疑处按有依据的部分收窄表达，不能把推测或机器识别当成已经核实的原话。时间位置只是回查线索，切点以校正全文的完整语义为准。

已有材料只含音频时，`videoPath`保存实际音频位置，不伪造视频或重下已有完整底稿。新采集的节目填写实际下载视频路径。

音视频只作为转录和同源核对的临时材料。本次转录、校正及所需的同源核对完成且文字稿可正常读取后，删除本次下载的参考音视频、切片、重复格式稿件、调用日志和临时结果。用于策划的画面关系和时间位置写入现有材料定位；长期只保留原始带时稿、校正稿及必要来源信息，不因可能以后回听而保留媒体。任务未完成时保留恢复所需的媒体和回执。清理不涉及节目生成素材或发布成片；已有清单中的`videoPath`只记录采集时位置，不表示媒体仍留存，也不要求下游读取媒体，不为清理改写已签发下游工作单的文字输入。

## 完整理解，回到共同策划

完整阅读本次选中及用户指定范围内的底稿。长系列按原顺序把每份校正全文分成可消化的连续段落，逐段读到末尾；沿每条故事弄清当时的处境、各方行动、局面怎样改变、接着如何回应及最终结果，再与前后视频连起来理解。不另存摘要策划，不用标题、抽样或人物履历替代通读。

辨认原片哪个问题使观众想知道答案，哪段经过把原因讲明，哪个具体细节或后果改变了理解，把有用的讲法及其作用交给P1参考。通用解说直接用这些具体内容搭故事。沿着有价值的段落，把当时的条件、谁采取了什么行动、另一方怎么回应、局面怎样改变连起来。机制或比较题则还原条件、作用过程、对比和结果。P0决定本集采用什么内容，P1自主写开场、安排讲述顺序和语言。

通用解说读片时，把可能承担主线的经过读到可讲的程度，从起始局面看各方怎样尝试、受阻、应对和调整，最后走到什么结果。例如围城中，前一轮失败、改换攻法、守方反击、援军怎样接近战场，各自可能有内容；几次都没攻下，也要分清它们让攻守形势发生了什么变化。区分真正改变局面的经过和同类重复，供P02选择重点。

有多片时，按同一事件、关系或解释问题对读。可以接合一部合集里相隔的分段，也可以把同一原片的不同经过分给各自能讲完整的集。相同背景只讲一次，把某片独有的行动、另一方的视角或更清楚的解释接到它能补上的位置。区分同一件事的不同记法和看似相似的两次行动。相同说法先辨明是否同源转述；说法冲突就定位分歧，用可核读的可靠正文核对，仍无定论则按有据范围讲，避免把两种说法拼成无据的新因果。

调查从故事具体卡住的地方下手。原片从行动直接跳到结果，就找中间的回应。只说地形有利，就找地形怎样改变攻守选择。关键说法可疑，就回到原典、可靠研究或原始记录。区分原片讲过什么、材料证实什么和我们据此怎样解释。补到的内容插回它解释的段落，证据只支持较弱判断时收窄原说法。补完再看整条线能否回答本集的问题，观众具体多懂哪一步。省掉与此无关的履历、逸闻和重复铺垫。

然后继续包根P02—P04，确定中心问题、拆合、单集故事和材料范围。原片有效的问题与解释关系可以沿用。修订保留未受影响的决定与材料，不重新取得已有底稿。

## 在同一候选中交接来源

在材料里保留实际采用的节目、作者与具体贡献，供P1回查。某项解释若去掉原作者归属就会变成我们无据的确定判断，先看本次材料能否支持，不能支持就收窄或不采用。口播围绕本集对象展开，只有评述节目或创作者本身时才以其为叙述对象。本步骤取得的底稿和媒体用于取材。涉及沿用原文表达、原画面或声音时，按实际用途另行核对许可或适用的引用依据，署名与素材权利分别判断。

故事及六项字段统一执行[共同策划方法](explainer-planning-method.md)。视频材料定位用来源ID、时间或校正全文起止锚点，指到关键经过的完整语义与上下文；原作者独有推断与实际疑点照实交接。文献定位按包根P03，不在此另立写法。

采用视频时，节目层`referenceProgram`指向实际使用的材料清单；每集`referenceVideoIds`只列实际使用的视频ID，允许多源合一或同源拆分。同季某集检索后无合适视频时，该集用文献策划并省略视频ID；全季未采用视频时省略`referenceProgram`。全文由系统交给P1取材执行者整理事实和回查，不复制进策划字段或直接交给文字作者。实际采用NotebookLM时才同时声明`researchLibrary`，沿共同P03保存真实来源编号并核对就绪；始终写同一`candidatePath`，沿P04提交。完成P0停止，不自动开始P1。
