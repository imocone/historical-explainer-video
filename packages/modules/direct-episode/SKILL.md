# 整集视觉导演

把整集口播形成连贯的观看安排：从什么处境进入，观众的认识与感受怎样推进，最后落在哪里。

| 层次 | 导演决定什么 |
|---|---|
| 整集 | 从哪里进入，怎样推进，最后留下什么认识与感受。 |
| 章节（TR） | 先划讲解章节，再将剩余全画幅内容按相对完整的叙述划章，确定各章首尾。 |
| 全画幅Beat | 沿字幕语义和口播节奏，这一拍具体看清或感到什么，在哪里把注意力交给下一个表达。 |

路线：**整集方向与章节划分 → 历史视觉考据与资料交接 → 仅切全画幅Beat并核对时窗 → 一次审修章节与Beat并封存 → 整集方案接纳、按章节交接**。一次工作单只维护一个`albumPlan + beats + templateRuns`候选。

统一使用“章节”，分为讲解章节和全画幅章节；章节沿用现有`templateRun`及`TR001`等身份，不新增层级、字段或时间轴。章节划分按[正文章节划分方法](references/template-selection-method.md)；**全画幅章内按字幕语义的具体表达与口播节奏切Beat，讲解章节不切内部Beat。**章节组织完整叙述与共同创作，Beat组织其中一次有明确意思的观看；同一行动的起因、决定、结果可以跨Beat承接，不把完整小段落当作默认Beat。

现有`beats`数组仍覆盖全部Cue：全画幅条目是独立观看Beat；新讲解每章只保留一条B范围记录，交清整章目标、必须可见内容与前后承接，供`templateRuns`及下游引用。这里的B只是现有合同的范围载体，不称为讲解Beat，也不要求作者补切Beat。作者按本章任务组织画面、部件、变化与真实Cue，一章不等于一幅图或一张画布。已接纳章节及其多成员身份保持，不能因新方法清空或合并有效成果。

### 第一步：确定整集方向，先划讲解章节，再划全画幅章节

#### 1.1 读取当前任务与方法，确认首次创作或返工范围

先运行并一次完整读取当前任务视图：

```sh
node packages/p3-task-view.mjs <workOrderPath>
```

完整读取`inputs.cues`和已接纳Understanding，核对模板目录、输出合同、`candidatePath`、写入范围和退回目标。完整读取以下方法；已完整读取且未变化的内容不重复加载。输出被截断或仅取得摘要、键名、样例时，从原返回或真源按范围补齐缺失正文，不以命令成功代替实际取得，也不重复打印已完整持有的内容：

- [整集画册方法](references/whole-album-method.md)：进入、推进、结尾与前后呼应。
- [正文章节划分方法](references/template-selection-method.md)：从完整Cue比较表达，决定模板和连续范围。
- [全画幅场面选择方法](../../templates/fullframe-narrative/references/scene-selection-method.md)：涉及全画幅时完整读取。

新单从本步开始。返工以`currentVisualPlan`为基线，按`returnRequest`修正实际范围，保留有效页面与选择，再重新规划。

恢复同一工作单时，先按本次会话计划与执行记录确认实际进度，不重新初始化选择：候选缺失或不完整，回本步；章节划分复核尚未完成，接1.3；章节划分完成但尚未形成适用考据交接，接第二步；已有适用资料和范围绑定但没有有效规划锁，接第三步尚未完成的动作；已有规划锁但未封存边界，接第四步；封存有效，进第五步。候选已保存不代表章节划分复核或全画幅切分已完成，技术锁也不能代替专业判断。

恢复时保留本次审计进度：当前会话计划记录已审范围、是否审完、完整问题清单和待修项；已经审完的，只接着完成这次修正和技术交接。进度不明时先核对本次会话的计划与执行记录，不能因缺锁认定从未审过，也不另建审计文件。

`returnRequest.revisionScope=director-revision`时，以`selectedBeatIds / cueRefs`界定可重新分页、改观看职责和模板选择的范围，整集方向四项与范围外页面保持原文；紧邻下一页只按需要调整`relationFromPrevious`。跨范围的讲解章节成员不能重分；全画幅章节可替换所选Beat的拆合成员，保留范围外成员身份、顺序和章节归属，重复元素只能修正所选范围内引用，不能改写其范围外用途。若意见必须扩大范围，停止并说明需增加的原Beat，不越权改写。未改B／TR／RE身份保留，拆页新对象使用当前未占用身份，合并保留其中一个原身份；数组和cue决定顺序，不顺延后面编号。五步仍核对完整候选及全边界，范围外有效选择只读继承。

用户仅要求Beat切分纠错时，只对全画幅页面判断拆合；已有讲解章节的范围及作者内部画面安排保持。完整候选仍核对cue覆盖和跨章节交接。两类章节的内容或模板归属修改，只按用户另行明确的范围处理。

必需cue或共享语义缺失，或来源冲突使当前导演任务无法成立时停止或正式退回；已由Understanding标明且不妨碍本任务的未决，继承其禁造边界继续，不自行裁决或补事实。正式退回只能使用`allowedReturnTargets`中的`understand`，写明理由和实际`cueRefs`，不得写`ai-understanding`：

```json
{"taskDigest":"<当前摘要>","returnTo":{"target":"understand","reason":"<具体问题>","cueRefs":[1]}}
```

#### 1.2 先从整篇确定观看方向与表达范围

调用整集画册方法形成进入—推进—结尾和节奏意图，暂不切Beat。连读完整Cue，结合此前已建立的内容认清本章观看任务，按正文章节划分方法比较全画幅与讲解的实际收益及可行性，确定模板和连续范围。全画幅为默认；讲解须以解释为主要任务，收益具体且显著，事实、现有能力与真实时窗支持。地图与空间沿讲解模板的专门方法，不按题材或关键词入选。这里确定章节边界，不是Beat切点；具体判据与讲法统一见正文章节划分方法。

讲解起止按本次图解任务的必要范围判断，不为完整包入已交代的背景或适合全画幅的独立事件，也不为缩短删掉必要参照、比较两端、结果和限定。具体判断沿用正文章节划分方法，在原章节划分与复核中完成。没有成立的讲解任务时，全部内容归全画幅；不按关键词抢占范围，也不把全画幅图数容量作为换模板理由。

先按现行判据划定讲解章节，再按章节划分方法将剩余连续全画幅内容组织为相对完整的叙述，不跨已选讲解章节拼接。此时只定章首尾，不切Beat，保住人物经历与整集节奏。

#### 1.3 保存完整章节初稿，交给考据步骤

按`{"taskDigest":"<当前摘要>","result":{...}}`将`albumPlan + beats + templateRuns`保存到同一`candidatePath`。首次创作时，每章先用一条B记录保存首尾真实Cue、整章观看要求和模板，再由对应`templateRun`引用；全画幅B此时只是待切范围，不冒充已成立的单次观看Beat。返工继承有效条目及身份，只保存授权范围内的实际修改，不重建整篇。字段须完整、范围连续覆盖全文、引用唯一；不交另一份章节划分稿或新增字段。前后呼应的元素在第三步形成真实B记录后落实；返工保留范围外原值。F/R及相关语义由System Control按Cue范围投递，不转抄到导演结果。

保存后，按章节划分方法复核讲解的漏选、误选与首尾，以及全画幅章节是否切碎或硬拼；全片只有全画幅时保留原额外复判一次。实际修正写回同一候选，再进入第二步。

### 第二步：建立历史视觉依据，交接人物、衣装和环境

本步消费第一步已保存的完整章节候选、正式Cue、Understanding与现有来源。完整读取[历史视觉考据组件](historical-context/README.md)，按其中研究方法完成本次实际入画对象的考据：人物先查本人画像／照片，服装按身份与活动另定，环境按时期、地域及使用关系形成基本特征。抽象关系或不需要时代复原的范围不强行考据；全篇均属此类时直接进入第三步，不制造空资料。

将已作出的专业选择与实际取得原件写入组件规定的当前scratch研究输入，运行publish取得登记资料SA，再bind到同一候选。**完成结果是来源库中可读取的资料与原图，以及候选内按Cue分配的读取提示**；写了说明、贴了链接或只存了搜索结果都不算完成。第三步先读取这个结果，再形成具体Beat与观看要求。考据不代替构图、相机和艺术表达。

恢复时读取当前候选的资料SA与原件：已适用则复用，未绑定只执行bind，已登记但交接中断重放原输入，不重新搜索或下载。修订只处理授权范围及实际变化的时期／对象，保留有效原件和范围外依据；不因模块代码变化重做研究。资料不足留在本步补查或明确合理复原边界；若与口播或Understanding冲突，沿1.1正式退回，不自行改事实。文件、权利或范围失败由组件返回具体对象，根入口修复对应输入后续接。

### 第三步：只切分全画幅Beat，落实观看要求并核对时窗

#### 3.1 读取章节初稿，只在全画幅范围内切Beat

实际读取`candidatePath`，核对摘要、全部范围与Cue覆盖；缺失时回第一步补齐。完整读取[全画幅Beat方法](references/beat-page-method.md)，沿字幕语义辨认具体表达落点，结合口播节奏、画面预想与真实阅读窗口，在相邻Cue之间确定切点，并替换各全画幅章的待切范围；不能跨讲解章节拆合。先判断每一拍要表达什么，再判断必要连贯，不能先包住整件事后只在过长时补A/B。讲解保留整章范围与要求，不分派逐幅职责、图数、画布或内部卡点。

#### 3.2 落实整集关系，保存同一完整候选

读取第二步已登记资料的实际正文，结合各context适用Cue，把人物、衣装和环境的必要历史特征落实到本次观看要求。按作者实际景别保留要点，不逐条强塞全部细节；不得改变资料支持范围。出现新对象或时代依据缺口，回第二步只补实际缺口，保留本单其它有效研究内容，再继续本步；不能把未查清的关键身份与场合留给并行作者各自猜测。

为每个全画幅Beat写清`viewerOutcome / directorBrief`，同步章节成员、前后呼应的元素及相邻承接。讲解记录的四项要求服务整章，可包含多个必要阶段，不套用全画幅“单一观看推进”的切分判据。全部B记录合起来连续覆盖Cue，每条记录恰好归一章。若切分暴露所选章首尾或归属不成立，回第一步只重判实际范围，再完成受影响的全画幅切分；不能只换模板名，也不重新初始化整集。完整候选保存后，有历史视觉资料时最后运行组件bind，把同一资料重新分配到当前范围并保留导演原文；随后进入3.3，不能在bind后覆盖掉读取提示。

#### 3.3 计算并消费当前完整候选的可创作性规划

保存后运行：

```sh
node packages/modules/direct-episode/inspect-authorability.mjs <workOrderPath> <candidatePath>
```

首次创作时，该入口按当前数组顺序统一B／TR／RE编号并同步明确引用，校验通过后写回同一候选；存在`currentVisualPlan`的返工不重编号，核对既有身份和本次范围后计算规划。它不改cue范围、模板选择或语义文本，不猜重复身份和悬空引用。完整读取返回的改号映射及当前单位结果，按[Beat方法中的规划读取说明](references/beat-page-method.md#可创作性规划的读取)判断预想组织能否交付观看职责。程序只检查已选条件，不替导演判定模板。

失败返回`authorable:false`且无可用锁，留本步修正重算，不能因容量不足改用讲解章节。规划全部通过、预想组织成立且候选未改，才将同版候选、规划正文和`director-authorability`锁交给第四步。

### 第四步：完整审计切分一次，集中修正一次并封存

先读第三步的完整候选、同版规划正文及其锁；上下文缺少正文时回3.3重取并读取，再运行：

```sh
node packages/modules/direct-episode/inspect-boundaries.mjs <workOrderPath> <candidatePath>
```

命令先消费同版可创作性锁，列出全画幅内部可切位置及全部相邻范围交接。实际读取完整索引、同一候选的`templateRuns`、对应原Cue与观看要求；摘要、总数或首条样例不能代表余下内容已读。按口播顺序完整顺读一次，同时审两层：

- **章节层**：按[章节划分方法](references/template-selection-method.md#4-复核本步结果并结束)检查讲解范围与承接、全画幅章节是否切碎或硬拼，确认各章首尾和整集节奏；涉及时代外观的关键场面，按组件研究方法及已登记资料核对依据、适用范围及跨章一致性。
- **Beat层**：按[Beat方法第3节](references/beat-page-method.md#3-逐边界复核)核对字幕表达落点与画面交接，检查新意思已开始却未切、语义未落却抢切、职责重复、时间不足或空撑；讲解不审内部Beat。

全部章节及其交接、全画幅长短Beat和内部边界均须覆盖，不能只看初稿疑点。已完整持有的同版材料直接使用，缺失按1.1补齐。索引只用于定位，不把每个字幕间隙重新当作一道拆合题；有疑点才按所属层的方法展开比较。两层在同一轮完成，不另加审计轮次。枚举和可创作性通过不等于专业判断通过。

先审完整个本次范围，再在同一会话计划中一次列齐章节和Beat的具体问题、改善、修正方向及必要依赖。审计途中不边审边改；完成本轮比较后不再反复改选切法。无问题直接封存；有问题只按这份完整意见在同一`candidatePath`集中修正一次，保留其余有效页面。修正仍由原画册、Beat和章节划分方法完成，不凭容量单独切页；已有讲解章节的切分整改边界沿用1.1。

候选一经修改，旧规划与枚举锁失效：有历史视觉资料时先对保存后的修正候选bind同一资料，刷新实际范围的读取提示，不重新研究；再只重跑3.3的`inspect-authorability`，读取修正结果的实际规划，再运行`inspect-boundaries`刷新同版索引与锁，随后封存。这里的范围绑定、重算与枚举是技术交接，不再次遍历、抽查或定点复审切分质量，不重新执行3.1／3.2的全量判定。规划、字段或锁失败仍按原合同修正，不能绕过接纳；若必须扩大问题范围、重建整篇或再次作质量切分才能成立，明确报告未完成，不自行开始第二轮。没有改动时复用当前有效规划与枚举锁。运行：

```sh
node packages/modules/direct-episode/lock-boundaries.mjs <workOrderPath> <candidatePath>
```

封存同时消费最近枚举锁和同版可创作性锁，绑定完整导演结果；它只证明候选未漂移，语义与节奏仍由Director负责。第五步不得静默改写。

### 第五步：整集方案接纳，按章节交接

封存成功后，按工作单提交同一候选，不补模板或重复整集复核。封存失败不得提交，按错误返回对应动作；封存与`accept`连续执行时使用`&&`或等价失败短路，不能用无条件换行串接。Accept独立重算现有合同；漂移或合同失败时返回形成该结果的动作修正，再按第四步刷新技术规划、枚举与封存，不重置已完成的质量审计、不发起第二轮切分修正，也不在此静默改写。

本步一次接纳整集导演方案，不逐章接纳导演计划。后续正文按章节派工、提交、接纳和统计进度：讲解章节整章投递，全画幅章节联合投递全部待创作Beat。全画幅内部仍逐Beat核验、保存和渲染，章节成员交付齐备才计该章完成；局部返工只投递获准成员。具体调度见[正文按章节并行](../../../director/references/p3.md#正文按章节并行)。Visual Director在此停止，不执行作者设计或下一阶段。

## 停止条件

责任内问题返回上述对应动作修正。人工智能只消费模板目录`catalog`和登记方法；`cuePolicy`及规划由登记命令和Engine调用，不打开模板清单或源码，不读取或配置Feature。不得另造Structure、第二时间轴、筛选报告、检查表或无消费者的中间成果，也不得输出`treatment / features / opener / _producer`或替作者决定构图、注意力路线、相机、运镜、媒体生产与P4。
