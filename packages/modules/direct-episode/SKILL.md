# 整集导演

通读整集口播，安排观众从什么处境进入、怎样逐步看清关系与变化、最后留下什么认识和感受。作者动工前，导演定好各章的观看任务和承接，以及全画幅镜头的顺序、切点和接法。

| 层次 | 导演交付 |
|---|---|
| 整集 | 共享理解、进入角度、观看推进、重点轻重、转折与落点 |
| 章节（TR） | 按完整观看任务决定模板和章界。先划整章有显著解释收益的讲解章节，再将其余连续内容组织为相对完整的全画幅叙述 |
| 全画幅镜头（B） | Cue范围、入镜注意力、揭示、切出前的停留、前后接法与观看结果 |

全画幅一镜用一幅完整静态主画面，作者沿原模板落实画面和运镜。讲解用一条B交接整章的时窗、观看任务和关键揭示。作者在同一工程粗排全章，决定章内切镜、连续演示和口播卡点。

路线为**文字理解并保存语义稿 → 整集改编与章节划分 → 历史视觉考据 → 全画幅逐镜精排与讲解段首尾设计 → 整集组接审修与封存 → 同一候选接纳、按章交接**。唯一候选包含 `understanding + albumPlan + beats + templateRuns`。

### 第一步：读懂整集，保存共享理解

#### 1.1 读取当前任务，确认首次创作或返工范围

先运行并一次完整读取当前任务视图：

```sh
node packages/p3-task-view.mjs <workOrderPath>
```

完整读取`inputs.cues`，核对模板目录、输出合同、`candidatePath`、写入范围和退回目标。完整读取以下方法；已完整读取且未变化的内容不重复加载。输出被截断或仅取得摘要、键名、样例时，从原返回或真源按范围补齐缺失正文，不以命令成功代替实际取得，也不重复打印已完整持有的内容：

- [共享语义方法](references/text-understanding-method.md)：在当前导演候选建立多方实际继承的理解。
- [整集画册方法](references/whole-album-method.md)：进入、推进、结尾与前后呼应。
- [正文章节划分方法](references/template-selection-method.md)：从完整Cue比较表达，决定模板和连续范围。
- [全画幅场面选择方法](../../templates/fullframe-narrative/references/scene-selection-method.md)：涉及全画幅时完整读取。

返工以`currentVisualPlan`为基线，按`returnRequest`修正实际范围。工作单有`currentUnderstanding`时，核对后继承有效部分。恢复的原导演候选若只缺共享理解，先将本单继承的有效语义补入同一候选，再接着做实际未完成的步骤。

`returnRequest.cueRebinding`表示正文未变，字幕分句变化或新时间造成转场冲突。对照其`previousCues`与当前Cue，保留原观看安排、模板、B／TR身份和有效考据，只修实际受影响的范围、接法与绑定；确实无法维持原边界时才调整相应页面。接纳后，原设计、素材与功能交给受影响的原作者单位继续局部修订，不把编号变化当成重新创作的理由。

恢复同一工作单时，先按本次会话计划与执行记录确认实际进度，不重新初始化选择：候选缺少已形成的共享理解，接1.2；已有理解但章节尚未确定，接2.1；章节划分复核尚未完成，接2.2；章节划分完成但尚未形成适用考据交接，接第三步；已有适用资料和范围绑定但没有有效规划锁，接第四步尚未完成的动作；已有规划锁但未封存边界，接第五步；封存有效，进第六步。候选已保存不代表章节划分复核或全画幅分镜与讲解章级交接已完成，技术锁也不能代替专业判断。

恢复时保留本次审计进度：当前会话计划记录已审范围、是否审完、完整问题清单和待修项；已经审完的，只接着完成这次修正和技术交接。进度不明时先核对本次会话的计划与执行记录，不能因缺锁认定从未审过，也不另建审计文件。

`returnRequest.revisionScope=director-revision`时，以`selectedBeatIds / cueRefs`界定可重新分页、改观看职责和模板选择的范围，整集方向四项与范围外页面保持原文；紧邻下一镜只按需要调整`relationFromPrevious`及其已归导演的入场接法。跨范围的讲解章节成员不能重分；全画幅章节可替换所选Beat的拆合成员，保留范围外成员身份、顺序和章节归属，重复元素只能修正所选范围内引用，不能改写其范围外用途。若意见必须扩大范围，停止并说明需增加的原Beat，不越权改写。未改B／TR／RE身份保留，拆页新对象使用当前未占用身份，合并保留其中一个原身份；数组和cue决定顺序，不顺延后面编号。全流程仍核对完整候选及全边界，范围外有效选择只读继承。

用户只选某类章节或镜头时，保留范围外有效设计。真实口播Cue缺失或证据冲突使观看任务无法成立时，报告实际范围和缺口。可表达的不确定性写进本单共享理解，并带进相应分镜。

#### 1.2 形成并保存共享理解

按文字理解方法通读完整口播，回答整集问题、核心判断和叙事推进，定位必须共享的事实、关系、说话立场、修辞和人的处境，写清来源、不确定性与禁造边界。复核每个局部判断是否有原Cue或登记来源，删去对后续创作没有增量的复述。

首次创作把这一步的实际成果保存到当前 `candidatePath` 的 `result.understanding`。此时可以先只保存 `{"taskDigest":"<当前摘要>","result":{"understanding":{...}}}`，返工则在原候选或基线上保存本次确定的语义，保留已有镜头字段。下一步打开同一候选，读取这份语义稿和正式Cue再改编。语义稿尚未成形或来源不足时回本步补齐。后续考据若改变理解，回写这一处，并重看实际受影响的章节与镜头。

### 第二步：确定整集方向，先划讲解章节，再划全画幅章节

#### 2.1 从已保存的理解确定观看方向和章界

读取同一候选中已保存的共享理解，调用整集画册方法形成进入—推进—结尾和节奏意图，暂不切Beat。连读完整Cue，结合此前已建立的内容认清本章观看任务，按正文章节划分方法比较全画幅与讲解的实际收益及可行性，确定模板和连续范围。全画幅为默认；讲解须以解释为主要任务，收益具体且显著，事实、现有能力与真实时窗支持。地图与空间沿讲解模板的专门方法，不按题材或关键词入选。这里确定章节边界，不是Beat切点；具体判据与讲法统一见正文章节划分方法。

讲解起止按本次图解任务的必要范围判断，不为完整包入已交代的背景或适合全画幅的独立事件，也不为缩短删掉必要参照、比较两端、结果和限定。具体判断沿用正文章节划分方法，在原章节划分与复核中完成。没有成立的讲解任务时，全部内容归全画幅；不按关键词抢占范围，也不把全画幅图数容量作为换模板理由。

先按现行判据划定讲解章节，再按章节划分方法将剩余连续全画幅内容组织为相对完整的叙述，不跨已选讲解章节拼接。此时只定章首尾，不切Beat，保住人物经历与整集节奏。

#### 2.2 保存完整章节初稿，交给考据步骤

按`{"taskDigest":"<当前摘要>","result":{...}}`将`understanding + albumPlan + beats + templateRuns`保存到同一`candidatePath`。首次创作时，每章先用一条B记录保存首尾真实Cue、整章观看要求和模板，再由对应`templateRun`引用；讲解沿用这条整章记录。全画幅的B在此先保存章界，第四步细化为实际镜头。返工继承有效条目及身份，只保存授权范围内的实际修改，不重建整篇。字段须完整、范围连续覆盖全文、引用唯一；不交另一份章节划分稿或新增字段。前后呼应的元素在第四步形成真实B记录后落实；返工保留范围外原值。F/R及相关语义由System Control按Cue范围投递，不转抄到导演结果。

保存后，按章节划分方法复核讲解的漏选、误选与首尾，以及全画幅章节是否切碎或硬拼；全片只有全画幅时保留原额外复判一次。实际修正写回同一候选，再进入第三步。

### 第三步：建立历史视觉依据，交接人物、衣装和环境

本步读取已保存的章节观看任务、正式Cue、Understanding与现有来源。完整读取[历史视觉考据组件](historical-context/README.md)，先确定每个关键场面有哪些画面决定需要史料，再查实际入画的人物样貌、身份和活动对应的衣装、场所或器物。参考图用于辨认对象的样子，画法和色彩由节目视觉设定及实际场面决定。全篇只有抽象关系或无需时代复原的范围时，直接进入第四步。

将已作出的专业选择与实际取得原件写入组件规定的当前scratch研究输入，运行publish取得登记资料SA，再bind到同一候选。**完成结果是来源库中可读取的资料与原图，以及候选内按Cue分配的读取提示**；写了说明、贴了链接或只存了搜索结果都不算完成。第四步先读取这个结果，再形成具体Beat与观看要求。考据不代替构图、相机和艺术表达。

恢复时读取当前候选的资料SA与原件。已有分配且仍适用时直接复用，需要随分镜或字幕调整分配时运行不带SA的bind。新资料已登记但未绑定时用该次资料SA运行bind，复用已有原件。修订只处理授权范围及实际变化的时期／对象。资料不足留在本步补查或明确合理复原边界。若与口播或Understanding冲突，核对输入与依据，修正确实受影响的内容。文件、权利或范围失败由组件返回具体对象，根入口修复后续接。

### 第四步：精排全画幅分镜，定讲解段的首尾

#### 4.1 读完整章，安排全画幅镜头和讲解时窗

打开同一候选，核对摘要、章界及Cue覆盖。完整读取[分镜与剪辑方法](references/beat-page-method.md)，结合上下章和真实Cue，逐镜定下全画幅的场面构想、观看职责、进入、揭示、停留、切点和接法。另一幅主画面确有必要就在本步另分一镜。讲解明确观众带着什么问题进入、接住哪个参照、必须看清什么及结尾如何把结果交给后文。涉及反转或后文依赖的揭示，指出对应Cue或短语。章内切镜和停留由讲解作者在全章粗排中确定。

设计相邻全画幅的切点时，把前镜的落点和后镜的第一眼放在一起想，按两侧口播决定是继续展开还是收住重起。用[同一次组接设计](references/beat-page-method.md#1-从正文形成镜头)确定叠化或闪黑及其时长，把接法和观看要求一起写在进入的镜头上。

#### 4.2 落实整集关系，保存同一完整候选

读取第三步已登记资料的实际正文，结合各context适用Cue，把人物、衣装和环境的必要历史特征落实到本次观看要求。按作者实际景别保留要点，不逐条强塞全部细节；不得改变资料支持范围。出现新对象或时代依据缺口，回第三步只补实际缺口，保留本单其它有效研究内容，再继续本步；不能把未查清的关键身份与场合留给并行作者各自猜测。

保存已设计的全画幅分镜与接法、逐章讲解观看要求。字段与专用接缝见[写入同一导演候选](references/beat-page-method.md#2-写入同一导演候选)。同步章节成员和前后呼应的元素。全部B记录合起来连续覆盖Cue，每条记录恰好归一章。若切分暴露所选章首尾或归属不成立，回第二步只重判实际范围，再完成受影响的分镜。修改观看原文时保留组件生成的依据提示，拆合时保留所涉及的全部提示以供重分配。保存完整候选后，如有历史视觉依据，运行不带SA的bind，再进入4.3。

#### 4.3 计算并消费当前完整候选的可创作性规划

保存后运行：

```sh
node packages/modules/direct-episode/inspect-authorability.mjs <workOrderPath> <candidatePath>
```

首次创作时，该入口按当前数组顺序统一B／TR／RE编号并同步明确引用，校验通过后写回同一候选；存在`currentVisualPlan`的返工不重编号，核对既有身份和本次范围后计算规划。它不改cue范围、模板选择或语义文本，不猜重复身份和悬空引用。完整读取返回的改号映射及当前单位结果，按[Beat方法中的规划读取说明](references/beat-page-method.md#可创作性规划的读取)判断预想组织能否交付观看职责。程序只检查已选条件，不替导演判定模板。

全画幅规划提供与作者和P4同源的实际运动窗口，包括节目已选片头、相邻模板、Cue间隔与接镜尾段，并给出速度范围、倍率上限及推近／拉远／平移能力参考；规划只有行程上下界，不预选速度。单纯推拉无可用恒速时，结合原图内有意义的完整路线预判，不能用循环凑时长、强制统一秒数或锁定作者速度。讲解规划提供与正文渲染同源的进出推移和完整显露时窗，供下步核对前镜读完、讲解起势和结果停留。

失败返回`authorable:false`且无可用锁，留本步修正重算，不能因容量不足改用讲解章节。规划全部通过、预想组织成立且候选未改，才将同版候选、规划正文和`director-authorability`锁交给第五步。封存后的章界及全画幅Beat边界归导演，作者在正式时窗内编排。

### 第五步：顺看整集组接，集中修正一次并封存

先读第四步的完整候选、同版规划正文及其锁；上下文缺少正文时回4.3重取并读取，再运行：

```sh
node packages/modules/direct-episode/inspect-boundaries.mjs <workOrderPath> <candidatePath>
```

命令先消费同版可创作性锁，列出全画幅内部可切位置，以及相邻全画幅镜头和讲解章节的交接。实际读取完整索引、同一候选的`templateRuns`、对应原Cue与观看要求；摘要、总数或首条样例不能代表余下内容已读。按口播顺序完整顺读一次，同时审两层：

- **章节层**：按[章节划分方法](references/template-selection-method.md#4-复核本步结果并结束)检查讲解范围与承接、全画幅章节是否切碎或硬拼，确认各章首尾和整集节奏；涉及时代外观的关键场面，按组件研究方法及已登记资料核对依据、适用范围及跨章一致性。
- **镜头与剪辑层**：按[Beat方法第3节](references/beat-page-method.md#3-逐边界复核)核对字幕表达落点与画面交接，检查新意思已开始却未切、语义未落却抢切、职责重复、时间不足或空撑。每处讲解接缝结合实际推移窗和两侧Cue，核对前镜的落点、讲解参照的首次可辨时刻、讲解结果的停留和后镜第一眼；仍在推移中的画面按实际显露判断。

全部章节、长短全画幅镜头及实际相邻边界均须覆盖，不能只看初稿疑点。已完整持有的同版材料直接使用，缺失按1.1补齐。索引只用于定位，不把每个字幕间隙重新当作一道拆合题；有疑点才按所属层的方法展开比较。两层在同一轮完成，不另加审计轮次。枚举和可创作性通过不等于专业判断通过。

先审完整个本次范围，再在同一会话计划中一次列齐章节和Beat的具体问题、改善、修正方向及必要依赖。审计途中不边审边改；完成本轮比较后不再反复改选切法。无问题直接封存；有问题只按这份完整意见在同一`candidatePath`集中修正一次，保留其余有效页面。修正仍由原画册、Beat和章节划分方法完成，不凭容量单独切页；已有章节的整改边界沿用1.1。

候选一经修改，旧规划与枚举锁失效：保留已分配的历史视觉依据提示，保存修正候选，有相关资料时运行不带SA的bind刷新实际范围；再只重跑4.3的`inspect-authorability`，读取修正结果的实际规划，再运行`inspect-boundaries`刷新同版索引与锁，随后封存。这里的范围绑定、重算与枚举是技术交接，不再次遍历、抽查或定点复审切分质量，不重新执行4.1／4.2的全量判定。规划、字段或锁失败仍按原合同修正，不能绕过接纳；若必须扩大问题范围、重建整篇或再次作质量切分才能成立，明确报告未完成，不自行开始第二轮。没有改动时复用当前有效规划与枚举锁。运行：

```sh
node packages/modules/direct-episode/lock-boundaries.mjs <workOrderPath> <candidatePath>
```

封存同时消费最近枚举锁和同版可创作性锁，绑定完整导演结果；它只证明候选未漂移，语义与节奏仍由Director负责。第六步不得静默改写。

### 第六步：整集方案接纳，按章节交接

封存成功后，按工作单提交同一候选，不补模板或重复整集复核。封存失败不得提交，按错误返回对应动作；封存与`accept`连续执行时使用`&&`或等价失败短路，不能用无条件换行串接。Accept独立重算现有合同；漂移或合同失败时返回形成该结果的动作修正，再按第五步刷新技术规划、枚举与封存，不重置已完成的质量审计、不发起第二轮切分修正，也不在此静默改写。

本步一次接纳整集导演方案，不逐章接纳导演计划。后续正文按章节派工、提交、接纳和统计进度：讲解章节整章投递，全画幅章节联合投递全部待创作Beat。全画幅内部仍逐Beat核验、保存和渲染，章节成员交付齐备才计该章完成；局部返工只投递获准成员。具体调度见[正文按章节并行](../../../director/references/p3.md#正文按章节并行)。Visual Director在此停止，不执行作者设计或下一阶段。

## 停止条件

责任内问题返回上述对应动作修正。人工智能只消费模板目录`catalog`和登记方法；`cuePolicy`及规划由登记命令和Engine调用，不打开模板清单或源码，不读取或配置Feature。不得另造Structure、第二时间轴、筛选报告、检查表或无消费者的中间成果，也不得输出`treatment / features / opener / _producer`或替作者决定构图、注意力路线、相机、运镜、媒体生产与P4。
