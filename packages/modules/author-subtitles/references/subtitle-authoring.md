# 当前字幕作者的共用方法

AGY默认执行，Codex接手及验收时使用同一方法。成稿与自查分别对应根Skill第2、3步，本文件只拥有专业做法；调用、修正次数、接手和提交由根Skill决定。只读取当前工作单、同一配音和本单已准备的时间证据；调用者须给出当前时间路线与实际模型参数。本方法不调用其它代理，不准备或重投TTS/ASR，不执行Engine的next/accept，不修改系统及正式成果。

文字、时间和完整句子优先原则对两种执行者相同。只能通过现有build入口改变断点，写入当前candidatePath；scratchPath只能保存本单允许的临时文件。工作单、口播、配音及raw-word.srt/raw-asr.srt均只读；不搜索其它工作单、旧会话、备份或其它剧集。

## 形成唯一候选

先运行同一入口的`inspect`。尚无候选时显示原稿完整句子、原文字位、可选标点断点和时长；已有候选时只读取当前候选。按全文语义决定必要断点后构建：

```bash
node packages/modules/author-subtitles/build-candidate.mjs inspect <work-order.yaml>
node packages/modules/author-subtitles/build-candidate.mjs build <work-order.yaml>
```

云端路线的两条命令均追加`--timing-source asr --native-timing-issue '具体原因'`；原生路线无须附加参数。程序默认只在句号、问号和叹号处分段；逗号、分号和冒号不是自动切换点。保留全部文字和标点，前引号随下句，无需VideoCaptioner重新猜句界。

恢复回执的模型不是默认BIJIAN时，追加实际`--requested-model`和`--actual-model`；不得把已发生的识别改记成另一供应商。

完整句子能正常显示和读完时保持一条，不追求18字或固定条数。32个正文字符仍是硬上限；超长句、明显长停顿或不合适的阅读节奏，才由当前字幕作者按完整分句选择`inspect`给出的原文字位，使用`--break-at 20,46`重建。不得在人物姓名、年代、数字与单位、完整名词或紧密语法成分中间切开，不按字数平均拆分，不为了字幕容量改写口播。

一条字幕换成两行同时显示，与两条字幕先后显示不同。正式cue仍交付连续正文。`inspect`由程序读取当前节目Visual的正式字体，复用render-video成片的字幕组件、字号和视频宽度，在浏览器测量后返回`display`来源及每条`layout.lines/lineCount/overflow`；作者直接据此检查行首行尾、标点和语义，不自行估算每行容量，也不另找字体。测量失败先解决具体输入或运行问题，不能声称已核对显示。不能只因单行较长就拆掉完整意思；超过两行或溢出时选择现有完整分句或并列属性边界，不改字、不缩字体。

短日期、地点或连接词通常随它引出的动作，不仅因其后有逗号就单独成条。整句超过容量时，先寻找能保留“日期＋动作”的完整分句边界。

程序只取真实词的首尾时间，不在词内均摊毫秒。ASR同音误字、数字书写差异按整篇顺序映射，原始`wordCues`原样保留在证据中；识别差异超过15%或断点落在一个识别差异、同一词内部时拒绝。相似度只用于拒绝明显错配，不能证明音频内容正确。

候选3.0保留`cues`、正文摘要、音频摘要、时间来源及实际操作；Engine和finalize-narration共同复算。成稿必须先写入当前candidatePath，下一项自查从文件读取；不能只在脑内拟好字幕就声称完成。构建只证明程序生成，不填写人工复核记录，不创建第二候选。

## 阅读和同步复核

构建后再次运行同参数`inspect`，从文件按时间顺序完整读取当前候选及其复核输出，不只回想自己的断句意图。逐条检查语义是否完整、上下句是否碎切、文字是否来得及读完、字幕与本单同源词级时间是否对应。输出提供实际折行、原文字位、时长、每秒可见字符数、前置间隙及相邻合并提示；`bindingErrors`必须先消除。不足1秒、超过7秒、超过9个可见字符/秒是重点复核提示，不是自动切句或凭空延长时间的理由。

先查完整份候选，再集中修正已找到的具体问题；不为“再优化一版”重写全部分组。每项修正必须能指向当前cue或原文字位及语义、显示、同步上的具体问题。没有问题就交回；修正后重新读取完整候选检查文字、时间及相邻句影响，不能只查改动的那一行。剩余问题如实交回根流程，不在本方法内另起重试或外部审查循环。

不必要的句内断点从`--break-at`删除。确需合并相邻完整句时，选择原稿按句末分段的前一条序号：

```bash
node packages/modules/author-subtitles/build-candidate.mjs build <work-order.yaml> --merge-after 1,12
```

合并序号只指原稿完整句子，不随`--break-at`新增断点变化；多个连续序号合并连续句子。每次构建都携带全部已选择的合并、断点及时间来源参数，文字和时间由程序同步生成。重建后必须重新复核当前候选，不能沿用上次审查。

逐项核对`inspect`列出的识别差异，尤其数字、日期、人名及可能漏读的地方；不能只因为文字相近就宣布通过。对照本单原文、绑定当前音频的原生词级时间或已有ASR结果，核实首尾覆盖、异常时间、所有改变的句界与识别疑点。只按已取得的证据作结论；音量、波形和时长不能证明某个字实际读对。已确认漏读、差异跨句或现有证据无法排除具体同步问题时停止，交回相应位置与缺口，不把遗漏内容塞入邻句，不凭音量编造字级时间。

## 交回唯一候选

完成实际复核后，仅在当前候选result.evidence.operations记录本次执行者：AGY写agy:subtitle-review，Codex写codex:subtitle-review，Claude写claude:subtitle-review，只保留一个实际执行者。可用本地JSON读写原子更新这个数组，不改cue文字、时间或其它字段。重建后必须重新复核并重记，不能把程序生成或前一次审查当作本次审查。

复核记录只证明上述文本、显示和同源时间核对已经完成，不包含AI试听或听感验收。回复说明实际采用的证据；不能仅因执行者不能听音频就挂起已可完成的核对，也不能声称已验证发音或听感。存在无法排除的具体漏读、数字误读或同步疑点时，不填写复核完成记录，交回具体位置和缺失证据；不编造一个通过结论。

最终回复只说明当前候选路径、条数、实际检查内容、是否做过集中修正及仍有的具体问题和能力限制；不另写报告或第二份字幕。Codex验收时重新从候选读取，使用本方法的语义、显示和同步要求及正式Schema/Validator，不能用AGY的回复代替实际检查。验收不是第二份创作意见；合格就交付，发现具体硬伤才按根流程修正。
