# 综合解说P1取材与引用边界

本文件只服务`author-narration`。P0六项内容合同规定本集任务与集间范围；按实际需要从公开正文、本地材料或NotebookLM Query取得依据，Codex核对原文后向`author-task.md`交付创作任务、写作范围和清楚的依据材料，AGY不直接读取Query，自行组织故事。

## 直接读取正文

普通／full按P0创作任务中的标题、URL或本地路径、页段与用途，读取相关正文及理解所需的上下文。指定本地书先核对原身份与摘要；定位缺失时指出具体缺口，不另猜一本书。网页必须实际打开，搜索摘要、目录、未读取链接和P0概述均不能代替正文。材料足够就进入作者交接，不强制找书、建库或运行Query；采用NotebookLM时再执行下文。

将实际使用的正文保存在本单临时目录的JSON数组中，每项含`title`（标题）、`source`（实际URL或本地绝对路径）、`text`（原文及必要上下文），必要页段、日期放`locator`。保存原文，不用模型总结代替；无需复制整本书。随后运行：

```bash
node packages/modules/author-narration/scripts/author-handoff.mjs prepare-reference <workOrderPath> <正文JSON绝对路径>
```

程序将正文写入原`reference-materials.json`，有视频时同时保留工作单原视频快照。补充正文仍用同一命令，传入包含已存原文的完整数组；不删改已有依据。该快照与实际Query均保留到接纳和后续修订，临时输入随原收口清理，不新增事实卡或材料库。N02依据这些原文形成作者能独立读懂的材料，时事保持P0规定的资料截止日期，区分事实、观点和预测。

## 主Query

仅在决定实际使用当前工作单的NotebookLM材料时准备提示并调用。尚未调用的提示草稿留在普通临时文件，运行前才写入下列正式Query路径；进入调用后，失败或未知回执都须保留并沿原入口处理，不能删掉Query文件以绕过恢复。

在当前`scratchPath/notebook-query.txt`写入一条完整提示，准确表达以下当前P0业务内容；标题和措辞可按取材需要组织，不以逐字包含作为任务归属依据。任务身份由当前工作单绑定，Codex负责理解任务并判断返回材料的相关性与充分性：

```text
本集问题：<episodeQuestion>
本集初步答案：<episodeAnswer>
创作任务：<episodeCreativeBrief>
本集边界：<episodeScope>
```

随后要求NotebookLM只在该范围内寻找最小充分材料：

- 能直接回答本集问题的关键事实、关系、机制或判断边界；
- 与本集解释有关的关键行动或变化：当时处境与条件、具体经过、各方实际回应、结果和可观察后果；原文涉及选择理由或判断依据时，一并保留足以理解的上下文，只记载先后关系时不补成因果，没有记载的动机不猜测；
- 必要的时间、地点、制度、数量、比较基线、反证、争议与不确定性；
- 足以区分原文直陈、有限推论和不能成立的断言的原始依据。

不要让Query替作者决定中心故事、人物、入口、高潮、段落或结尾，不按完整年表和背景百科搜全，也不为预设文学细节、固定事实数量、字数或时长凑材料。每项返回直接原文和NotebookLM引用，保留理解行动、变化及原因所需的连续上下文；取材多少由解释需要决定，不能只摘结论句。同一命题有异载或冲突时明确并列，不能把搜索总结当证据。引用带回的前后集事件不扩大本集范围，也不因它们有材料就另加覆盖要求。

要求每项概括紧邻能支持它的原文与引用，说明原文实际支持的主体、行动、条件或结果；先定位本集对象和事件，再取必要背景，不用同题材其它事件的段落凑引文。找不到对应原文、只找到页面图片或只能支持较弱判断时如实说明，不用概括补出缺失的引文。请求仍负责取材方向，返回概括仍可帮助理解材料线索，不要求NotebookLM写成口播。

P0的`episodeAnswer`只是待材料核验的初步答案。原文削弱、扩展或推翻它时，后续作者必须据实收窄、修正或限定；不为维护P0原句寻找偏向性证据。

提示写好后，从项目根运行正式入口：

```bash
node packages/runtime-config.mjs python -B packages/modules/author-narration/scripts/run-cited-query.py <workOrderPath> --confirm-clear-chat
```

该命令清空当前Notebook聊天后执行主Query，按工作单绑定材料目录，并保留原回执；不要绕过脚本直接调用NLM。已有调用先按原恢复边界处理，不能把再次执行命令当作恢复。

## 读取与判断

首次取材仍按下文完整读引用。此后核对一个具体命题、但不知道它在现有Query哪条原文时，运行 `node packages/modules/author-narration/scripts/find-evidence.mjs <原Query.json绝对路径> <命题文本文件绝对路径> <本单scratch绝对路径>`。命题文件只写本次正在核对的一句话，放本单临时目录；程序从原Query筛出source_id非空、citation_number非null且cited_text非空的文字引用，保留原数组位置对应的R编号、原文和来源；无效条目不阻断其它引用，整批无有效引用仍按原补缺或停止方法处理。不先由Codex重读或改写摘要。脚本沿同一TypeSafe选择与原缓存返回实际原引用，不复制SDK或凭据；用户在本机`.env`设置`TYPESAFE_API_KEY`，进程环境优先，仍可使用原`~/.config/typesafe/api-key`。已知出处时直接读该条，不固定再调一次API。

入口从有效文字引用中直接选出一条完整支持该命题的出处，`selected.reference`原样保留原文和来源字段；没有完整支持时返回`decision: none`及`selected: null`。Codex直接使用所选出处继续原有事实核对，不再把整批引用重选一遍。`none`表示本批没有找到完整支持，不是史实为假，也不排除局部支持或相反证据；沿下文原有方法处理确实影响本集的材料缺口，不固定重扫全部引用、不自动补查。事实错误仍须有原文证据，不能仅凭`none`退稿。服务错误单独报错，由作者按原方法完成受影响的查找，不自动重投。首次完整阅读及交给作者的全部有效文字引用保持，不新增逐句调用、审稿轮次或事实表。

主Query成功后完整阅读每条有效文字引用的`cited_text`，结合`answer`定位其试图解释的事实与关系，再核对引用是否真的支持。概括可以帮助理解线索，但不能代替原文；引用非空也不证明与本集有关。同一时间、主体、行动和结果的多条引文先按互证、异载或冲突处理；只有原文明示时才拆成不同事件。

概括与引文错配时，按该命题缺少依据处理，正常有据的部分继续使用；图片地址、页面编号和答案里自称的“原文”都不等于`cited_text`。本集关键经过或判断依据缺失时，按下述各自条件采用唯一补Query或一轮公开来源补缺；不得因偏题或图像引用自行扩大重提次数、改原JSON或把已知材料缺口说成远端结果未知。仅概括措辞需要收窄时，就在原文支持范围内理解，不额外查询。

事实断言的上限由实际正文或`cited_text`决定：

- 原文直接说明的，可以按其主体、时间、范围和强度写；
- 原文只显示并存、可能因素、争议解释或有限关系的，只能按同等强度表达；
- 原文没有支撑的真人具体对白、动作、神态、心理、经历或新增因果，不能写成历史事实；
- 明确标为非档案复原的代表性或合成视点可以用于文学组织，但不能借此制造新的历史断言。

## 唯一补充Query

只有同时满足以下条件，才允许在`notebook-query-supplement.txt`写一个定点补充提示并复用原`conversation_id`：

- 当前`episodeQuestion`或`episodeCreativeBrief`不可缺少的一项具体事实关系确实缺失；
- 缺失会阻断本集回答，而不是只让另一种写法更丰富；
- 一条窄Query可以关闭缺口，不需要换题、越过`episodeScope`或改换内容主体。

补充提示只写缺失命题、它为什么是当前回答的必要条件，以及仍须返回直接引文和引用。不得补搜文学现场、预设高潮、作者偏好的另一个故事或一般背景。

补充提示写好后运行同一入口，脚本从主Query回执读取并复用原会话，不清空聊天：

```bash
node packages/runtime-config.mjs python -B packages/modules/author-narration/scripts/run-cited-query.py <workOrderPath> --supplement
```

主Query或补充Query已经明确返回非空答案和可确认的会话身份、但没有可用`references[].cited_text`时，正式脚本只把同一提示在同一会话原样重提，连同首次最多三次；这不是新补充问题。任一次取得有效引用即停止重提。三次仍无有效引用时，不再运行Query，也不因此退回P0，进入下述公开来源补缺。远端结果未知、JSON无效、会话身份不一致或提示词变化时不得用这条规则重投。

## 公开来源补缺

普通与`full`路线在读完现有`cited_text`后，若现有材料仍缺少本集解释所需的关键经过、行动条件或判断依据，可由Codex使用当前可用的公共网页搜索能力，将已确认的缺口集中补查一轮。围绕这些缺口检索并打开命中来源核对，取得可用材料就采用；这一轮仍未找到可靠依据的部分按下述缺口处理，不反复扩散搜索，不为一般背景或文学细节另开一轮。优先政府、档案馆、博物馆、大学、学术出版者及其它能够明确识别作者或机构、原始出处和事实范围的来源；必须实际打开来源正文，搜索摘要、聚合页标题和未读取链接都不是证据。

采用的公开来源先由Codex核对，按上文保存实际正文。N02将它支持的事实写进同一`author-task.md`的`依据材料`，仅来自公开补查的事实简短附来源标题和URL；N05补读直接用于本次事实核对及原错误清单，不重写作者任务书。必要的观点归属、进展状态与不确定性保持，不另建事实卡、来源清单、网页报告或证据等级表。来源只能补足当前P0任务，不能越过`episodeScope`或把推测写成事实；仍找不到可靠依据的断言按实际支持范围处理，其余有据内容继续。

写作必需的公开补缺在包根N02整理作者任务时完成；普通／full选中稿后，N05仍可按事实核对方法针对实际断言缺口补读正文。两者追加到同一快照，已读且充分的依据直接复用，不增加一轮全面研究；原Query继续保留，不建立第二份来源清单。主／补Query三次无引用时，脚本以`confirmed_answer_without_citations`回执交给N02，Query原JSON照常保留，但其中无引用的答案不能作为史实依据。

`narration`和`opener`返工不新增公开取材；`narration`只从工作单固定的`reusedNarrationMaterials.authorTask`继承原有创作任务、写作范围、依据材料及其中确有的公开来源，原文件不得改写。如果返工确实需要新事实，使用现行完整重跑边界，不把新证据偷偷塞进旧材料身份。

## 完成与停止

继续创作前，Codex须能从原Query和已保存的实际正文追溯`author-task.md`中的每项依据材料；作者任务本身只保留创作任务、写作范围和清楚材料，不把引文、证据分类或来源编号重写成文章骨架。AGY只依这份作者任务创作；P0某项仍缺证据不阻断P1，也不能假装已有依据。

需要换题、越过`episodeScope`或更换主要内容主体时才停止并交回真实上游；不要让Query、网页检索或Codex替P0改合同，也不要让材料数量代替内容判断。
