# 综合解说口播创作

只接收`episodeBrief.programForm=historical-explainer`，只提交一份正文、片头与发布内容的联合候选。

## 共用创作职责

P0决定本集问题、主体、范围、关键经过与必要解释。Codex读懂来源，把完整故事和作者用得上的依据交到N02。遇到材料与核心任务冲突，指出证据和受影响的解释。参考全文与Query原回执供Codex取材和核对。

AGY独立完成正文和片头，自主安排讲法。Codex先比较正文，再看片头怎样把观众带入这段故事。所选原作者围绕同一个看点完成封面与平台文案，Codex核对整套事实。

## 完整制作的交接顺序

| 步骤 | 负责者 | 交给下一步 |
|---|---|---|
| N01 取得依据 | Codex | 实际读过的来源，保存在本次材料快照和适用的Query回执中，供N02整理。 |
| N02 准备作者输入 | Codex | `author-task.md`交清故事任务和能说明答案的经过，补实关键依据。 |
| N03 独立写口播 | 三位AGY作者，程序收稿 | 每位作者交正文和片头，程序原样收成工作稿。 |
| N04 选定口播 | Codex判断，程序锁稿 | 按整篇的讲述质量和观看体验择优，正文优先。把同一路正文和片头写进唯一候选。 |
| N05 定稿封面构思和平台文案 | Codex准备输入，所选原作者续写 | 同一候选增加横竖封面构思和三平台文案。 |
| N06 核对并接纳 | Codex核对，所选作者按需纠错，Engine接纳 | 正式正文、片头、发布内容及可读文案。 |

文字接纳后，Director沿独立`produce-covers`节点交付横竖封面，P1至此结束。封面节点消费已接纳的文案和构思。

## 按请求选择路线

- 普通制作和`full`：走上表全程。`full`使用新`executionId / scratchPath`，只读取本次输入。
- `narration`：复用工作单固定的来源材料，重新交清本次任务，以新的单路AGY会话处理正文返工，按用户范围保留或修订片头；该稿发布续写、事实纠错和后续修订跟随新作者。
- `opener`：复用固定材料并续接现行正文作者，同步修改片头及必要的正文开场与承接，其余内容保留。用户指定片头原句时只锁定该句，仍由作者调整正文。
- `publication-copy / publication-all / cover-content`：直接进入[定点返工的发布内容](#定点返工的发布内容)，按工作单固定的现行稿处理获准字段，作者会话按发布方法确定。正文和片头保留。

换题、越过`episodeScope`、更换主要主体、用户明确整稿不要、固定材料或外部结果无法确认时，保留现场并停止或交回正式入口；不静默换会话、重投或扩大范围。写作必需的材料缺口沿取材方法处理；整套只在N06核对具体重大疑点。仍缺关键依据时说明它影响的事实或解释，保留已经成立的故事内容。

本次P1第一次实际调用AGY前，运行`agy --output-format json models`确认`gemini-3.8-flash-high`可用；不可用时停止，不静默换型号。

## 正文方法的选择

N02读取正式工作单`inputs.episodeBrief.explainerType`，按P0确定的类型使用对应方法，不从题材、标题、参考频道或旧任务书重新分类：

- `current-affairs`：采用[时政解说方法](references/current-affairs-authoring-method.md)，学习《王局拍案》的整篇讲述与推理方式。
- `general`：继续采用[通用解说方法](references/explainer-authoring-method.md)。

类型缺失、非法或与用户新要求冲突时，说明需要P0补齐或修订该选择，保留现有成果；不默认通用、不在P1暗换路线。

本次选择及方法绝对路径写入`author-task.md`的“创作任务”。AGY只读取本次所选正文方法。通用解说完整读取，时政解说必读“作者必读”，技巧与案例按需参考。首稿读取已选片头规则；选稿后按发布输入读取平台、封面方法与所选Cover资源。

普通／full三路共用同一方法，由各作者独立组织整篇。正文／片头定点返工也按当前P0类型交接该方法，只在本次获准范围内使用。N04用相应方法比较正文的讲述方式和听感，事实判断归N06。

## 准入

按`inputs.returnRequest.revisionScope`唯一确定路线。Codex核对P0六项内容合同、节目受众、当前来源身份、用户明确的时长限制和现行正文／片头，确认题目、范围、主要主体与集间边界没有变化；完整核对供理解任务与取材，不表示逐字全部交给作者。

N02原样交接P0的本集展开意图、用户明确的时长要求及存在时的`episodeBrief.maxDurationSeconds`；篇幅由AGY依据任务与材料决定，不设统一字数、最低长度或常见节目时长参考。`narration / opener`须证明固定来源材料、旧证据与当前任务一致；材料缺失或摘要变化时停止，需续接的作者会话缺失时也停止。`exactOpenerNarration`先通过已装配片头Validator，不得让AGY改写。

## N01：取得本集依据

先从当前工作单确定实际来源；普通／full可按本集需要组合取材：

- 有`inputs.episodeBrief.referenceProgram`：完整读取[`references/video-led.md`](references/video-led.md)，保存并阅读当前参考原文。
- 公开网页、本地书稿或NotebookLM取材：完整读取[`references/explainer-evidence-and-query.md`](references/explainer-evidence-and-query.md)。按P0创作任务中的材料定位实际读取正文；采用NotebookLM时按该方法调用`scripts/run-cited-query.py`，不能用answer代替实际引文。没有Notebook输入时直接取用可靠正文，不为取材强制建库。

实际采用的公开与本地正文保存到同一`reference-materials.json`，与视频和Query共同交给后续事实核对及返工恢复，再进入N02。正文与片头返工只复用工作单固定材料，不重新取材。已开始的远端调用仍按原边界恢复，不靠改用网页掩盖失败或未知结果。

## N02：准备作者输入

完整读取[作者任务方法](references/author-task-editing.md)，在`scratchPath/author-task.md`交清P0故事任务、写作范围和充分材料，由作者决定讲法。定点返工按该方法交接本次输入与锁定范围。准备好口播输入后进入N03。

## N03：独立写正文和片头

完整读取[`references/author-handoff.md`](references/author-handoff.md)，用已登记的`author-handoff.mjs`保存调用进度、原始回包和工作稿；固定字段、逐字封装及机械检查由程序完成。定点与纠错返稿也使用该入口，不临时编写封装或重抄正文。

按[作者任务方法](references/author-task-editing.md#使用固定作者提示)发起或恢复。普通／`full`的三路共读相同的任务、正文方法与片头规则，各自写好正文并完成能接入正文的片头。每路只交这两项。

程序从原回包收取正文和片头，校验后分别保存为`author-1.json`至`author-3.json`。定点路线保持单路及原锁定范围，直接形成唯一候选与本次作者身份，经[定点返工的发布内容](#定点返工的发布内容)交接实际受影响的文案与封面，再进入N06。

进程正常退出、JSON可解析、`response`非空且无权限软拒绝时，从`status=SUCCESS`或按作者交接方法核实同轮503后已完整交稿的回包收取。三路正文和片头均通过收稿并标为`received`才进入N04。任一路明确`failed`时，继续接收其余已发起结果，保留稿件并报告“三稿未齐，P1未完成”，不减少选稿数量或自动重投。用户明确授权重试失败一路时，只按[作者交接方法的单路重试](references/author-handoff.md#用户授权后的解说单路重试)恢复，其它有效稿件保留；重试再次失败须有新的授权。未知结果只恢复同一次调用，不能当失败跳过；无法确认原调用时保留现场并停止。定点路线机械失败停止。

普通／full原回包已到但未收得完整稿时，按作者交接方法读同一次原回包。若作者报告材料缺口，Codex核对现有依据并继续收取其它已发起的结果。确有缺口使本集任务无法完成时，按内容任务冲突处理，保留工作单和已有稿件，说明卡住的经过或解释及其所缺依据。

## N04：判断并锁定口播

完整读取[选稿方法](references/draft-selection.md)。按观众实际听到的顺序比较三套口播，正文优先，看片头怎样把人带进同一篇正文，择定最值得听完的一路。事实真伪和措辞是否超出材料统一在锁稿后的N06核对。没有可选稿时保留三路原稿，沿选稿方法停止。

选出成立整稿后，按[作者交接方法](references/author-handoff.md#锁定整稿)的`select`命令提交所选路号。正文和片头原样写进唯一候选，记录作者身份，进入N05。选择锁定后沿原路恢复。

## N05：所选作者定稿封面和平台文案

按[发布输入方法](references/publication-author.md#解说选稿后的发布输入)以锁定口播准备本次`publication-input.md`，再沿[选中作者补写发布内容](references/author-handoff.md#选中作者补写发布内容)续接所选原会话。封面和实际片头共用一个看点，朗读自然且小图清楚时共用原句。程序只合入`publication`，完整交接后进N06。续写出错或未知时保留锁定稿和原回包，沿本次续写恢复。

## 定点返工的发布内容

仅narration或opener形成修订稿后，完整读取[发布内容作者方法](references/publication-author.md)，按本次范围交接发布内容，再进入N06。解说整篇重写时，由本次原作者沿已有的一次发布续写把整套文案与题图按新正文过一遍，重做适用的YouTube章节，调整受影响的表达。局部修订时，仍适用的整套发布内容可由程序继承；有变化则按本次授权由原作者一次补齐。publication-copy、publication-all、cover-content工作单直接按该方法单路处理，不重新取得或选择正文材料；公开文献所需补读按该方法保存在同一发布输入，不改变固定正文与原材料。普通／full不经过本节。

## N06：事实核对与接纳

读取[`references/narration-audit.md`](references/narration-audit.md)，在这一次核对中只处理能够确认讲错或编造、且会使观众误解基本史实的硬伤。只按该方法定点回查具体重大疑点，保存实际使用的正文。平台文案和封面适用同一尺度。一次列出必要错处，交原作者做最小替换，其余逐字保留。进度与事实清单按已读交接方法保存和恢复；已有清单直接复用，不重置核对或纠错次数。

普通／full无错误时用原mark将所选工作稿标ready；定点返工不标三路进度。各路线有错误时只按核对卡回所选原作者会话一次，再用交接程序的correct更新唯一候选。完成原有机械交接后，只按[原错误确认](references/publication-author.md#纠错后的原错误确认)核对原清单及必要连带表述；不重做整套核对、不查找新问题、不润色、换作者或追加修改调用。机械失败停止，未知只恢复原调用。

无未知调用，唯一候选已完整交接，原清单确认为空或已完成原错误确认时执行`accept`；普通／full还须所选工作稿为ready，定点只确认本次原调用已完成，不创建ready状态或三路记录。恢复有原错误的ready工作稿也须完成该确认；未改对或无法确认进度时保留候选并报告，不接纳或重投。Engine保留本次实际使用的Query及reference-materials、作者任务书与所选作者会话并清理工作稿。文字接纳后交回Director收尾。

## 提交边界

普通P1、`full`、正文与片头返工均提交正文、片头与publication。发布内容修订锁定正文与片头。Engine分别写入正式文件，不把发布文案送入TTS。机械通过不代表观众接受，也不代表纠错返稿经过第二次内容审计。
