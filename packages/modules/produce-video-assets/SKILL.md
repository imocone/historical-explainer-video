# 剧情视频生产工位

由本次P4视频子代理在视频设计正式接纳、主代理交付本节点正式工作单后继续执行，不另建第三位作者。只从本单完整读取已接纳设计与生产输入，保留原方法、技术验收、恢复身份及授权边界，不以设计阶段的记忆替代本单；交回候选路径、交付/远端身份和具体问题，不向主代理回传图片、视频或候选全文。设计阶段已验看且当前仍持有的同版首图可沿用观察，不重复发送整图；本单设计、来源身份和实际状态仍须读取核对。原生成后的不看片边界保持。

准入时确认当前P4 video-assets工作单及允许写入，读取videoPlan、正文/Cue、videoPlan中的实际首图、visual和固定video-template的AUTHOR，进入其视频生产分支。只用工作单固定选择，不重新选段、定分次或创作提示词。候选初始化、范围换算、剪接及归集由程序负责。供应商调用使用`dreamina-canvas`；首次使用、升级、登录或CLI故障时读取[画布CLI使用与升级](references/canvas-cli.md)。

路线：逐组原节点生成或恢复 → 下载原片 → 一次编码裁切与转换规格 → 全段归集交付。前组成功的原生成节点是普通续接的输入；全部组完成后形成完整clip并写回唯一候选，沿原accept收口。Template提供首图起态与参考使用方法；本Module拥有运行、交付及失败返回，程序执行调用、剪接和归集。

## 生成与恢复

videoPlan.spans是独立剧情，parts是P4已定生成分次。各独立段当前可执行组先提交或恢复，再统一等待；同段后组默认直接引用前组成功的原生成节点，不下载剪片再上传。Template明确交付剪后参考原因时，才提前剪定并上传对应前组；其它组不重传。首次使用唯一AR001首图，后续不另生首图、不累计上传整片，参考仍须满足当前模型容量。

首次生成前读取已选Template的P4方法，查看各待启动段首图的必要构图。模型、分辨率、提示词及容量从已接纳合同取用，不自行换模型；720p来源归一为1920×1080、60fps无声视频不等于新增画质。

```bash
node packages/modules/produce-video-assets/generate.mjs --workspace <节目根> --work-order <当前工作单绝对路径> --all --wait --authorize-paid-generation
```

首次付费标记只传递当前P4已有授权；程序保存节点、查询积分报价，并在该授权内批准本次报价上限后运行，不能替换已有未知或失败对象。未获准替换的未收口原编号先恢复，包括新设计不再使用的旧组；跳过旧父请求前按原替换链检查，不改原请求。批次由一个进程持原整集锁更新唯一候选，运行期间不另开generate或手写轮询脚本。服务端明确pending／running的原对象由程序有界等待，到期后沿原入口继续；absent、unknown或未识别状态交回核实，不能凭预先保存的编号推断已受理。查询、下载或本地异常恢复原对象，不另开供应商命令。

本集画布身份保存在原video目录的`canvas.json`，生成节点、输入资源和提交编号保存在各分次原`generation.json`。出现`canvasUrl`后打开并发送该链接，复用已有标签页；画布只供查看与续作，不取代正式设计或本地交付。首图上传一次；普通续接直接连接原生成节点，仅剪后参考例外上传对应前组剪片。所有可能写入的身份在调用前保存；提交响应丢失只查询原submitId，不重放run、不按提示词寻找任务。

正常批次返回各段complete、pending或blocked及同一candidatePath。完成来源直接进入程序剪接，不返回默认看片取材任务。受阻或未知段保留现场；其它仍明确排队或生成的段以`--span <id> --wait`恢复，不反复批次查询同一阻塞。全部已选剧情齐备后才能接纳。0段由正式next直接交付空clips，不签发AI工作单、不调用供应商。

## 程序取用、剪接和交付

普通链全部原生成成功后才下载原片；下载使用独立临时路径，核对CLI交付后原子落位，文件已到位但记录未保存时也能恢复同一资源。剪后参考例外只提前处理其依赖前组。程序从本组源片开头连续保留原交付窗口：首组头部余量在正文之前，各镜头正文范围按已定frameCount顺序分配，末组保留尾部余量。程序写原cuts，以同一FFmpeg调用完成帧率换算、尺寸转换和剪定，不先输出转码中间片；这些范围表达既定时间安排，不声称识别了实际动作或完成质量验收。来源帧数不足则报告技术失败，不循环、冻帧、变速或自动重投。

已有绑定当前来源的有效cuts及已完成part保持，恢复不因新方法重选或重剪。范围、来源及工作单身份仍由原程序核对。每组part.mp4只供剪后参考例外及最终归集；全部组完成后按序直接拼接统一规格码流，将完整clip写回唯一候选。独立span不合成同一剧情，交付仍按原旁白窗口供P4播放。不要求AI确认中间剪辑或转抄身份。

默认生成后不打开源片、抽帧图、整合视频或上下文预览，不判断动作、接续与观感，不主动评价缺口或提议质量返工；画面由用户检查。只汇报交付和必要技术故障，不填写review、质量评分或未观看豁免，不重述旧画面缺口；已有真实review保留，不写成本次观看。用户点名看片或编辑时才进入下文对应入口，普通生成与整改不增加观看授权。

全部complete后沿原Engine accept提交，再读同参status；stage-complete后回Director执行原P4收尾打开Studio，打开即止，不播放检查。accept遇到技术错误只修本地交付或报告真实上游，保留有效结果；不因未看片或旧质量评论阻塞交付。

## 接入已完成的外部首组

仅在用户明确要求时，以原`--span <id> --import-source '{"request":"原请求JSON路径","submission":"原提交回执JSON路径","edit":"实际首图编辑说明"}'`读取画布原请求记录及对应node run回执，查询下载同一成功对象。请求记录包含原request、canvas的projectId/nodeId/inputFile，提交回执由data.items提供对应nodeId与submitId。核对实际首图表达当前设计，保留实际首图及编辑来源，不冒充原AR001。程序不提交、不付费；重复接入恢复同一编号，随后直接剪接交付。此参数不与all、重生、编辑或付费参数混用，不接受未知对象，不扩成任意文件替代。

## 仅在用户明确要求时看片或编辑

用户另行明确要求后，才沿原单使用以下入口；整改、旧质量评论或AI自己想到的疑点不自动触发。先`--span <id> --inspect '{"part":1}'`取得当前来源、selectionToken及帧号材料；有范围时可同时给startFrame/endFrame。按用户点名范围定位，必要时查看局部，不扩大为整段或整单审片。

```text
--apply '{"part":1,"selectionToken":"inspect返回值","cuts":[{"shotId":"S01","sourceStartFrame":54,"sourceEndFrame":354}]}'
```

示例数值无默认含义。帧号对应60fps剪辑时间轴，原片在剪接或查看时同源换算，从0开始、结束帧不包含；也可用成对sourceStartSeconds/sourceEndSeconds，不能混用。cuts只含正文，原程序保留连续首尾余量；范围顺序、不重叠、正文时长、来源身份及余量按现行合同执行。selection-saved后继续原生成入口剪接，不附加再次看片。改前组可能影响已付费续接时按末节边界处理，不能自动重投。

用户明确要求完整上下文预览时，使用`node packages/modules/produce-video-assets/preview.mjs --workspace <节目根> --work-order <当前工作单绝对路径> --span <id>`。只写scratchPath，不写正式video-manifest或P4成片；原旁白、字幕及转场保持。不新增观看任务或报告。

## 失败与定点重生

提交前保存意图及稳定submitId；编号只表示本次身份，不证明已经受理。响应未知时只查同一画布操作，不通过任务列表或提示词猜选。其它独立段仍可沿原授权推进。远端明确失败或源媒体技术不合格时保留原编号及已完成部分，不自动再次付费。剪辑范围填写错误属于本地选择问题，不改原远端为failed。已选视频缺失或技术交付故障未处理时不删段、不回退静图、不完成P4。

用户要求处理平台审核拒绝时，先核实当前原任务编号、远端终态、平台原报错及可见详情，对照实际提交的完整提示、实际首图或前组原生成视频；使用剪后参考时，核对实际上传的剪定MP4。不能只看计划提示或把查询超时、本地异常当作内容拒绝。明确pending／running仍恢复原对象，未知仍按原边界处理。用户明确要求检查参考内容时，才沿既有inspect入口查看点名分次的必要范围，不扩大为例行审片。

相同报错文案不等于相同原因。平台指出具体文本、图片、视频或生成结果问题时修正该实际问题；只给“内容不符合平台规则”时，如实说明具体触发项未披露，不凭猜测删除历史身份、旗帜或建立敏感词表，不把第三方提示词审计当作平台原因证明。整改须符合平台规则并兑现当前叙事，不能用换词掩盖被禁止的内容。

已核实为同类续接拒绝——当前实际参考片未变，已有记录显示只调整文字仍被拒，且未定位到可单独修正的文本项——优先沿换首图、联合调整场面与动态提示的办法处理，不继续同参考片反复换词付费；不为凑齐判断证据追加试生成。这是已有同类现场验证过的整改办法，不能据此断言参考片是唯一原因，也不能套到所有审核报错。

需要改首图或场面设计时，只按allowedReturnTargets返回video，reason写明已核实的失败、实际输入及整改范围，给真实cueRefs，由P4按Template的V2方法修改当前候选。重做改变首图后受影响的首组及依赖续接，保留不受影响的独立段和合格素材。已有针对本次或同类整改范围的明确授权时连续执行，不逐节点重复询问；授权须覆盖新首图和实际受影响的付费分次，不套用未知超时的一次重试许可。整改再次明确失败或未知时保留新旧任务，停止追加提交并报告。

设计错误也沿同一返回入口；生成错误保留具体来源与请求身份。改变设计或首图实际输入后，消费重新接纳的设计沿正常生成入口执行，不能拿旧requestDigest强行regenerate-from；下列定点替换用于设计不变的原请求及其接续：

- 已知编号但结果未知，先说明可能重复付费。用户明确批准替换该组，或符合AGENTS已授予的同类提交超时一次重试许可，才执行替换。该持续许可仅适用于原进程已结束、已有唯一编号、正式恢复仍无远端状态或结果的分次；符合时不重复询问。已明确排队或生成则恢复原对象；无编号、明确失败和质量返工不适用这项许可，明确失败或质量返工须另有针对该组的授权。
- 取得适用授权后，用`--span <spanId> --regenerate-from <原组requestDigest> --authorize-paid-generation`。保留旧状态与编号，旧结果迟到不覆盖新交付；重复同一命令恢复已建立的替换，不创建下一代。替换再次失败或未知，只恢复或停止，不自动再次替换。
- 前组重生或原生成身份改变后，实际依赖它的已付费续接可能失效；普通剪辑修改只影响明确使用剪后参考的续接，程序停止并报告实际影响。只有用户明确授权该续接并指定原requestDigest，才替换并绑定新前段，不能用首次付费标记自动重投，也不能把这种重生当成无成本剪辑。其它独立剧情视频保留。

本包仅写本集`制作/p4/video/`内的媒体、原记录和执行锁、当前candidatePath及scratchPath；空选程序只交付本节点正式video-manifest，不重开阶段，不改P4设计，不另写Dreamina请求、切换模型或自行调用供应商。
