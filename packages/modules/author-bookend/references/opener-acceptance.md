# 片头接纳与TTS恢复

本资源只用于`author-bookend`片头候选提交后的确定性接纳或恢复。它不创作片头文案或视觉选择。

## 正常接纳

1. 先按当前模板判断是否需要旁白。`documentary-opener`不创建TTS输入、音频或卡点，直接完成无旁白接纳；有旁白模板在获得正常流程付费授权后，按模板定义的可听字段和顺序形成唯一TTS输入，并执行工作单投递的`opener-tts-contract.json`与真实卡点程序。
2. 先完成一次纯音频合成，立即保存TTS输入、MP3和回执；再从同一音频取得模板要求的句级卡点。
3. 锁定的TTS输入是唯一文字真源。识别文字只提供句界证据，不得因识别错字改写口播，也不得并句、拆句或调用语义模型重写边界。
   真实识别按剪映（JIANYING）→必剪（BIJIAN）→本地Whisper.cpp（WHISPER_CPP，large-v3-turbo）依次尝试，成功即停止；本地使用已安装模型，不上传音频，回执记录实际识别引擎。逐段片头的本地转录与原文能可靠对齐且能找到对应真实停顿时，以原音频静音区间定位句界；识别错字仍保留识别原文作证据，不改正式口播。无法定位时沿原词级时间路径，不把句级结果冒充逐字卡点。
4. 成功后只回填当前合同要求的正式口播证据，再按TTS合同、模板Validator和模板时间线核验；不得减速、插静音、截音频或让画面脱离口播。`opposed-opener`和`glass-opener`按作者已定语意段从同一音频取得各段卡点，时长随真实口播与收尾动作形成；同一文本和音频仅分段改变时只重取卡点，不重提TTS。

## 恢复与停止

- TTS远端结果未知时保存真实原因并锁定同一请求，禁止另建请求或再次付费合成。
- 音频已经保存但卡点失败时，状态固定为`awaiting-timing`；后续只复用该MP3重取卡点。
- 旧合同留下的不同请求指纹只作历史证据，不得阻断新合同的一次正常执行。
- 真正超出所选模板容量时停止并返工P1片头稿；不得在P4改字、加速音频或插静音。固定时长模板不延长；`opposed-opener`和`glass-opener`按真实配音和收尾形成时长。
- 正式片头证据接纳后，本次接纳动作完成。
