# 正文视频设计工位

由P4独立视频子代理执行，可与片头作者并行，但不继承主会话或片头作者上下文。完整读取本单正式输入、所选模板的规则、方法、教材及必要参考，不削减创作和首图验看。主代理只领单与串行接纳，作者交回候选路径、完成范围及具体问题，不回传媒体或候选全文。

本任务是执行已有Module与Template，不是维护Skill；不重跑P3理解/导演，不替主代理领单、派工或接纳。只在当前正式video工作单执行。准入时核对允许写入、当前正文和Cue、P3已接纳正文设计及理解、来源、节目已选visual与固定选择的唯一video-template；不重选模板。读取其AUTHOR、Schema，方法及例子只在模板点名时按工作单登记身份读取。输入核对是准入动作，不另建分析稿或核对步骤。

路线：按模板完成选段、联合设计及首图交付 → 核对唯一候选 → 正式提交。选段方法、数量与时长、画面和视频提示词均由模板拥有；本模块不复制一套规则。

## 进入模板与恢复

并行时完整正文投递在本单storyboard中，片头由`inputs.openerReference.source`指向正式episode-package的opener，不复制未定稿片头。先进行V1及不依赖片头的联合设计；选中范围始于正文首Beat时，在原V2接镜处等待主代理确认本次片头正式接纳，在首次消费、上下文缺失或片头实际变化时执行`node packages/p4-opener-reference.mjs <workOrderPath>`，取得完整正式opener及其绑定版本，再执行原方法要求的末态/接镜核对及首图落实。同版完整输入仍保有时沿用；程序仅在原scratch绑定来源与版本，作者不手抄摘要、不新建候选。未交接时不猜末态、不跳过核对或消费旧版；候选与其它段设计保留。接纳前须完成所选范围的全部方法。

专业步骤按Template的V1/V2执行，迭代单位是V1选出的spans，不逐Beat另开工作单；在同一候选内完成各段，或按模板合法返回。

按模板规定在同一`candidate.result`先写选段、再补完整设计，只写当前candidatePath。无当前候选时从V1开始；只有选段结果时，V2先读取已落盘结果；已有部分设计时，读取并核对它与当前选段的一致性，只续作未完成部分。已有完整设计时进入提交核对，不重作选段。不得等全部脑内完成才补写前步，也不能以字段非空代替模板完成条件。

V2允许调整同段镜头、分界和提示词；要改变选段、叙事目标或来源时回V1，只重做实际受影响的后续设计。已有正式成果的返工必须由当前工作单授权，不自行以旧video-plan建立候选。

返工单投递`currentVideoPlan.content`时，该值是当前正式方案。无当前候选时，先将其原样保存为同一候选的result，再按本单`returnRequest`进入模板的返工分支；只修实际失效部分，未变选段、镜头、提示词和接缝保留。首次创作、完整阶段重跑或明确要求重新划段仍从V1开始；输入没有该方案时不得另读旧文件补入。

## 汇总、提交与返回

模板返回后核对：全部选中段均已完成V2和实际首图交付，或V1已明确交付空选；当前唯一候选符合工作单Schema及写入范围。提交当前候选，由Director执行正式accept；Engine校验后写video-plan，同阶段produce-video-assets消费实际首图、镜头和动态提示词。设计正式接纳后，主代理将原video-assets节点的新正式工作单交回同一视频作者，切入produce-video-assets入口；本Module不越过接纳自行启动生成，也不重做已成选段、设计和首图。0段也是正式结果。

接纳拒绝时按具体错误回模板V1或V2修正同一候选，不临时绕过合同。输入缺失时停止说明真实上游缺口；只在allowedReturnTargets确有相应责任方时走正式返回，不补造、改正文或擅自调用生视频。
