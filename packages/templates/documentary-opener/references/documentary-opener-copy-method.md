# 回忆画流片头文案方法

本方法服务节目配置选中`documentary-opener`的纪录片或历史解说；节目形式不替代模板选择。它不做反常识标题、知识问答或结果—原因公式，而是在正片前从一个具体观察中提炼全片的核心关系。

1. 先完整理解最终正文；纪录片同时读取当前`storyOutline`，历史解说以本次作者任务的主题、范围和实际正文推进为依据，不要求不存在的故事大纲或P0问题、答案。用一个内部判断串起本集的起点、主要推进和最终显出的历史或生活关系；再选择一个能承载这条完整故事线、并在片头内部成立的人物、物件、动作、时刻或空间。它不能只是局部场面的醒目细节，也不是正文第一段的前半截，不负责交代故事起点。
2. 用一句约16—20个汉字的陈述，把这个具体观察与全片最终显出的生活关系连起来；不用分号，不展开证明，不先解释城市机制，不写导演阐释，也不提问。
3. 纪录片片头可以使用P0明确授权的合成人物、合成路线和必要连接动作；历史解说继续遵守其正文非虚构边界，不因选择本模板取得虚构许可，但不能把它写成文献目击或真实个体传记；涉及历史事实的地点、行业、制度、数量、时序、因果和生活后果，纪录片必须由Query引用承担；历史解说以作者任务中已核验的材料与最终正文为依据，片头修订依据当前正文及本次固定材料，原Query与来源追溯由Codex核对。
4. 片头与正文是两个独立文本。正文必须从零建立必要主体、地点、处境和任务；即使没有播放片头也完整顺畅。正文可以自然交代片头涉及的必要基本信息，但不得复述片头的核心表达、句式或同一组开场事实，也不得用代词、省略主体或续接动作来迁就片头。
5. 片头只有一句，不使用分号或问号；第2条的约16—20个汉字是创作目标，去除空白与标点后的机械上限为20个可读单位。这句在P1照常形成并供P4约束进入观察与选图，但片头成片不朗读、不显示；它应克制、具体、在片头内部成立，而不是短视频标题、散文题记、正文残句或导演阐释。候选提交后由确定性`copy-policy.mjs`核对，不把程序正文投递给作者。
6. 成品反查正文开头、主要推进和最终落点：三者应共同赋予这项观察完整意义。若只读正文前半部分就已穷尽片头的意义，说明它只是局部引子，必须重新选择；但片头仍只呈现具体观察，不改写成问题、结论摘要或结果—原因公式。

P1仍只形成一条`openerNarration`；按上层任务与正文联合交付时仍服从上层返回格式，不额外返回片头候选或说明。是否朗读由P4所选片头模板决定，本模板不合成它。
