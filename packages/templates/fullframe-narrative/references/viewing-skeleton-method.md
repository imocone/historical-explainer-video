# Viewing Skeleton Method（观看骨架方法）

本方法由Codex正式作者执行，把[场面选择](scene-selection-method.md)落实为画面数、逐图职责、注意力语义与Cue边界。这是联合设计的构思方法，和构图、路线一起调整，不单独锁定或交付。

## 1. 建立来源与任务边界

联合单先理解所选段的共同推进，再分别从每个成员的Beat、完整`directionContext`、cues、语义投影、正式来源、`mustNotInvent`和`templateContext`形成其观看任务。单Beat修订只修改当前任务；同段参考不扩大来源和Cue范围。图文分工按[场面选择方法](scene-selection-method.md)：逐图职责共同保留`mustShow`，与口播一起兑现`viewerOutcome`；不把cue中每个名词、数字和背景自动增加为画面义务。画面新增的历史断言须有明确依据，口播、已承诺关系与新增断言均不得与来源冲突。作者按场面选择方法理解语义投影中的`intendedMeaning`与`prohibitedLiteralization`，区分表达和事实误读；素材编译程序按本图当前所引来源与作者单位Cue合成适用限制，不写回候选，作者不需重复抄写禁止句。

先按[场面选择方法](scene-selection-method.md)形成实际表现并核对当前任务。选场薄弱时直接修正；只有任务确实超出现有静图、取景和呈现能力，或当前Beat吞并了应分别建立的观看推进时，才把具体缺口交Director复核，作者不自行换模板。画面配合口播已兑现职责时保留，不要求静图独立讲完全文。同一次改革或因果链不自动等于同一页任务；没有独立推进、只是共同完成当前任务的部分可以留在页内。

将导演切出的每拍意思接成实际观看：这段字幕何处取得重点，上一拍留下什么，当前画面要让什么获得分量，离开时观众应已经读清什么？这些选择在原`purpose / attentionPlan / sceneDescription / motion`中共同落实，不另交匹配表。相邻Beat表达不同，画面就要有相应的状态、关系或观看侧面；不能仍用一幅泛场景换旁白，也不必每拍换地点或主体。

结合[构图方法](picture-construction-method.md)与[相机方法](../camera/design-method.md)同时决定源图及观看路线。短拍可从已经可辨的主体或关键关系进入，在持续运动中加强其分量；需要展开空间或揭示另一端时，把连接和目标安排在源图及实际能走到的路线中。长拍要有持续观察、逐步读清或情绪深化的具体内容。时长不固定对应近景、远景或某种运镜；更短不等于画得更粗，完整场景的形体、光影、材质与层次仍按原构图方法实现，只调整当时需要读出的主次。

把重点成立的时刻配回当前Cue和转场显露窗口，既不在旁白尚未转折时提前揭晓，也不等到切出才刚扫到关键对象。运镜是在同一完整静图中组织取景，不能替图中人物继续搭桥、卸货或转身。源图表达、实图执行和最终取景分别沿原设计复核与实图落镜确认：正确生出整幅图，不等于这一拍的实际镜头已表达清楚。场面、入口或路线可修时由作者联合修正；Beat本身吞掉多个意思或没有足够窗口时，带具体冲突返回Director，不自行移动边界、停镜或牺牲必要内容。

## 2. 决定画面数与职责

单A与A/B按当前表达共同考虑，不默认优先一种，也不因Beat时长强制换图。单A可用持续观察、取景揭示或情绪积累兑现任务；A/B须符合[共读判据](scene-selection-method.md#两个决定性瞬间)，两图推进比持续单图更清楚时采用。程序提供技术可行的真实字幕切点；作者仍须按[场面方法的清晰观看下限](scene-selection-method.md#阅读与运动)逐张取舍。A/B任一张不足时重选合法切点，或在完整保留表达的前提下合成单A；单A也不足或必要A/B无法成立时，带具体Cue和任务返回Director调整边界。

将已选画面中支撑理解或感受的内容写成可观察的对象或区域。直接认识一个场所也可成立，不强加情绪、转折或新增信息。

将结果写入每张的`requestId / kind / frameId / purpose / sourceRefs / mustNotInvent / required`及三个`attentionPlan`字段：

- `purpose`：按场面选择方法写本图选定的具体场面、状态和可见依据，再说明配合旁白的意味；不把抽象结论留给生图寻找画法，也不另交理解报告。
- `viewerChange`：这段观察带来的具体认识或感受，点明已选画面怎样支撑它；不以“体现压力、突出分歧”等结论代替依据。运动类型、方向、速度及其构图实现在联合设计中选择。
- `entryFocus / landingFocus`：承载上述作用、具体可定位的对象或区域，保留当时需要共同读到的关系。可以是同一主体或同一组关系，不能仅凭两个字段推导需要移交注意力，也不因有人物就自动落到脸和手。

例如“已有货源，还不等于能安全交货”：`purpose`可选罐区、泊位油轮与外海航道相连的完整港区；`viewerChange`写“罐区有油，装运环节和伸向外海的航道让观众看见交付仍须经过的环节，安全与否保留当前旁白的不确定性”。入口可看货源与装运联系，落点可看油轮与航道，也可持续观察这组关系；单写“从船看到人”或“推近体现风险”没有交付这个观看作用。名称和风险背景可由旁白说明，不用虚构事故证明风险。修改时保持职责、场面与运动一致，不能为了凑运动降低观看任务。这是原字段的构思方法，不增加答卷或锁。

正文事实直接引用当前`Cxxx`；非显然语义或登记来源引用F/R/E，来源资产引用SA；`mustNotInvent`保留本图事实与误读边界。

`purpose`说明本图场面与观看收益，只写本图；完整静态画面由`sceneDescription`交给生图，按[完整场面交付说明](picture-delivery-reference.md)写入。整拍解释留在Director结果，前后图比较只用于作选择。混写时归回各自请求；仍说不出本图看什么，就回到场面选择。动作、状态及关系与机位、布局、景别、明暗、主体比例和路线共同形成。

## 3. 选择Cue边界

只从本Beat的`templateContext.cueOptions`给出的完整选项中选择；联合单分别消费成员输入，不共用第一Beat的选项。A固定使用`start-frame-motion`，B使用现有动作名`dissolve-in`（表示B进入的Cue锚点，具体效果在联合设计中选择，不代表固定叠化）；每个选项已经给出`frameId / action / cueId / edge`。写入`featureResults["cue-sync"].items`时，`target`必须是同一`frameId`画面的`requestId`，其余三项原样来自所选选项。单A只写A绑定，A／B各写一项；不得自造Cue、边界或动作。

程序只枚举技术上有可行时长的切点，不判断这里是否应该换图。作者根据每句旁白当时表达的状态、关系和变化选择边界；场面发生在前后不同时刻时，把各自画面放回实际覆盖的句子，判断是否把结果提前或把变化延后。单A须能与整段旁白共读，不能用一张已经改变的状态，再靠说明文字声称它在句中才发生变化。

选定后只读`motionBudgets.options[]`中与整组绑定相同的预算：

- `transitionCapacity`：该切点容得下的转场上限。结合[作者时长范围](../../../modules/render-video/references/transition-execution-reference.md#时长与呈现)及两图职责选择，容不下全局最长转场不等于不能用双图。
- `readableDurationMs`：扣除该切点最大可行共显窗口后的保守正文阅读时间。联合设计选定效果与时长后重算实际预算，再结合跨Beat转场显露落实清晰观看下限；技术可行不等于已满足该下限。

时窗或表达不足时重选场面、职责或合法切点。所有选项都容不下作者时长范围、且要求A/B时，按原返回路径请Director调整观看单位或Cue安排。

本图职责与注意力变化须能在自己的窗口内成立。跨Beat进出场不计作清楚阅读时间。`motionBudgets.speedRange`提供运动族基准与速度下限，不设统一上限；初始规划按下限计算，不预定速度变化。整个实际窗口持续运动，速度安排服从原motion。`runtimeCameraTravel`已含确定的预进入与退出尾段；`maximumRuntimeCameraTravel`仅作最大假设参考。

规划预算不写入候选。联合设计选定各图速度与B转场后，原测量程序按这些选择及原Cue重算实际预算，不用作者手算；详见[相机时窗合同](../camera/design-method.md#4-时窗合同)。阅读与情绪体会在持续运动中成立；行程不足按[失败修复](../camera/design-method.md#测量不足时修什么)联合调整，不能停镜补空、把关键发现留到窗口之外、自行移动Beat边界或硬加画面凑路线。修改场面、职责、Cue或相机时直接更新同一候选，并复核实际影响。

## 交给联合设计的结果

将画面数、来源与禁造项、职责、三个注意力语义字段及Cue绑定写入同一候选，结合所选预算继续或调整构图与相机。它们不是单独提交物；完整字段形态、测量和交付见[模板根](../AUTHOR.md)。
