# 运镜执行说明

选镜与构图由[运镜方法](design-method.md)及所选方法卡完成。首次写坐标时读取几何、时窗合同；参考上一镜时读取第5节。测量、返回与交付仍归模板根，不增加步骤。

## 3. 几何合同

viewport宽度1只表示显示整张底图，不表示远景；宽度0.75也不自动成为特写。景别来自底图的观察距离、主体分量与实际取景的共同结果。

每个viewport是完整位于成图内的归一化正方形：`x / y / width / height`在0—1内且`width = height`；每个`width / height >= 2/3`，即整条路线最大放大不超过`1.5`。

运行时只移动、缩放同一静态母版的取景框；不改变母版透视、遮挡或清晰度，不提供真实环绕、升降机位、视差或转焦。纵向移动只是沿图像上下取景，不能把俯视变成平视；缩放也不能凭空增加细节。母版景别须适合此尺度范围，不能用一条路线承诺从小物特写跨到宏大全景。

这里的缩放上限、路线形状和下节速度下限是本项目执行约束，不是Ken Burns手法的通用限制。

**取景放多大与放大后是否清楚分开判断。** 同一主体在原图中占画高的比例，除以实际viewport.height，就是完整留在框内时的屏幕占高。例如原图占高30%，在宽高0.75的框中占40%；提高原图分辨率不会改变这个占比。1.5是能力上限，实际幅度仍读取本图测量结果，不要求每镜用满。若所需主体仍太小，按画面方法联合调整机位、主体分量与环境，不能把加像素当作变近。

像素决定这个大小下有多少原始细节：以一张1920×1080的场景叶图为例，宽高0.75的框使用约1440×810像素，再铺满1920×1080输出。这个算例不设置画质门槛，也不代表每图都会模糊；必要动作能否看清须由当前作者看实图。素材实际尺寸与输出规格由原生产、渲染消费者提供，不能把工具预览的尺寸当成每张场景叶图的尺寸。作者不在画面字段里发出升级分辨率或放宽缩放的生产指令。

- 全部运动的相邻非零中心向量不得直接反向折返；程序只阻断这个明确几何错误，不把曲线方向是否符合空间语义冒充为机械结论。
- `traverse`全部viewport等大且相邻点不同。
- `push-in`逐点严格内含并缩小；`pull-out`逐点严格外含并放大。两者都可同时改变框位置与尺度；内含／外含不要求同心或焦点居中，沿途保住当前需要的对象与关系。

## 4. 时窗合同

调用方先选定语义边界，相机组件再读取同一预算。相机值为`scale=1/width, left=-x/width, top=-y/height`；traverse行程是相邻`left/top`距离，push／pull行程是相邻`scale`差。

在选运动与落坐标之前，读取本图所选Cue及规划预算。`motionBudgets.speedRange`提供运动族基准和100%下限，初始行程按下限计算，不预定具体速度变化。推拉基准为scale每秒0.0313945632，平移为归一化left/top每秒0.01883673792；`motion.speedRatio`选择起始比例，运动段不得低于1，不设统一上限。速度仍须让关键对象与关系看清，行程也须在源图内成立。

需要变速时写`speedChanges:[{timeMs,speedRatio},…]`。timeMs从本图实际运镜起点计时，按正整数严格递增；程序从起始速度到各点线性变速，最后一点后保持该速度。全画幅从实际运镜起点到退出尾帧必须持续运动，不提供停留字段。省略`speedChanges`时沿用作者恒速。

例如起始比例1，2秒升到3、4秒回到1，可写`speedRatio:1`、`speedChanges:[{timeMs:2000,speedRatio:3},{timeMs:4000,speedRatio:1}]`，此后以比例1继续运动至实际窗口结束。这里只解释计时，不推荐这组速度或时长。作者依据构图与窗口选择，完整路线须承载整个时窗的行程。

A/B各用自己的运动时钟，含确定的预进入和退出尾段，不能把整Beat时长给两张共用，也不相加叠化重叠时间。规划、设计测量、接镜、实图预览、解说框取景与P4都按同一速度积分求当前框；阅读预算不决定运动截止。画面、路线、速度与转场联合完成后由原入口重算，不手算逐帧坐标或另写运镜脚本。

- `visibleCameraTravel.<运动族>`是当前图进入至正文可见结束的行程，已含A的真实预进入；`runtimeCameraTravel.<运动族>`还计入末图真实退出尾段，包含接到下一段Cue的停顿和固定接出余量，完整作者路线不得短于它。`readableDurationMs`仍只计算正文内扣除实际转场窗口后的阅读时间；
- `maximumRuntimeCameraTravel.<运动族>`包含边界预留并覆盖已经确定的真实段间时间，只提示接镜可能增加的行程，不是每张图必须耗尽的实际窗口；真实接镜与P4使用已经确定的进入／退出帧，下一Beat沿用既有预进入和退出尾帧，原Beat总时长不增加；
- `maximumZoomScaleTravel`是现行几何允许的最大尺度行程，供与`runtimeCameraTravel.zoom`比较；它不是当前路线的可用行程，具体路线仍以测量为准；
- **走不完：**窗口已结束，但还没走到`semanticEndViewport / safeEndViewport`。这是允许的部分路线；当前观看任务在实际扫过范围内成立即可，不为赶终点加速，也不要求路线恰好用尽。
- **路程不够：**窗口尚未结束，可用路线或场景已经到头。此时行程不足，按原入口返回窗口失败事实，由Author修正设计与所需空间；不能由程序在运行中自动减速、停驻、折返或增加无意义尾段填时间；作者须联合调整构图、起止取景、焦点间距、路线和速度安排，必要时换用适合当前观看任务的运动方式，持续运动且不低于速度下限；仍无解则沿原责任返回。设计合理而实图缺空间时，按当前作者的图片入口修正。

作者路线必须让运动类型、方向、最大尺度和画布边界同时成立。组件提供实际末态与扫过范围；窗口内观看任务是否成立，由调用方按[实际窗口判断](../references/picture-review-method.md#当前窗口内的设计成立)判断，程序不以固定路线完成比例代替。组件只返回失败事实；修正范围及上级返回由[模板根](../AUTHOR.md)决定。不得只按数字猜坐标，或为过门无理由换Cue、折返或改运动类型。

路线形成后，调用方把当前`treatment`与已选A／B运动卡点交给登记的模板测量入口；该入口完成上级语义检查后，调用相机组件读取`motion`并复用正式几何与路线真源。

相机组件成功返回当前图的`visibleDurationMs / visibleCameraTravel / visibleEndViewport / visibleRouteViewports / remainingVisibleRouteDistance`，均由所选窗口和作者路线计算，不是推荐坐标。`runtimeDurationMs / runtimeCameraTravel`说明含接镜的实际运动需求；最大假设预留不参与路线长度拦截。失败返回`route-definition / framing-contract / motion-shape / direction-conflict / window-contract / route-contract`分类和具体失败事实；上级准入、语义复核和失败返回由调用方负责。不得直接导入内部运行时或几何函数取得第二套报错。

### 转场观看反馈

原测量每张`target.transitionReading`给出当前入场的同帧取景与呈现事实；没有剧情入场时为`null`。`outgoingTarget`指向本次B的A或当前参考的上一末图，缺失的前图取景为`null`，不推造。`cueOffsetWindowMs`相对当前入场Cue，末边界不包含在窗口内；`samples[].cueOffsetMs`是实际取样时刻，负值在Cue之前。渐进效果样本包含开头、首次正显露、四分点及结尾；闪黑另含黑位边缘。它们帮助还原过程，不替代连续观看或穷尽所有临界帧。

`incomingViewport / outgoingViewport`分别是两张母版的取景，不能直接互比坐标。源图点`(x,y)`映到屏幕归一化位置为`((x-v.x)/v.width, (y-v.y)/v.height)`；落在框外就不在屏幕内。相机沿作者速度安排计时；隐藏采样不表示已经可见。

`exposure`按实际效果分别读取：

| 效果 | 反馈含义 |
|---|---|
| 叠化 | `blendWeights`是渲染器混合两层的权重；不是主体可辨度或面积。两张完整取景都参与混合。 |
| 闪黑 | `opacities`是两层透明度，`blackOnly`表示这一帧两层都为零；不能在黑位假定共显。 |

将对象的边界、姿态接点和屏幕分量放进这些状态，按[共享转场方法](../../../modules/render-video/references/narrative-transitions.md#在原联合设计中落实用法)判断最先能读到什么、之后怎样接住观看任务。原`transitionEntryViewport`和`visibleComposition`仍分别说明入口框与相机沿途构图；只有取景进入并不能证明转场已经露出。首次使用看[联合实操](../examples/joint-reading.md)。

## 5. 前后镜头观感与严格接镜

A只参考同段紧邻上一创作单位的末图，B参考当前候选的A。段首独立起镜，不读取段外相机；普通跨段转场仍按当前语义和入场设计。参考发生在观看骨架已形成、画面与路线尚未定稿时；不额外建立一个设计后接镜步骤。独立创意、观看职责、来源与禁造边界保持，构图、景别、入口和运动方式仍可联合选择。

先用上一镜的焦点文字和空间设计理解观众正在看什么，再结合`transitionHandoff.previousVisibleEndViewport / previousRuntimeEndViewport`了解正文末态与预留尾段末态。跨Beat任务视图的`previousTreatment.cameraState`同时提供`sceneDescription`与上述`transitionHandoff`；结合两者定位所看对象，按本方法把取景变化解释为屏幕变化，不能仅凭`type / semanticEndViewport / attentionPlan`推定交接。同Beat的B依据当前A设计形成接缝，最后用同次联合设计测量返回的A/B实际取景共同复核和修正，不另插入A的提前测量。所需同版本材料已完整保留时沿用，缺失时从当前任务视图、候选或原测量补回，不为打印同一副本重复读取。交接轨迹是稳定相机余量的参考，不代表每种效果都会显示完整余量；联合设计测量按当前`incomingTransition`取样，返回`transitionEntryViewport`和上述`transitionReading`，分别复核入口构图与转场中的联合观看。`semanticEndViewport`可能尚未到达，不能冒充实际末态。取景框是各自母版坐标；不同图片坐标相等不等于屏幕视觉重点相同。上一镜所看对象、画面主次、运动方向和尺度变化只是参考，不能凭数值确定眼睛落点，也不能虚构尚未生成图片的实际构图精度。

当前任务允许时，可使重要对象在相近屏幕区域接住注意力、顺势保持运动感觉，或用合理的景别变化建立新关系；叙事转折也可以独立起镜。不得强制推拉轮换、方向交替或每镜匹配，不为了接镜补造对象、倒置当前观看顺序或要求上一镜返工。选择落实在当前已有`sceneDescription / motion`中，不另写评分或衔接报告。没有简单合适的方案就保留当前独立设计。

`cameraRelation`声明实际依赖：

- `first`：本段没有前画面，段首独立起镜；不表示它必须是全片首拍。
- `reset`：没有采纳上一相机参考，当前独立起镜；可以读过参考后作此选择。
- `visual-match`：确实参考上一镜观感形成当前构图或运镜，可以换场景、换运动类型；不声明同一物理空间或精确几何对齐。Engine记录真实上一镜依赖，程序不代替专业观感判断。
- `continue`：同一物理现场、同运动族顺势继续。
- `motivated-reverse`：同一物理关系中由可见对抗、回看或空间动作驱动的同运动族反向。

后两类严格接镜按所选效果核验第一组正共显帧；无连续共显时，Beat内比较前图实际末态与后图入口及各自可见运动方向；跨Beat比较既有相机余量内切点处的轨迹。不伪称黑场存在共显。入口容差等于当前图选定速度的一帧行程，前后方向证据分别按各图选定速度核对；样本必须有真实运动；联合设计测量与实图/P4取样同源。叙事对照、换地点或运动类型不同不能冒充`motivated-reverse`。这些专用几何门只消费后两类，不约束`visual-match`；全部类型仍服从完整路线、画幅、最大尺度、真实时窗与安全尾段的同一测量。
