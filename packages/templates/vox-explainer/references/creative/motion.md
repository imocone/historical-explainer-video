# 运动编排与实现

设计前读完“创作方法”；“实现示例”在制作需要相应手艺时读取。

## 创作方法

### 按观看任务组织运动

从整段最值得亲眼看见的作用、差别或处境开始，让同一主体或已经形成的结果接着带出下一次观察。例如讲物资集中，先认出分散的来源，跟住一件物资看它抵达，再展开看后续怎样积累，最后比较留下的差距；讲范围受限，就让行动在真实限制处改变。字幕边界提供发声时间，不决定换页或切镜；按观看主线把这些事接成一段。

先在原scene摆出最能说明问题的画面，选清楚呈现差别、联系或作用的方向和距离，再向前接必要参照，向后接下一次观察。需要变化时，先让关键状态在画面上成立，再连接路径、姿态与运动，分别安排主体、镜头和回应。静态职责与比较用对应关系、共同基准和发现顺序展开，不补造手续或历史因果。

图解也可以有主动作：把一个正在绘制、测量、装配或经历条件的对象放到前景，让过程带出图形与结论。[Lemo的图表作品](https://github.com/lemomo-ai/lemo-opuscar/blob/main/styles/dataviz/demo/film.js)让笔沿数据前进，遇到超出原尺度的点时惊停、翻转，再改尺度；镜头追随笔和当前变化，随后拉开才给出全体比较。它的作用来自对象、图形与取景的配合，不是给静图持续加虚线。当前题目按真实含义取用演示动作，不套笔、角色性格、BPM或镜头次数。

需要用变化展开含义时，可以从下面选择相应操作，再围绕它安排主体和取景。纸、数字或符号同样可以参与；图形的运动呈现关系，事实由对应的单位、归属与结果保全：

| 要让观众亲眼确认什么 | 怎样做成连续动作 |
|---|---|
| 分散的量怎样形成集中结果 | 各单位从可辨的原位错时出发，汇聚到同一处；后一批承接已留下的部分，镜头先跟一件看去向，再展开看积累。 |
| 一个局部怎样改变整体判断 | 从整体中带出同一个对象，近处展开关键差别；变化落定后让它回到整体，原参照因此得到新结果。 |
| 同一事实换表示后显出什么 | 保留单位对应，将当前形象展开、排列、堆叠或转形成下一种表示；位置、形状与尺度分别排时，让观众认出是原来的东西。 |
| 某个条件怎样使结果不同 | 先让对象经历已知条件，再在作用处改变可见状态；比较的另一条件保留同一对象或尺度，结果形成后并置确认。 |

粮食补给例的过桥补缺与余粮入库、快递例的接近落点与离开原位，展示了这些操作。学手艺时沿实际时间看完一件事，再查看同一段源码怎样分配主体、镜头和回应的进度；一张终态只给构图，不能教出准备、加速、作用和停驻。用本题的对象在原粗排中把选定操作做出，随后向前接准备、向后接新观察，整章从这段实际经验继续展开。

### 主体动作与取景一起排

先在实际观看尺寸摆出本次观察的画面，选能看见作用的方向、远近和边界，再排主体怎样动。需要认出路线与去向，就保住起点、路径和落点；要看接触、开合或内部变化，就把相应作用面朝向镜头并带近；比较数量或尺度时，则让对象共享可辨的参照。场景里有这个部件，不代表当前角度看得见它；先用画面确定观众看哪里、能看见什么，再决定移动还是停驻。

取景和主体各有时间。可以先切近、停住，再让机构完成一次清楚的作用；也可以让运动把注意带到画面边缘，下一镜沿同一对象或去向接住，结果形成后再拉开比较。先摆交接两端的实际画面，按对象、运动方向或空间锚点接续，避免关键作用正好被移动的镜头或新字盖过。主体的大小、路线和背景反差共同取得注意；接收者、活动件与环境给出真实响应，镜头也可以保持不动，让主体穿过画面取得速度。

[Lemo拆解片的实际时序](https://github.com/lemomo-ai/lemo-opuscar/blob/main/styles/teardown/demo/src/timeline.js)把整机分层、进入夹层、观察部件、退出合拢分别配以取景；[相机实现](https://github.com/lemomo-ai/lemo-opuscar/blob/main/styles/teardown/demo/src/main.js)分别控制机位、注视点与视角，局部停驻时保持观察位置。借用的是“先露出要看的结构，再到能看见它的地方”，不套产品题材、连续运镜、BPM或镜头数量。[3Blue1Brown的圆锥展开源码](https://github.com/3b1b/videos/blob/306a1346a356c7a7b097875ceb51c5cd67d0a56c/_2025/guest_videos/euclid.py)也随表面与线条的展开改变观察方向，最终正对平面；机位变化因此显露新的关系。

已有关系图可以保留为世界，观看窗口按作用处重新取景。共同参照在建立关系、比较与返回时取得完整范围；观察局部时暂时不需要的部分可以离屏，事实状态继续存在。粮食补给例跟车时裁去暂不需要的场面，装车、在途与卸粮仍在同一场景中接续，随后退回总览。二维平移、裁切与放大只能改变已有画面的取景，不能露出没有画出的背面或内部；本题需要时改画侧面、剖面，或沿原能力用真实三维视图，不以放大全图代替换观察位置。

二维裁切与取景按需读取[实现示例](#二维取景)，Three.js与数据地图使用自身相机；都按当前观察目的安排。需要读数比较时保住共同尺度，标签随对象保持归属。持续漂移和呼吸缩放没有新用途时就停下。

### 运动与进出场

先把主动作做成一段表演，再调缓动曲线。把准备、真正作用和结果放在相同的最终画宽下，设计观众实际能感到的轮廓、重心、空间占用或状态反差：主体怎样取得速度，作用怎样改变它或周围对象，回应后留下什么供下一次观察。动作在世界里移动了多少，与它在屏幕上取得多大分量是两件事。用当前景别、必要行程、形态与前后构图共同形成力度；具象主体的支点、姿态和材质响应参与表演，抽象主体则用展开、挤压、堆积、翻转或重组承载变化。精细的描边、短促发光和轻微位移可以辅助已经成立的主动作，不能替它承担全部变化。

小触发可以接出有分量的后果。先把作用处带近，让关键一下可见，再让它实际改变的对象展开、转形或取得新的构图位置；已建立的身份和条件跟着这次变化保持。看[快递示范](../../examples/parcel/README.md#镜头怎样参与这18秒)：印章的实际下行不长，镜头却先到印面附近停住，接触、印迹和抬走先后发生，随后展开才看见货物仍未动。借用的是小作用怎样接到新的观看，不是把所有主体都放大、远移或弹跳；本题的后果按真实含义选择。

先选口播中值得强调的变化，决定发声贴的是起势、真正作用还是落定，再从这个落点倒排准备和行程，向后安排回应与阅读。讲述窗口可以很长，主动作仍可短促完成；余下时间用于观察已经形成的结果，或接向下一层发现。句内精卡沿[实测短语接口](../tools/cues.md#实测短语与句内卡点)，`advance-explainer`只提供时间，不替作者形成动作。

力度来自速度与状态的对比：先建立可辨的主体和去向，启动时取得速度，在作用处明确接触或改变，随后由对象的材质、重量和用途决定收势。轻纸片与重机械用不同的加速和响应；不是每件东西都反向蓄力或弹跳。进场可用`power3.out`先快后缓取得位置，退出可用`power3.in`加速让位，镜头或大组重排可用`power2.inOut`协调启停；这说明缓动的角色，不规定整片同一种曲线。

强调一个关键反差时，可以让较长的准备接很短的揭示，再停住看结果；不要把讲述这件事的整句时长平均分给位移。先靠近那一个单位，主体在准备时稍留余地，作用时迅速取得新状态，接收处或字组稍后回应，其余内容暂缓。画面已经稳定后再展开比较，下一处熟悉的重复可以更快通过。这样形成准备与爆发、运动与停驻、近处与全体的对比，安静时段也有前面动作留下的依据。具体动作速度从实际过程试出，事实发生条件仍与视觉收势分别求值。

重复作用可错开出发并让过程重叠，使观众追得见来源，也看见结果逐渐形成；已经熟悉的重复可以压紧，新的差别再放开给观察。主动作、接收处的回应、结果短字不必同起同落。具体错时与附着见[作用与回应示例](#作用与回应的错时)。

### 让前一个结果继续带出下一次观察

需要推敲跨画面承接时，可看[粮食补给的动作与结果](../../examples/supply-mg/README.md#动作怎样留下结果)：桥从原场景移入数量图，旧文字退出，新标签与到达粮袋随后进入；余粮入库时，前一天留下的两份继续承接第二天新增的两份。主体、环境、文字和读数各自排时，已经形成的状态支持下一次观察。

先沿原声安排整章的起伏：哪里建立观看方法，哪里持续展开，哪里揭示新的关系，哪里让结果留下感受。认识与兴趣可以由现象、处境、疑问或反差引出，按本题组织。景别、疏密、运动强弱和声音共同形成变化；连续几段都用同一景别、同一速度时，回看是否有值得换一种观看的内容，不为变化而换镜。

再把时间分给观众正在做的事：认出新对象、读懂表示、追踪作用、比较差别或体会结果。第一次对应展开看，掌握后的重复收紧，新条件或新表示再留出辨认。文字阅读与关键动作争夺注意时，调换先后或让其中一项保持稳定。时间不足，先压缩重复、缩短寻找距离或改用更直接的表示，保留必要内容与新认识。

切镜同时设计前镜的结束与后镜的第一眼。前镜把注意带向哪里、留下什么期待，后镜就用对象、方向、位置或声音接住；需要明确转折时，也可有意改变这些关系。先摆交接两端，再接运动。观众已取得所需认识，便可进入下一观察；尚在比较或等待关键作用，就保留必要时间。静态比较、停留与直接切换都可成立，不设固定镜长或切镜频率。

最后用原速过程调动作内部的准备、作用、回应与收势，具体手艺见[运动与进出场](#运动与进出场)。结果刚出现就离开，延长辨认或提前建立参照；同一终态停得过久，收束重复或展开下一项内容；动作很多却没有力度，拉开准备与揭示、主体与回应的差别。卡点服从语义与观看，音乐节拍只在需要时参与。正常播放校准剪辑点的做法可参考[Murch访谈](https://theasc.com/post/the-film-book/walter-murch-2-real-time-cuts-image-editing/)。

### 状态、接触与同一时钟

数量何时进入总量、对象何时到达并改变归属、条件何时生效，按本题真实完成条件求值。让相关形体、路径、数值和反馈读取同一状态；跨镜接续已经发生的增减、去向和结果，回看或假设读相应状态，返回后接回实际进展。首次用周期运动解释变化时选对与发声对应的相位，完成该次观察再接持续循环；慢示、停驻与恢复不暗示设备停机或事实逆转。

接触时校准真正作用的边缘或关节及其反馈；转身时让体积、可见面和遮挡一起改变。重要动作过快会跳过作用，过慢会失去力度或被误认成犹豫，按实际画面调整路径、时长与停驻。主动作需要注意时，次动作和新文字错开，背景降低分量；把时间用于找到所指、看懂变化及确认结果，不能把盯着截图慢慢读懂当成原速观看成立。

以上均写入原scene、moments、Cue、timeline与onFrame，由当前时间确定完整状态；可沿[scene.events](../tools/cues.md#画面动作时刻)声明共用动作时刻，不建第二事件表或时间真源。卡点、事实发生与音乐节拍分别判断，声音Feature响应已成画面，不代替视觉编排。具体接口见[画布与动画](../delivery.md#画布与动画)。

## 实现示例

### 二维取景

普通二维先分清世界、观看窗口和屏幕参照。世界中的对象保留原坐标，外层窗口裁掉当前不看的部分，内层相机移动世界；公共字幕仍由原字幕层处理。当前确需稳定可读的尺度或身份可独立放在屏幕层；提问、关键词和结果字组则与主体一起设计大小、位置和进退，也可成为画面中的对象。窗口与文字空间按这一镜安排，不从开头固定一条标题栏再把所有动作塞到下面。下面的结构只说明裁切与相机的嵌套，具体窗口按本题画幅、safeArea和当前构图安排：

```html
<defs><clipPath id="shot-window"><rect x="120" y="240" width="1680" height="720"/></clipPath></defs>
<g clip-path="url(#shot-window)"><g id="camera"><!-- 本题场景对象 --></g></g>
<g id="reading"><!-- 当前确需独立于镜头的屏幕参照 --></g>
```

再按要看的作用范围求取景，而不是先猜一个放大倍数。范围包含本次必须同时看清的对象、接触处与必要行程；先摆出它在正常尺寸和手机整幅中的实际画面，再连接镜头。以下沿原timeline与onFrame落实，替代该组其它变换，避免两个实现抢写同一元素：

```js
const view = {x:120, y:240, width:1680, height:720};
const frame = b => ({x:b.x+b.width/2, y:b.y+b.height/2,
  s:Math.min(view.width/b.width, view.height/b.height)});
const camera = frame({x:100,y:230,width:1720,height:740});
timeline.to(camera,
  {...frame({x:505,y:405,width:360,height:250}), duration:.5, ease:'power2.inOut'}, cue('M001')+.9);
onFrame(() => select('#camera').setAttribute('transform',
  `translate(${view.x+view.width/2} ${view.y+view.height/2}) scale(${camera.s}) translate(${-camera.x} ${-camera.y})`));
```

这些范围取自[批准与送达的可运行示范](../../examples/parcel/README.md)：先建立文书与箱货，接近印章落点，接触与印迹形成后返回；箱货出发时跟随它，再提前到接收处停住，最后展开比较。`frame`按所选范围适配窗口，原scene的`cameraKeys`把镜头与印章、货物各自的时间接起来；相机落定后保留位置，直到下一次观察。实际题目重选范围与时间，范围仍包住整张图时不会形成近景，不能直接套本例坐标或镜头顺序。

按对象范围求取景可参照[Manim的auto_zoom实际实现](https://github.com/ManimCommunity/manim/blob/16ea443e2a5f1d79db0a721161411ce916d6e733/manim/camera/moving_camera.py)；[Motion Canvas相机示例](https://github.com/motion-canvas/motion-canvas/blob/7b91435c301d530351dcf5ebb91dd139c002e405/packages/docs/docs/getting-started/camera.mdx)同样把对象状态与观看窗口分开。此处二维适配不提供三维透视；Three.js与数据地图使用自身相机，按同样的观察目的安排。需要读数比较时保住共同尺度，标签随对象保持归属，屏幕字号按观看距离调整。持续漂移和呼吸缩放没有新的观察用途时就停下。

### 作用与回应的错时

以“物件落入可动托盘”为例，先在markup中对齐物件终点与托盘，把物件和托盘放在同一`#landing`组内，再将该组放入取景组：

```js
const hit = cue('M002'); // 本例贴Cue边界；句内落点取本单实测偏移
timeline.to(select('#view'),
  {x:-180, scale:1.25, duration:.6, ease:'power2.inOut'}, hit-.9);
timeline.to(select('#piece'),
  {x:300, duration:.32, ease:'power3.in'}, hit-.32);
timeline.to(select('#landing'), {y:8, duration:.08, ease:'power2.out'}, hit);
timeline.to(select('#landing'), {y:0, duration:.16, ease:'power2.out'}, hit+.08);
timeline.fromTo(select('#result'), {opacity:0},
  {opacity:1, duration:.18}, hit+.14);
```

这里的数值只解释一次编排：取景先完成，物件较快抵达，承托组随后带着已接触的物件一同回应，读数再接过注意。换对象就按真实结构改姿态、路径和反馈，静止地面不跟着跳；归属与读数按真正完成条件改变，不因视觉收势反复增减。用onFrame时同样为这些角色分别求进度和保持态，再由同一时间重建完整画面。

### 动画实现参考

声音与运动的交接还可参考[Manim Voiceover的发声标记实例](https://github.com/ManimCommunity/manim-voiceover/blob/main/examples/bookmark-example.py)：不仅定位某个词，还用到下一标记的时窗安排当前动作。它在缺少细边界时使用的线性插值不作为本模板实测依据。[Motion Canvas时间事件](https://github.com/motion-canvas/motion-canvas/blob/main/packages/docs/docs/getting-started/time-events.mdx)把关键事件与动作时长共同调试；在此仍使用原Cue、实测偏移和同一timeline。[Remotion字幕示例](https://github.com/remotion-dev/template-tiktok/blob/main/src/CaptionedVideo/Page.tsx)按词的真实时间窗口求当前强调状态，可借到本题确需的重点字组，不套其整套花字或英文空格分页；文字的语义选择、力度与阅读交接仍由作者决定。

[官方示例](https://github.com/motion-canvas/examples)展示了组织动画的实现方式。当前作品确定了要表达的关系与画面后，可按需取用这些思路，把已设计的对象对应与变化落实到动画结构：

| 制作思路 | 示例中的做法 | 在本模板怎样实现 |
|---|---|---|
| 同一对象转换表示 | [光照合成](https://github.com/motion-canvas/examples/blob/master/examples/deferred-lighting/src/scenes/lightBasics.tsx)将颜色层、光照层展开成运算关系，再合成同一图像 | 保留对象的形象与对应，将它拆开、重组、放大或转成图解，使变化本身解释关系 |
| 共用状态保持呈现联动 | [视差组件](https://github.com/motion-canvas/examples/blob/master/examples/smooth-parallax/src/components/Parallax.tsx)由同一相机位置和层级比例控制多层图片；[演示场景](https://github.com/motion-canvas/examples/blob/master/examples/smooth-parallax/src/scenes/layers.tsx)把层的位置与比例关系展开 | 从本题数据或已定演绎状态求出主体、局部与读数，使同一结果的不同表现保持一致，再由原onFrame按当前时间呈现 |
| 按对象关系分组 | [层级](https://motioncanvas.io/docs/hierarchy/)让子物件继承整体运动，同时保留自身变化 | 外层组织整体位置与镜头，内层组织活动件；转换视图时保持锚点、身份与前后姿态连续 |
| 按理解过程组织动作 | [时序](https://motioncanvas.io/docs/flow/)提供并行、顺序、延迟和错时，[时间事件](https://motioncanvas.io/docs/time-events/)将关键动作联系到声音 | 沿真实Cue安排动作的重叠、先后、停顿与缓急，让作用、反馈和阅读各有合适时机 |

这些思路沿现有GSAP、timeline和onFrame落实；当前时间直接确定完整状态，跳帧和倒放保持一致。Motion Canvas的生成器流程在此转换为原Cue上的时间关系，对象与状态写入原scene，预演与P4继续消费同一交付。具体造型、布局、速度和制作顺序由本题决定。
