# 一次批准与一次送达

成品视频不随仓库分发。本例保留教学源码、图件和时序；需要动态预览时，沿本例已有构建入口在本机生成。配套旁白仅为同长度静音占位，构建程序优先读取本机保留的原声。已有完整原片保留在本机的local-media/private-assets/对应路径。

本项目旧快递试作的过程与状态示范：先让批准改变文书，再展开货物运输与接收，最后比较批准和送达。采用现行scene、图片与Cue接口，情境为虚构。

18秒成片（仅本机保留）、[原素材](assets/parcel.png)和[完整scene代码](scene.mjs)可以对照查看。

这是无旁白、无字幕的画面示范；实际任务按本单原声时窗与字幕预留区重新构图。旧素材只供对照分件与动作，当前画法仍以本包art和本件所选参考为准。

| 片中发生什么 | 素材与代码怎样配合 |
|---|---|
| 印章落在文书上，随后抬走；箱货仍在原处。 | 文书、印章和箱货从同一张素材图分别裁取。`stampKeys`让印章先接触、再离开；`approved`只在接触后改变印迹，货物位置不变。 |
| 货物出发，经过通路，到达接收桌。 | `cargoKeys`连续改变同一个箱货的位置、尺度和姿态；路径随货物退去。文书仍留在原处，批准与运输没有混成一个状态。 |
| 货物落定，接收处出现勾和“已送达”。 | `arrive`同时决定货物末态与接收反馈。“已批准”和“已送达”最后共同可见，动作留下的结果完成比较。 |

## 镜头怎样参与这18秒

`scene.mjs`的`frame`先用动作范围适配观看窗口，`cameraKeys`再排观察时刻。窗口由固定外层`shot-window`裁切，相机只变换内层世界；标题等阅读层独立，文书和货物离屏时仍保留原状态。

| 时段 | 实际观看与源码 |
|---|---|
| 约0—3.3秒 | 先认出文书和箱货，镜头在印章落下前到达印迹附近并停住。`sealView`把接触处作为取景范围；印章抬走后看见批准，再展开确认箱货仍在原处。 |
| 约4.5—8.5秒 | `cargoView`先接近将要出发的箱货，`travelView`接着它的行程移动；背景的文书和通路经过画面，位移有参照，镜头和货物没有共用一条位置插值。 |
| 约8.5—11.9秒 | `landingView`先到接收桌附近，停住让货物抵达、落定，接收反馈再出现。近景也用于核对实际承托与遮挡；本次将落点移开桌铃，避免物件相交。 |
| 约12—18秒 | 展开已经改变的全场，批准文书与送达货物共同支撑结尾比较。镜头结束自己的工作，保留结果供阅读。 |

这份实作采用与原示范相同的素材、18秒时长及批准、运输、送达关系，展示的是按作用范围取景及镜头与动作分开排时。相机算法参考[Manim的对象范围取景](https://github.com/ManimCommunity/manim/blob/16ea443e2a5f1d79db0a721161411ce916d6e733/manim/camera/moving_camera.py)思路，示例代码由本项目编写；不复制其实现或引入新依赖。

可迁移的是围绕本题，把必要动作、作用对象与结果连起来，让最后的解释有可见依据；分件取用与共用进度服务这段演绎。盖章、运输、接收桌、横向路线和三个转折属于本例，当前作品的讲法与布局由本题决定。

`scene.mjs`中的`createExample()`给出完整画面和动画。示例Cue为`M001=0 / M002=5.1 / M003=9.45`秒，只用于复现这18秒；实际任务仍通过本单cue-options与cue-sync绑定真实声音。`AR001`对应原图1536×1024，代码中的各个`viewBox`只裁取所需图件，SVG通路、印迹和接收勾辅助这些实图。

维护时可运行`node packages/templates/vox-explainer/examples/parcel/build.mjs <临时项目目录>`，再沿项目原HyperFrames渲染入口导出。构建器只复现这份示范，不参与生产或生成当前作品。素材沿用本项目2026-10-17留存快递试作，未复制外部仓库代码或调用生图。
