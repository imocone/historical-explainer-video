# 变更理由档案

开发过程档案只留本机，不进入开源Git。本目录公开保留本说明；缺少本机档案不影响安装或生产，执行依据始终是现行清单、合同和方法。

本目录保存值得长期保留的设计取舍与故障经验，解释当时为什么这样改。建档条件、写入时机、历史查阅范围和保留边界由[AGENTS.md的变更理由档案](../../AGENTS.md#变更理由档案)唯一规定；本文件只承载操作方法，在实际建档、更新或检索档案时读取，不扩大范围或授权。

## 按范围检索

先按AGENTS规定的日期范围筛文件名，再在范围内按具体路径、字段、函数或故障特征搜索正文；先看命中片段，再按需读最相关的一两份全文，信息足够即停止。不默认读取最近若干份，也不递归追读引用。

## 建档写法

文件名使用`YYYY-MM-DD-<scope>-<slug>.md`。日期表示本次记录建立的日期；不为进入查阅范围重命名旧记录。同日独立决定用具体slug区分。

内容围绕四件事写，简单事情用几段话即可，无须逐栏填模板：

- 为什么改：实际问题和必要证据。
- 决定与理由：采用什么，重要取舍是什么，不复制现行规则全文。
- 影响谁：责任方、直接消费者和预计影响，完成后补实际影响。
- 验证边界：计划如何核对，完成后实际证明了什么、仍有哪些缺口。

## 连续更新与替代

同一目标尚未完成的调试、复审与修正更新同一份；已完成决定后来改变时另记，不改写旧历史，也不因属于同一模块而合并独立决定。

存在替代关系时引用对应旧决定并说明替代部分；不为补引用额外扩大历史查阅范围。不记录施工流水或无关验证。旧记录保留当时事实，当前行为以现行规则和真实消费者为准。
