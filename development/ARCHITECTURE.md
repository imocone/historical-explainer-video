## 一、施工图职责

本文件是项目唯一现行施工图，只保存系统边界、正式身份、唯一位置、责任方、消费者、正式真源、公共关系、失效归属和外部副作用边界。

- `AGENTS.md`负责读取路由、架构变化门、最小验证、Git现场和授权硬门。
- `README.md`只提供公共运行入口；`director/SKILL.md`只提供剧集生产控制方法。
- `development/decisions/`保存有长期价值的设计取舍与故障经验；建档条件和按需查阅范围统一由`AGENTS.md`规定，不是现行合同或第二施工图。
- 精确节点顺序以`workflow/*.yaml`为真源；包身份和资源角色以各包`package.yaml`为真源；字段与机械接纳以Schema、Validator和真实消费者为真源。
- `development/CHANGELOG.md`只是本机历史档案，不随开源分发，也不是现行规则。

本图不复制包内算法、数值阈值、提示词、CLI教程、测试数字或版本史。若本图与机器真源冲突，暂停依赖该冲突的写入或外部动作并核实修正，不能自行挑一份继续；不依赖该冲突的已授权调查与方案准备按[共同停止边界](ai-responsibility/README.md#共同停止边界)继续。

## 二、系统边界

节目委托不承载发布账号；账号配置与实际发布由仓库外个人Skill拥有。项目仅由Codex作为主代理和原生子代理执行；图片统一使用Codex原生imagegen，不提供客户端识别或图片API提交。已有合格图片、来源与真实调用记录保留；历史API记录只供原结果导入和来源核验，未知对象不切服务重投。P1原AGY作者、NotebookLM、配音及按需剧情视频工具保持各自职责。


P4默认只制作片头并最终压片。剧情视频由用户明确要求才启用；System Control在本集`制作/p4/video-settings.yaml`保存该明确选择，未设置视为关闭。`next --stage p4 --video on/off`传递用户已有选择，明确执行video节点或视频修订同样表示启用；不会依据题材或已有素材自行启用。关闭时不派video作者、不执行video-assets、不生成空的作者视频方案；压片直接消费正文与片头。启用后仍走原video → video-assets交付、首次付费及未知对象恢复。开关不删除原方案、候选、远端记录或有效素材；P4最后压片不变。


开源版的制作终点是P4交付`final.mp4`；不注册P5阶段、发布Workflow节点或公开发布命令。片头与按需剧情视频创作归P4，保留原作者分工和video-assets交接，render-video在同一阶段最后执行。P0—P3的方法、责任与顺序保持。P1文案、双封面与最终MP4可交给仓库外的个人video-publish Skill；该Skill只负责发布，不压片，不进入开源分发。

System Control支持仓库根`local-media/private-assets/`内的本机媒体原件。原责任方读取该本机原件或公开许可明确的资源，并如实交付当前实际文件、字体、来源和摘要；本机原件不成为正式随仓资源，不进入Git或公开历史。公开目录不包含成品或示例视频，本机保留完整版本。公开制作不依赖个人文件才能启动或完成。

### 系统范围与职责

项目把节目委托依次生产为节目策划、单集任务、正式口播、音频字幕、分镜、素材、成片和发布交付。先确定观众必须理解什么，再决定表达、视觉载体和技术。

- 代码仓保存系统控制、责任包、合同、公共命令和测试。
- 真实节目位于仓库外的显式节目工作区；生产命令必须显式提供工作区。
- 输入存在不等于生产授权。阶段授权、付费和发布边界见第七节。
- 人工智能负责开放创作；确定性程序负责顺序、装配、合同、接纳、失效、文件安全和技术验收。

项目顶层对象只有System Control（系统控制）和Formal Responsibility Package（正式责任包）。System Control拥有本施工图、Workflow、阶段和生产对象身份、Engine、公共命令、系统级合同、装配解析、原子写入、候选接纳、提交恢复、来源权利和视频规格。`development/ai-responsibility/README.md`是项目内人工智能责任包维护的唯一治理入口。

Workflow拥有完整依赖关系；Stage是可独立运行和停止的范围；Node是一次模块调用位置。它们都不是责任包。所有视频消费者共同读取`packages/video-spec.mjs`；不存在第二套预览或成片规格。

项目新增、维护、修正和审计均由AGENTS入口路由到现有治理入口的责任分工判断；方法唯一归`development/ai-responsibility/README.md`及其内部能力标准，纯确定性变更只读取适用的分工原则，不因此进入全部人工智能包治理。

### 运行入口与资源读取

System Control的`packages/runtime-config.mjs`统一读取仓库根本机`.env`与进程环境，供现有配音、图片、音效、资料工具和视频程序取得运行位置及用户配置；进程环境优先。`.env.example`提供可公开的配置说明，本机`.env`不进入Git、工作单或生产摘要。节目选择仍归原节目配置，技术与创作合同仍归原责任包。配音程序把本次实际音色合入原请求和恢复身份，不因凭据或工具路径变化重做已交付成果。

System Control的`scripts/setup.mjs`由`npm run setup`安装本仓库Node和Python依赖并准备HyperFrames浏览器；`--check`只检查本地环境。首次安装以macOS为支持范围，不登录账号、不调用生成或发布服务，也不成为每次生产的前置步骤。

System Control的`packages/image-provenance.mjs`只读核对已成图片的真实来源，不调用生成服务。正文Template继续拥有画面与镜头，produce-covers继续拥有完整双封面交付；Codex沿现有图片入口取得原参数、原生生图并导入，不增加生产节点或服务选择。

`engine/runtime.mjs`是CLI与Studio的公开调用入口；`engine/runtime/`是System Control的内部实现，分别拥有模型与包装载、合同校验、成果依赖、任务构造、Workflow状态、命令和各阶段返工。状态解析读取独立返工合同；命令协调返工执行与当前任务执行，内部实现不反向依赖公开入口。P4状态通过内部素材交接组件读取所需作者成果中的实图、视频交付和文件，不回查制作过程。原子写入和安全路径由既有公共工具拥有。Schema组件只复用与当前文件内容一致的编译结果，不缓存业务事实、授权或远端状态。

阶段模型在单次命令内复用程序、规则与合同的资源读取，下一条命令重新建立读取范围；业务成果、授权与远端状态仍读取当前现场。任务构造与交付读取分开，状态查询按已有成果和明确修订请求确定进度，只有待执行的节点形成任务。P3模型视图保留唯一业务输入，通过正式来源交付规则与输出合同。Video状态拥有流程推进，既有故事板校验组件拥有新Author候选的交付检查；图片修订由原作者完成。

阶段节点、模块声明和控制器与执行资源分开读取。完整阶段队列与中断收尾仍由原System Control消费者处理，实际压片和Studio取得完整渲染资源。

所有节点只读取本节点实际需要的上游交付；到位即可开始，不递归复验上游阶段、不以旧工作单、提示词、规则版本、生产回执或历史哈希作为准入条件。生产者在交付前对自己的新结果负责。下游在实际读取或执行时遇到缺失、不可解析或无法消费的数据，只报告对应对象，不据此扩大成整阶段重做。状态查询只反映交付、当前请求与当前执行事实。

### 连续执行、返工与恢复

System Control在现有Workflow和节点上提供阶段重置、指定范围连续执行、暂停恢复与项目进度查询；不增加工作流、责任包或外部调度平台。`engine/runtime/stage-control.mjs`承接公共控制，阶段重跑使用当前阶段`_work/restart.yaml`保存本次身份，成果沿既有producer记录证明本次交付；单集`制作/run.yaml`只保存用户选择的执行范围、当前位置与暂停意图，不复制业务队列。

重跑保持上游和旧正式成果，当前阶段每个节点必须交付本次结果；只有实际业务变化通知真实下游。付费与发布仍由原模块管理，未知远端先恢复，已发布回执不重置。连续执行由Director完成原阶段收尾后推进至指定终点。局部修订只限制真正读取受影响内容的消费者。保留有效恢复事务。

返工沿明确修改对象及实际受影响内容处理；参考、相邻、同组和摘要变化本身不产生返工义务。未改成果不重签、不重创作、不重新接纳；同一修订在获准阶段内连续完成。结果已落地而收口中断时，恢复同一次提交，不再调用作者；远端操作恢复与写入互斥由实际执行模块内部负责。

程序模块拥有正式成果写入；System Control 的普通执行与返工准备共用同一执行和收口实现，以正式文件读取交付。执行中断后，已写出同次成果的节点只补完真实下游待办和原请求清理；尚未交付的远端操作仍由原模块恢复。P0实际片头或视觉包选择变化通知相应消费者，单纯版本或资源摘要变化不扩大返工。

工作单与候选的恢复共用现有接纳事务，覆盖普通阶段及P1创作与封面、P3各段作者、P4各节点工作目录；恢复完成后移除已消费的停放记录。P1收尾保留仍被停放工作引用的完整材料。阶段重置按原文归档本地工作记录及停放工作，损坏的本地草稿不阻止新一轮，原远端身份与回执仍保留。

P1联合交付中断时，读取其交付的P2与P4先由原接纳事务补完保存；status只报告待恢复，next和accept恢复原提交，不调用作者或重做成果。

## 三、正式责任包

| 类型 | 唯一职责 | 唯一清单位置 |
|---|---|---|
| Module | 节点调用的可复用责任实现 | `packages/modules/<id>/package.yaml` |
| Template | 一个内容单元的P3或P4画面／镜头设计、标准素材合同、专业落地方法和P4呈现方法 | `packages/templates/<id>/package.yaml` |
| Feature | 为模板或模块提供可复用的跨模板能力 | `packages/features/<id>/package.yaml` |
| Visual | 除vox-explainer外的正片及封面画风、场景颜色、字体、绘制及渲染外观和固定画风参考；节目字幕字体与配色 | `visuals/<id>/visual-package.json` |
| Cover | 可替换的封面皮肤：文字材质与配色、字号层级、图文比例、横竖排版及配图的视觉强弱；本集可见文字及每集图像内容由P1作者拥有，画法由Visual拥有 | `packages/covers/<id>/package.yaml` |

当前共有30个正式责任包：15个模块、8个模板、3个功能、3个视觉包和1个封面包。

```text
modules:
  author-beat, author-bookend, author-documentary-narration, author-narration, author-subtitles, author-video, direct-episode, finalize-narration, plan-historical-documentary, plan-program, produce-covers, produce-video-assets, render-video, synthesize-narration, understand-episode

templates:
  fullframe-narrative, vox-explainer
  episode-opener, documentary-opener, crossfire-opener, opposed-opener, glass-opener, cinematic-video

features:
  cue-sync, background-music, sound-effects

visuals:
  meiji-state-machine, song-celadon-guoman
  modern-editorial

covers:
  type-first-editorial
```

任何正式对象必须有唯一身份、位置、责任方、消费者、失效和验证归属。包内资源和包内组件继承所属正式包的责任，不取得正式包身份；共享资源必须有真正所有者。人工智能包以清单登记的`SKILL.md`或`AUTHOR.md`及其按需资源为唯一内部执行合同；确定性硬门仍由工作单、Schema、Validator和消费者负责。动作、方法、确定性资源、包内组件和正式责任包的建立与维护边界只见`development/ai-responsibility/internal-capability-standard.md`。

已经完成专业审定、需要防止普通维护顺手改写的方法、入口、正式示例、结果合同、确定性硬门或包内组件，由System Control列入`development/ai-responsibility-protection.json`；该文件是受保护路径的唯一机器真源。现行保护覆盖P3从Understanding、Director到正文与片头Author的成熟责任包，所选正文与片头Template、必需Feature、直接结果合同、P3任务视图运行时，以及能够改写本制度与生产路由的System Control入口。保护原则只见`development/ai-responsibility/capability-protection.md`，其它文件不复制精确路径清单。

保护不改变资源的正式身份或消费者，也不禁止以后维护。受保护差异由`development/verify-ai-responsibility-change.mjs`按当前实际文件逐项阻断；保护条目删除另行阻断。机械放行只是一道防误操作背挡，不判断授权真伪或开放质量，也不创建剧集生产授权。

`cue-sync`是由正文Author写入真实字幕绑定的必需功能；`background-music`是由System Control按包清单初始状态启用、P4确定性消费的默认增强，不再由P3人工智能节点配置。Feature被选中时，System Control必须使用其正式包清单的`catalog.initialState`建立正式初始状态；未选择以字段缺席表示，不能把本应为对象的初始状态投影成`null`冒充已启用。阶段装配可以只向当前执行者投递必需角色，但不能因此丢失System Control自身建立正式状态所需的清单元数据。

背景音乐包不随公开源码分发个人默认音乐。没有节目指定曲目且没有本机配乐配置时保持无配乐；节目显式关闭优先，现有登记来源选择保持。个人默认曲目、来源与使用权利由本机`.env`声明，音频放在System Control忽略跟踪的`local-media/background-music/`目录；包读取实际摘要并交给原作者上下文、预览及P4，不增加节点或改变混音。视频使用许可不自动成为源码再分发许可。

`sound-effects`是可关闭的独立Feature，由author-beat在原B1画面形成后调用，独立理解本章内容与已成画面，组织环境、动作、编辑重音和留白，再按原交付单位保存；同一执行者进入该包方法，不新增作者、节点或工作单。Template只拥有原画面、动作及中性时间接口。Feature拥有Lemo制声资源、作者专用制声源码与配方、声音资产和事件，结果随原B2与Feature接纳进入storyboard.features。声音设计可在同一结果表达音乐收放意图，background-music拥有其音乐包络解析与成片贡献，render-video拥有确定性混音；音效包不选曲、生成或切换BGM。未启用音效时不执行这些设计，背景音乐原选择与基础播放独立成立。

候选预览只读合并当前指定功能与未改画面时序，支持独立声音返工；预览、Studio及P4共用声音与音乐收放解析和共享混音。准备声可在正文时窗内先于下一段进入，尾音可自然越过Beat，只在节目结束收口；被剧情视频覆盖的图片声音与音乐收放不执行，片头声音仍归原Template。背景音乐包从原Feature状态解析实际开关、指定或默认音乐及播放规则，供声音作者和候选预览共同消费；预览显式选曲只作本次比较，不改正式选择。声音调整不重生图片、不改动画、旁白或字幕，既有未启用音效的成果保持。

已选Feature可沿清单的authorContextEntry向原作者交付自身只读上下文。sound-effects投递同章已接纳的声音、Cue与实际时序，供联合创作和局部返工衔接；原任务视图刷新当前参考，不改变工作单身份、写权或其它成果。音乐收放允许末点电平持续至本单位结束，相邻单位各自表达衔接；最后正文单位可保持至节目收口，不强制恢复原音量，不把局部意图永久施加到后续独立章节。

音效选择归System Control的`engine/runtime/sound-effects.mjs`：导演计划形成后，既有`next --stage p3|p4 --sound-effects on|off`只更新故事板Feature状态的`enabled`并通知原P4渲染消费者，不推进阶段或发布；`engine/assembly.mjs`按该状态装配作者与渲染，关闭保留已成units。当前正文作者尚在写入时先收口其工作，选择操作不重绑活动工作单或候选。包内理解与配声判断仍唯一归Feature，共享render-video拥有实际混音、完整母线处理和播放投影。

视觉包拥有除vox-explainer外的正片及封面画法、各用途字体与绘制和渲染外观，不拥有节目语义、构图、版式、模板动作或功能行为。相应P3正文Author经原节目Visual插槽取得绘图默认外观，与P4共用同一包；图形生成时便消费该外观，不在成片阶段仅靠换色代替线条画法。Cover拥有封面文字材质、配色、层级、版式及配图的视觉强弱；在Visual画法内约束背景的明暗、对比和细节分配，不另定人物画风，不拥有本集事实、标题、封面文字、远端生成或发布。两类包的结构、资源、编译和生产细节只由各自清单、公共编译器和直接消费者拥有，不在本图重复。

vox-explainer唯一拥有讲解的共同画法、色彩样式和字体描述，画风真源为本包画法说明、指定插画参考及包内地图样式；原treatment.appearance保存本段实际外观，作者上下文、完整画法、生图、预演与P4共同消费。绘画、人物、字线、动画及字体文件均由本包持有，不读取其它Template或Visual的创作实现；相邻画面交接只消费其所属模板形成的结果。空间局势与军事推演也由vox-explainer拥有画法、字体和实际呈现，不再消费Visual地图配置。公共字体加载、媒体读取和计算组件不拥有模板样式；节目字幕仍由原独立字幕层负责。图片入口保存本次实际样式来源；布局和卡点变化不要求重生未改图片，实际画风和配色变化由当前作者处理受影响图片。

Vox普通讲解以代码与组件编排全动效，根据表达需要可补充配合使用生图素材；地图沿包内数据地图组件制作，局部情境图片沿原专门方法制作。作者在原图片蓝图中按本张图所需形态选择相应画法说明，不按整段题材选择；人物、器物和旁图情境与地形图片共用同一参考图学习画法，地形分支服务有需要的局部地貌、剖面及操作情境。原图片程序按该选择组装生成参数并核对实际调用，语义取舍归作者，程序不按题材关键词猜测。画风参考、同一对象原图与修图参考继续沿同一入口交付；已有有效图片不因规则变化自动重生。

Vox的continuity保存本段时期、地点、人物与道具；carryToNext是可选的后续复现提示，可随完整正文供片头等作者参考，不要求每段填写，也不产生正文段间自动继承。已有填写内容保持。

Visual只登记全画幅、片头和封面的生产方案，不拥有讲解生产方案或讲解地图外观。每个Visual包内内容相同的字体与参考图共用一份原文件。跨Visual及vox-explainer的字体资源仍由各自包持有。

候选、工作单、缓存、账本、渲染计划和恢复文件都不是真源。不得创建第二份节目策划、口播、理解稿、分镜、素材清单、正式成片或发布文案。

同一工作单只有一个`candidatePath`。人工智能在创作步骤内可以用当前完整草稿原子覆盖该路径，供下一项正式设计工具读取；“唯一候选”限制候选身份和并行真源，不限制同一路径按真实依赖更新。只有通过Preflight／Accept的最终候选才能进入正式成果。

历史解说与纪录片P1普通创作、完整重跑在各自作者Module内部保留三份同输入独立作者工作稿。解说每份包含完整正文、片头、三平台文案与横竖封面构思，纪录片每份保持正文与片头。工作稿不取得候选身份或下游消费权；择优后，所选作者的完整结果原样进入唯一`candidatePath`。工作稿保留进度、选择、事实清单和作者会话，供同次任务恢复；正式交接保留所选作者身份，接纳后沿现有材料收口清理工作稿。当前尝试有获准的单路失败重试时，原收口保留三稿、失败记录与作者原始回包。定点返工保持单路。创作、选稿、事实核对和停止条件见下文P1责任及各作者包。

`storyboard.yaml`是一份文件，但区块责任独立：

| 区块 | 责任方 |
|---|---|
| `understanding` | `understand-episode` |
| `albumPlan`、全画幅Beat边界、整段与逐Beat观看要求、模板判定和`templateRuns` | `direct-episode` |
| 正文和功能结果 | `author-beat`执行所选模板和功能 |
| `authorQuotes` | `author-beat`汇总正文预留引文，取得史料原文与真实出处后接纳中文引文 |

片头由`author-bookend`写入独立的`episode-package.yaml#opener`，不再写入正文故事板。

现行合同没有`closer`。人工智能只能写工作单允许的候选；Engine验证、接纳并写入正式成果，人工智能不得直接改正式真源或自报通过。

## 五、工作流与阶段责任

| Workflow | 生产对象 | 阶段 | 节点顺序 |
|---|---|---|---|
| `program` | `program` | P0 | 两个P0模块按`programForm`互斥执行 |
| `narration` | `episode` | P1—P2 | 对应P1作者 → produce-covers → 合成 → 字幕 → 收口 |
| `video` | `episode` | P3—P4 | understand → director → author → opener → 按需video → 按需video-assets → render |

Engine只从Workflow和正式包清单推导阶段范围与`resolvedAssembly`，不得维护第二份节点顺序或选择真源。公共命令为`check / status / next / accept / reset / run`；具体参数与恢复方法只见`README.md`和当前责任包入口。

阶段执行每次接纳后都以相同参数重新读取`status`，只有正式完成、上游阻塞、历史解说P1按作者包判定无可选稿、外部结果未知／新增授权、硬系统故障或真实权限缺口可以结束当前执行；仍有可执行工作单或队列的普通进度不是终态。当前阶段交付及Director规定的本次收尾完成后，单阶段停止，已明确授权的连续范围推进至指定终点。

Director只保存统一循环、授权边界和工作单纪律；开始或继续某一阶段时才完整读取该阶段规则。执行P3不默认加载P0、P1、P2或P4细节。渐进披露只改变上下文装载，不改变Workflow、命令、责任、授权、接纳或恢复行为。

`status.queue`只保留Workflow顶层节点，不把P3每个正文创作单位膨胀为独立队列卡片；`author`节点的进度以已接纳导演计划中的`templateRuns`按章节统计，`unit=segment`，`completed / total`表示完成章节数与总章节数，`currentUnitId`指向当前章。全画幅章节的成员Beat全部交付后才算完成，讲解沿整章交付计数；`beatCount`只统计全画幅Beat。Visual Plan正式接纳后才报告总数，完成情况仍由当前同一次状态推导中的正文结果形成，不另写队列文件、进度游标或人工计数。

### P0

`plan-program`负责历史、时事、政治、经济等解说节目，沿用`historical-explainer`内部身份。`planningBasis`只决定策划从参考节目、主题或指定书起步，不决定取材工具。网络正文、本地材料和NotebookLM可按实际内容需要单用或结合；`referenceProgram`与`researchLibrary`可同时存在，也允许只交接可读取的公开正文。材料理解、充分性和取舍归原AI作者；System Control只投递实际声明的来源，保留真实材料与恢复身份，不建立研究Workflow或第二份策划。

综合解说内部由P0确定节目级`explainerType`：`general`为通用解说，`current-affairs`为时政解说。用户明确指定时，Director记入同一`request.yaml`，P0采用该选择；未指定时由plan-program依据当前任务与材料判断，最终值只以`program.yaml`为真源。System Control通过既有`packages/program-brief.mjs`原样投影到`episode-brief.yaml`及P1工作单，P1不重新分类。该选择独立于`planningBasis`、Visual、Cover、片头与P3模板，不增加节目形式、责任包、Workflow或节点；纪录片不使用该字段。

实际改变解说类型属于P0修订，更新后的单集任务沿原接纳链通知P1处理真实受影响的正文。旧策划缺少类型且需要新写正文时，由原P0修订入口补齐，不在下游猜填；已完成交付不因新增规则自动失效，只修封面或发布文案也不以补正文类型为前置条件。

解说的`video-led`入口由`plan-program`消费指定本地参考节目清单与完整底稿，理解单集或系列后决定拆合与逐集任务；用户想法融入现有委托与内容任务，补充取材只关闭实际缺口。节目仍只有`program.yaml`一份策划，保存`referenceProgram`及逐集`referenceVideoIds`。既有`episodeCreativeBrief`承载完整故事策划：人物和事件、起因与经过、关键关系和转折、结果及其策划逻辑，并附可借鉴的叙事方法和材料定位；`episodeScope`承载范围。P0交清楚讲什么故事，P1继承故事实质并自主决定讲述入口、顺序、详略和语言，不锁定原节目的段落结构。System Control的`packages/reference-program.mjs`将对应全文交给P1取材执行者，全文不直接成为AGY扩写输入。普通研究方法对P0具体故事结构的限制仍只适用于`topic-led / book-led`。

`request.yaml#programForm`显式选择`historical-explainer`或`historical-documentary`，分别进入`plan-program`或`plan-historical-documentary`；`planningBasis`独立选择`topic-led`、`book-led`或仅适用于历史解说的`video-led`。系统不得从题材、书名或自由文本猜测，也不兼容旧合同。P0拥有策划、对应路线的材料交接和单集投影；具体调查、策划和材料方法归所选P0包。历史解说研究路线单集只交付`episodeTitle / episodeQuestion / episodeAnswer / episodeCreativeBrief / episodeScope / episodeBenefit`六项内容合同；P0不决定主角、故事类型、叙事载体、具体开场、固定推进单元、事实顺序或结尾。`program.yaml#visualPackage / openerTemplate`分别是后续视觉与片头选择真源，片头不随节目形式绑定；正文的`fullframe-narrative / vox-explainer`由P3 Director按连续内容选择，不进入节目策划。

显式P0修订以同一节目已接纳且内容摘要完整的正式策划为起点；现行新增字段缺失不阻断进入修订，候选仍须满足全部现行合同。未接纳、身份不符或内容摘要损坏的文件不能作为修订基线。

P0尚未接纳或正在修订时，用户中途修改同节目、同形式的委托，由System Control原`--revise-program`入口更新工作单输入，保留同一路径的草稿与材料，仅备份被替换的旧单和草稿供中断恢复；不把草稿当作已接纳基线。P0作者按新要求修正当前唯一候选，再由原accept接纳。普通next继续当前任务，不自动采用变化后的委托。参考节目文字校正由plan-program拥有：AGY不可用或明确失败后Codex按相同来源边界接手，只读未知调用不重投、不覆盖已交付校正稿。现有VideoCaptioner负责必剪、剪映超时及原任务恢复，P0只在明确失败且无待恢复对象时切换备用服务。

基础书本地文件由P0读取和选择导入时核对；材料交付到NotebookLM后，P0接纳消费资料库身份与必要来源就绪状态，不再把上传原件的本地路径和摘要作为接纳依赖。解说直接读取的网页或本地正文通过现有`episodeCreativeBrief`交接出处、相关页段和用途；采用NotebookLM时才保存并核对真实库与来源身份。该边界同时适用于首次策划和修订，指定基础书的骨架责任和材料内容充分性仍归原P0作者。

P0拥有材料反推与取得协作：解说按内容选择适合的公开正文、书籍或NotebookLM材料，纪录片保留以书籍为主的原材料方法。无法自行取得的重要书籍由P0在会话中向用户提出具体找书需求，用户提供后仍由同一P0作者核对并续作。关键材料未取得时留在P0材料步骤，不以目录、概览或来源就绪状态代替内容充分性，也不把缺口转嫁P1。这是材料输入交接，不是新增审批节点、正式书单或生产状态；唯一候选及已取得的Notebook身份继续保留。

纪录片P0在节目委托的时长内确定单集核心收益、内容范围、必要生活过程和集间分工，保留故事骨架与重构边界；不把沿途细节全部固化为正文覆盖任务。P1继承这些业务决定，作者可以合并或省略非关键连接动作、选择叙述入口及展开方式，不能改变本集主体、必要关系、历史先后或范围。具体容量与取舍方法由纪录片P0/P1包拥有。

Director允许当前阶段明确要求的必要输入等待，先完成独立工作，再从同一任务恢复。P0区分材料尚未取得与已读证据不能支持设计，前者保持候选等待，后者由原作者在委托内修订，触及用户限定或入口变化时交回用户决定。同一候选增量保留已知Notebook和来源身份供恢复，身份不代表材料合格或可以接纳。包入口拥有执行与交接，现有方法资源拥有专业策划判断；验证范围与起点由责任包验证标准按实际风险裁决。

### P1

P1按programForm只进入`author-narration`或`author-documentary-narration`。Codex拥有材料理解、创作任务交接、整稿选择和有据基本事实核对；AGY拥有各自稿件的讲述中心、材料取舍、结构、语言、节奏、转场、结尾与全部文字。P1最终只接纳一套正文、片头与发布内容，P2、P3与P4的正式输入合同不变。

author-narration按正式单集任务的`explainerType`消费包内对应正文方法：通用解说保留原有故事与解释方法；时政解说使用从20期《王局拍案》完整字幕及试稿提炼的讲述与推理方法。方法选择在原任务书与发布输入中交给作者，三路完整创作、固定提示与整稿选择使用同一路线；专业方法由该包拥有，不预定本集立场、结论或段落，不改变一次事实核对及必要原作者纠错的职责。

解说三种P0入口共用[author-narration](../packages/modules/author-narration/SKILL.md)。当前任务与材料缺口决定参考节目、公开正文、本地材料与NotebookLM的组合，不因Notebook存在而强制查询。唯一临时`author-task.md`保真交接业务目标、范围及依据，已有完整故事策划不能缩成一句主题或变成必须照写的段落大纲；任务书写法归[作者任务方法](../packages/modules/author-narration/references/author-task-editing.md)。

纪录片保留P0故事骨架、唯一`creative-outline.md`、有据Query、文学重构与独立片头方法。现有episodeBrief交接受众、核心收益、范围与创作委托，programPlan从正式program.yaml携带按需存在的maxDurationSeconds；不另造时长字段或统一字数。短大纲与作者取舍归[author-documentary-narration](../packages/modules/author-documentary-narration/SKILL.md)，时长和正文预算不构成新增接纳门。

普通创作与完整重跑由三个独立AGY会话同输入创作。解说作者在P0内容任务与有据材料内先拟标题及封面构思，再写正文与开头，在同次创作内相互调整并一次交付完整方案；必须收齐三路完整方案，Codex才按题图、实际开场与全文共同形成的体验择优，明确失败不减少选稿数量。P0拥有讲什么及必须讲清的内容，P1拥有讲法与平台表达，不为题图改变本集问题、主要主体、范围或独有收益。纪录片保持三路正文与片头择优，选中原作者再补齐发布内容。两者都原样选同一路作品，不能跨稿拼配、代写或追加润色；可交付与择优条件由各自作者包裁决，不能交付时保留现场并报告，不自动补开作者或重写。

整套形成后只对唯一候选做一次基本事实核对，按需原会话最小纠错一次，再仅确认原清单及必要连带表述已改对；不展开第二轮整套审稿。解说在现有N05集中核实具体引语、文书及关键事实，现有依据不足时定点补读可靠正文，实际使用的正文存入原材料快照；N01只解决写作必需的材料缺口。未选稿不审不修，文学空间、片头意义和写作方法不成为事实纠错理由。定点返工仍单路并保留本次未授权改变的内容，未知只恢复原调用，不重置核对与纠错次数。

两类作者共用`author-narration/scripts/author-handoff.mjs`进行确定性交接：承接原始回包和执行者的真实进度、保留原事实清单、补齐确定字段、调用现有机械校验并原子保存工作稿或唯一候选。AI拥有创作、选择、事实判断及原错误确认；程序不调用作者或审查内容。解说首稿某一路明确失败且用户明确授权重试时，原交接入口只重开该路，保留失败记录、原回包及其它稿件；未知调用、已交付首稿和选稿后进度不适用。纪录片纠错不独立重复机械复验，正式accept仍执行原接纳合同。内部命令、进度与恢复只由[作者交接方法](../packages/modules/author-narration/references/author-handoff.md)和[原错误确认方法](../packages/modules/author-narration/references/publication-author.md#纠错后的原错误确认)拥有。

任务连续性由现行业务输入、唯一候选和材料执行身份承担。Engine保留本次实际Query、reference-materials、作者任务或短大纲、实际会话及已用发布调查输入，绑定当前正文供接纳与返工消费；P3引文单按当前正式正文绑定的材料身份读取已保留的正文及Query引用，作者选择引句，原引文程序绑定实际来源，不重新查询已有依据。参考原文不伪造NotebookLM回执。查询提示不以逐字包含P0字段作为接纳或复用条件，对P0的忠实表达与证据充分性归作者包，Engine核对固定文件、摘要、引用及会话身份。

解说正文定点重写复用固定来源并开启新的单路作者，纠错及后续修订跟随该稿新作者；片头定点返工复用材料、续接正文作者并修改必要承接。用户锁定的片头原句由程序保留，正文仍由作者调整。缺失、变化或无法确认的固定材料停止，不扫描其它尝试补齐。具体取材、免费Query有效性失败的重提与失败恢复，分别由[解说取材方法](../packages/modules/author-narration/references/explainer-evidence-and-query.md)和[纪录片取材方法](../packages/modules/author-documentary-narration/references/evidence-and-query.md)拥有；远端未知只恢复原对象，不借切换取材渠道掩盖。

用户明确放弃已形成的未接纳正文返工候选并再次要求重试时，System Control沿原正文返工入口核对现行请求、工作单与候选归属，通过原工作保留机制重新签发；固定材料、锁定片头和旧正式交付保持。未知调用仍只恢复原对象，不增加阶段、节点或正文真源。

具体断言的出处回查由author-narration包内原定位程序调用同一TypeSafe接口选择原引用；不依赖维护者私人脚本，不安装另一份SDK或复制用户凭据，仍读取原进程环境或用户配置文件。原缓存、专业标准、实际原引用与无匹配语义保持，当前主代理消费所选出处判断。首次取材仍完整阅读。实际材料缺口不单独构成退回P0的理由。

### P2

P2只消费正式正文。`synthesize-narration`拥有音频合成与完整原生时间读取；`author-subtitles`由Codex准备同源时间证据，默认交给AGY按正式文稿组织字幕边界并复核唯一候选，AGY不可用或无法完成时由Codex按同一方法接手。接手须确认原调用不再写入，不重投未知的音频服务，不放宽输入或质量要求。确定性程序保真切片并绑定实际音频的词级时间，不得手工改字或编造时间；实际复核执行者如实记录，Codex负责正式验收与提交。原生时间缺失、无效或经核实不符音频时由现有VideoCaptioner云端取得时间。`finalize-narration`拥有最终音频字幕合同并复核同一正文、音频身份与时间证据。模型、时间轴、字幕算法和数值限制只由这些包及合同拥有。

finalize-narration在现有subtitle-quality证据中保存绑定最终旁白的实测短语时间，沿用author-subtitles的原文对齐，不插值或重做识别。P3输入按需读取该交付；vox-explainer的作者上下文只投递本段的可用短语及相对Cue偏移，作者决定动作开始、作用或落定与哪处声音相接。它不改变正式字幕分句、cue-sync的句界合同或P4时钟；缺少细粒度证据不冒充已完成精卡，也不自动返工已有有效结果。

用户明确要求返工已完成P2的字幕时，System Control通过`next --stage p2 --revise-subtitles`在原Workflow重新签发`author-subtitles`工作单，保留正式口播与配音，只投递同一正文、同一音频已接纳的时间证据供恢复；旧分句不作新分句的输入。新候选仍由原接纳及收口链生成唯一正式字幕交付。字幕修订只替换相关交付，并明确实际受影响的字幕或画面时序；不重新合成已有配音，不自动跨阶段重做。

### P3

P3由主代理完成理解、整集视觉设计、切分审计、调度、串行接纳与历史引文收口；正文按已接纳的章节（templateRun／TR）一章一位原生子代理，最多三章并行，待办不足或并发受限时按实际数量启动。每章首次派工使用不继承聊天历史的全新独立上下文作者，沿原正式工作单完成本章所选全画幅或讲解模板的创作、素材、预演与交付；成功接纳后结束使用该作者，下一章另建，不跨章复用。同章未完任务、接纳修正及作者不可用时的恢复仍沿原单和有效成果执行。主代理不承接逐章正文创作，也不在交回后重复整章观看复核。专业方法由对应Module、Template及Feature拥有，System Control负责确定性装配与接纳。

各章节工作单、唯一候选与临时材料分别位于`p3/_work/author/<TR编号>/`；理解、导演和引文收口仍使用阶段工作目录。`next --stage p3 --claim fullframe|explainer`在原写入锁内选择未领取章节并签发工作单，已有工作单或候选的章节不再分配；fullframe与explainer各自只领取对应模板的待办。主代理按当前整集status中的待办顺序选择类型，在并行空位内为新作者领取；按交付到达顺序串行接纳、刷新整集状态并补派新作者，不等待其它章节一同完成。`status / next / accept --stage p3 --segment <TR编号>`定位既有章节任务，普通status提供整集进度。章间允许乱序交付，主代理沿原接纳事务将各章节结果写入最新故事板；恢复与重置覆盖这些工作目录，不新增业务队列或调度节点。

全画幅章内保留前序实图、动作与相机连续性；章间独立创作，不投递其它章节的已成画面作为作者参考或等待条件。所有作者仍消费所需正式口播、整集理解、导演安排和所选视觉规范。真正连续的镜头由Director放在同章，不为并行强行拆章。普通相邻转场与讲解底板仍由原渲染消费者组合，作者在既定创作范围内完成衔接设计与复核。

P3以准确的知识关系支持有趣、可感的视觉叙事。Understanding建立整集及跨段的共同理解，并明确必要的事实与误读边界；Director拥有整集观看推进；Template拥有合理演绎、视觉隐喻、象征和幽默的具体表达。创作自由不改变关键事实、身份与因果，象征画面不作为新增历史证据。全画幅根据口播语义自由创作，不限人物或剧情；每张是一幅完整画面，沿原入口一次生成，并按观看重点运镜。模板归属仍由Director按实际图解需要判断，不因题材或能否画成单图决定。

P3直接读取P2口播交接、音频字幕和所需来源资料，不设独立入库回执，再依次完成理解、整集视觉导演和正文模板创作；不重新核验P2音频质量、时间证据或生产摘要。来源登记及引用权利由实际使用来源的产出责任方负责。正文全部接纳且必要历史引文已由同一Author责任完成取证、填写或取消并接纳后，Engine报告stage-complete，Director据此结束P3。全画幅沿原模板完成创作内设计复核与实图落实，讲解包括空间推演，沿模板完成配音预演与手机尺寸复核。P3交付后不再执行整集连贯性、节奏与衔接检查或集中修正。片头与剧情视频设计在P4完成，没有片尾。

P3缺省来源清单尚未建立时，System Control返回可由正常`next`继续的`initialization-required`，由既有初始化程序建立空清单后重新预检；`status`保持只读。真实上游缺失及无效来源输入仍停止，不将初始化新增为Workflow节点。

P3导演和正文作者补查的资料由System Control的`packages/p3-sources.mjs`写入现有来源资产清单及其`sources/`目录。AI负责取得原文、判断依据与权利、交清用途和精度；程序负责文件、摘要、身份和追加写入。导演通过原观看要求交接SA编号及其支持的关系；全画幅与讲解的作者视图、设计检查、图片、预演及接纳读取同一现行清单。只追加资料且原资料未变时保留原工作单、候选和锁；改动或删除原资料仍按真实输入变化处理。补查不改口播与Understanding，不增加节点或第二资料清单。

历史视觉考据由direct-episode的`historical-context/`包内组件拥有，是章节方向形成之后、全画幅Beat切分之前的独立导演步骤。组件的专业方法负责人物样貌、衣装和环境依据；包内交接程序消费AI在当前scratch形成的研究输入，复用System Control来源登记，把原件及带适用Cue范围的资料存入既有来源库，再向当前导演候选的观看要求分配依据。来源登记、文件安全与权利仍归原System Control，不新建正式包、Workflow节点、人物库或独立接纳身份。

导演根拥有章节、考据、Beat、一次审修封存和接纳的顺序，组件只返回资料、范围绑定或有限失败事实。所选正文Template通过原任务视图与`directorBrief`读取同一历史视觉资料及原件，把适用特征落实到场面、代码造型或图片请求；作者使用方法保留在`references/period-appearance-method.md`，只拥有消费与局部补查。P4继承相关依据及已定外观，P4只消费正式交付。资料不足回导演考据，错误图纸和生成偏差回实际作者，失效仍按实际输入和引用传播，现有节目不因组件或方法变化自动返工。

#### Module与作者单位

Feature由正文Author在拥有编排权的Module或Template声明位置调用、汇总并接纳，不支持独立Feature节点或工作单。cue-sync保持模板原调用位置，sound-effects由author-beat在画面形成后按开关调用；背景音乐仍由原System Control与渲染链管理，不归音效包。

- `understand-episode`唯一拥有`storyboard.yaml#understanding`，一次性交付多个下游必须共同继承的最小语义：整集问题、论点、叙事弧、非显然主张与关系、必要语境、声音边界、修辞真义、人的处境、未决项和禁造边界。正式cue本身承担正文证据，不复制为narration evidence；登记来源证据只在共享语义确实读取来源资产时建立。结果不要求逐cue事实覆盖、连续编号、全量证据账本或没有消费者的中间枚举／封存。
- `direct-episode`是唯一Visual Director，交付`albumPlan + beats + templateRuns`完整画册脚本；它拥有整集方向、模板及连续范围、全画幅Beat边界、Cue分配与观看要求，不拥有具体构图、相机、素材请求或生图或P4实现。正文作者消费当前创作单位投影；片头只消费整集进入方向、首Beat和候选实际引用正文。全画幅Beat是连续真实Cue上的独立观看单位，其切分、真实时长复核与导演合同由本包登记的Beat方法唯一拥有；跨模板比较、完整连续范围与本集归属由Director的模板选段方法唯一拥有，模板目录提供实际能力与限制。新讲解每章沿现有beats保存一条整章范围与要求记录供templateRuns引用，内部讲法、画布、部件和Cue由原模板作者决定，不作导演Beat切分；有效旧多成员章节保持。根入口拥有先划章节、历史视觉考据与交接、仅切全画幅Beat、同源可创作性计算、章节与Beat两层的一次审修、封存与提交的顺序和失败返回。模板通过现有确定性检查提供创作条件；全画幅共读视觉方法由Director在预计画面组织时按需消费，正式画面数、Cue绑定和相机仍由Template作者形成。原可创作性入口在首次创作的计算前整理当前候选的顺序编号与明确引用；已有导演计划的修订保留既有身份，作者判断拆合及实际引用归属。封存与接纳共同消费整理后同版完整导演候选的可创作性结果，计算通过不证明画面质量，下游Template不能取得分页权。
- `author-beat`在Workflow的`each-author-unit`节点执行Director／Engine已经选定的唯一正文Template。Module拥有逐单位编排、Feature汇总、Preflight、提交和失败返回；Template拥有当前单位专业创作步骤。每个作者单位取得当前cue、Director观看任务和按cue范围确定性交集的紧凑语义；素材来源可直接引用当前cue的`Cxxx`、相关F/R/E语义对象或合法SA，不要求Director为普通页面转抄语义编号。`cue-sync`只在Template点名的位置形成字幕绑定并返回Feature结果，不是Workflow节点或第二提交流程。各章节可同时持有自己的作者工作单；B2只检查当前候选；全画幅与讲解子代理均在完成B2后交回主代理串行接纳。System Control的现有任务视图向Author提供去重但保真的当前输入；Preflight对已选Cue作确定性排序，经原完整校验通过才保存同一候选，不改变语义选择。仅返工指定Feature时，Author共享补齐能力由Preflight与Engine共同调用，从工作单原设计补齐省略的正文；显式改写原设计或未指定功能仍拒绝。
- P3同一人工智能工作单需要顺序恢复时，只用任务摘要绑定的最小临时锁连接真实前序结果与直接消费者；锁不是第二候选或业务真源。前序结果变化由所属责任方修正并重新锁定，保留仍有效的后续内容；后一步不能静默覆盖前序；工作单接纳或退回后按Engine合同清理。

#### 正文Template与各自呈现

- `fullframe-narrative`唯一拥有全画幅`treatment`，内部`camera/`、`callout/`和`effects/`是包内组件，不是正式Feature、Workflow节点或第二成果；模板根拥有三者与`cue-sync`的编排和失败处置。`vox-explainer`是唯一讲解Template，拥有连续作者单位的treatment、素材合同、真实Cue与渲染方法，包括空间局势和军事推演。Director先从完整口播选定必要讲解章节，再按章节尺度组织剩余连续全画幅内容，随后只切全画幅Beat；templateRun保存所选模板及连续成员，同一战争推演的部署、应对与结果保持连续。全画幅章节组织叙述与联合创作，正式成果、功能、媒体和渲染单位仍为Beat；讲解保持原整章treatment。作者沿已选模板创作，范围或选择不成立仍返回Director。

  vox-explainer从导演的整段口播、观看目标和事实边界出发，以Vox视觉思路创作有表现力、细致的全动效设计与非线性演示动画，以具体形象、短字、解释性动作和连续画面承载含义。它独立拥有创作入口、画法、字体、appearance、图片交付、私有treatment及播放实现；共同画法与画风参考由本包拥有，不复用旧模板的元素体系、教材或案例编排。作者在同一treatment内交付完整HTML/SVG画面、原生动画和有序观看变化，cue-sync把这些变化绑定真实字幕。普通讲解由SVG、HTML/CSS、Canvas和JavaScript配合GSAP及现有组件编排全动效，按表达需要补充生图素材；当前sourceAssets中的可用原件仍沿原来源及权利合同导入，构图由本题决定。整段HTML画面在独立Shadow DOM内呈现，GSAP、Web Animations和逐帧绘制都由HyperFrames唯一时钟定位。预演与P4消费同一候选、图片、字体和真实旁白；临时草图不取得正式接纳权。创作、素材和画面问题回本模板作者，程序交接失败归实际消费者。

  普通讲解可按表达需要组合代码绘制、共同坐标、镜头与窗口技法，并在同段切换表示。地图定位、地理空间与军事推演沿本包空间方法，在共同空间中建立地点、力量、通路与状态关系，保留必要的连续行动与结果。地图由包内spatial/的数据准备与MapLibre地图窗口组件呈现，统一浅纸边框和地形色面；数据在作者制作时准备并内嵌原scene，渲染不联网取图。地图作为共同讲解画布上的对象展开、缩放和移位，兵棋默认SVG并可按需生图；旁图以开口观看独立内景并保留地图参照，全屏细节按场景转换承接。地图专门方法归vox-explainer的references/spatial.md，普通讲解可借用其中编排与代码工具，补充素材沿本模板的素材与动作方法准备；符号、地理计算、路线和屏幕布局归包内spatial/资源，均不是新责任包。原scene、moments和cue-sync承接作者结果，HyperFrames唯一时钟驱动预演及P4。地图窗口是现有模板的内部组件，不新增地图专用模板、Schema或预绘制链；不迁移、不自动重做已有节目成果。

  全画幅按完整观看推进组织Beat，不按图数或默认秒数切分；单A与A/B由作者依据表达和实际可读时窗选择。A/B成立判据由场面选择方法唯一拥有，Director预判和Template观看骨架共同消费；正式选择、锁定和后续创作归Template作者。全画幅根在锁定图片前核对图片／解说框边界；场面、观看职责、构图、Cue与运镜在同一次设计中调整，从任务视图直接参考同段紧邻上一全画幅的实际末态。参考不改变当前观看职责与来源；跨场景观感衔接由作者判断，同场景严格接镜继续由同源运行时核验。联合设计测量并由作者复核，后置解说框消费定稿画面；局部修改沿同一完整候选保留有效画面、解说框与Cue，复核实际影响后刷新原锁。正文Template的步骤、阈值、几何、相机、Cue和校验细节只由各自根入口、方法、合同、Validator与直接消费者拥有，施工图不复制。

  全画幅静态画面由P3作者在唯一的`sceneDescription`中写成完整、可直接绘制的画面，随原treatment交付。完整指一张表达成立的成品，内容与构图由口播含义和观看需要决定；按用户要求不做拼贴或拼图。设计复核、前序与相邻参考、生图和实图落实共同消费这份原文；程序不重新组织语义。观看任务、来源、禁造边界、精确文字、连续性和相机仍由原合同分别承担。原exactTexts可交付作者概括或有据原文，文字事实与引述真实性由作者判断，程序不以逐字匹配代替语义；历史引文组件仍独立取证。生图请求保留作者画面，只附加已定文字、事实限制、合法参考及Visual画法。
- vox-explainer拥有讲解图片、来源、排版、空间定位与Cue动画；现有自包含Schema及Renderer消费整段scene。准确标签由程序排印，地形、人物与情境按作者画法制作；历史坐标与路线依据当前来源，概略示意不冒充测绘或精密仿真。内置离线地理数据只提供海陆水系；高程由制作时选取的DEM数据提供，历史边界和行动仍由作者依据来源交付。文字、符号与局部细节保持对象对应及手机可读尺寸。设计错误回本模板作者，事实缺口回真实上游，程序错误回实际消费者。公共视频规格、字幕、来源权利与媒体读取继续由原责任方提供。

全画幅`effects/`拥有场景氛围与短时人物反应的专业方法及呈现。P3作者在原逐图候选选择效果和参数，并据实图交付人物或光源锚点；原设计锁、接纳、Studio与P4共同消费。场景效果随所属图片及其转场显示，短时动作沿原cue-sync；组件消费原相机，不改运镜或静态生图投影，字幕与解说框保持在其上层。选择或定位问题回当前作者，实现故障归该组件。

全画幅在同一候选按“联合创作 → 实图与最终镜头 → 解说框及Cue”完成。生成前由作者完成设计复核，生成后在原实图落实中确认画面表达、必要辨识与实际取景，落实最终镜头和效果锚点；不新增审图步骤或质量状态。具体失败沿模板原定点修正处理，仍受原图片修正与外部调用授权约束。System Control的`packages/authored-images.mjs`直接装配Template图纸、Visual与合法参考，保存当前所选工具原图及真实来源；同单位图片的生成参考由当前作者按真实连续性明确选择，调用记录固定实际请求，不由导入先后推定。最终相机只写原motion。`packages/authored-media.mjs`从作者成果确定性归集媒体供Studio与P4使用，不保存第二图片清单。

全画幅首次创作由原author节点将同章待制作Beat投递到同一联合工作单及唯一候选，原图片、测量与解说框入口按成员分别执行并保留原Beat身份；Engine逐Beat校验、记录生产来源并原子写回各自treatment及功能。章内前序设计与实图由同一候选提供，实际相机接续仍消费同源时窗。指定正文或Feature返工只投递实际所选Beat及原章节只读语境；有效成员不重签或重生。参考复用、原调用恢复和B2提交续领保留，P4仍逐Beat消费全画幅。章节元数据本身不清空有效Beat成果，只有实际业务依赖变化才通知相邻作者。

#### 设计复核、上下文与时窗

- P3状态只报告执行与交付事实，不从目的文字差异或路线相似度推断构图质量；相邻相机状态仍供当前作者按设计需要参考。
- `fullframe-narrative`原`inspect-design`同时提供创作候选测量与正式分镜只读读取；两者共用包内相机测量和转场显露计算。只读入口从当前正式分镜、口播与Cue组装完整Beat材料，供明确的查询或问题定位读取完整设计、来源正文、实际取景和相邻转场反馈，不依赖创作工作单、候选或步骤锁，不写节目、锁或审计状态，也不触发P3交付后的例行检查。
- 全画幅上下文投影向原作者交付正式全片口播 Cue、完整导演安排及当前所在位置，供作者先理解全集推进与节奏；前序已接纳图片提供职责、场面、静态构图、运动意图及已有转场原文，支持局部设计与必要连续段的节奏比较。精确上一镜几何随现行任务视图提供，绑定原工作单记录的同一前序输入，不把尚未创作的后镜当成既有画面。其它正文模板只提供通用图片职责。全片语境与前序参考不取得其它页面写权、不扩大本图来源授权，也不因参考或摘要变化自动返工后续成果；原工作单身份、候选和锁保留，原任务视图补充现行只读参考。实际正文、观看职责、选择与承接输入变化仍由原连续性核对处理。
- System Control把已定作者单元边界交给所选Template上下文程序；全画幅复用P4接镜计时，在当前作者的预算、设计测量和接纳中核验自身真实运动窗口。数值时窗和上一镜几何共同供当前联合设计使用；窗口不足留在当前作者修正，不延迟到下一工作单构建时才发现。

#### 历史引文收口

- 全画幅引文是补充展示。正文作者从当前口播识别具体原话、文书或历史记载，在原callout位置预留检索线索、锚点和显示Cue；全部正文设计完成后，由同一Author收口工作单优先复用P1已保留的正文及Query引用，选择引句、确认出处，只为当前引用的实际缺口补查，不例行重审口播。参考视频只提供线索。作者核对实际史料正文与语境，选择连续引文；非中文原文忠实翻译成中文后上屏，中文原句照录，并署实际书名及必要篇卷；程序直接绑定工作单已投递的P1依据及当前scratch的新增来源，不把参考视频当成史料出处或伪造远端回执。偶然发现明确反证时，按引文方法先报告完整问题与制作影响，保留正式成果，沿获准范围修订，不边查边接纳P1改稿。已经启动的NotebookLM查询保留同任务、同Notebook与同批请求的唯一回执，完成复用，未知不重投。authorQuotes只拥有引文决议与独立生产溯源；正式下游投影把中文引文放入原预留位置，原文保留在现有取证记录中；确实无法取得原文或归属的项只移除其框与显示绑定，不调整其它时间。正文原成果及后续作者依赖始终消费设计时预留事实，不因引文收口改写生产者或失效；人物介绍、术语解释、画面相机与素材合同仍由原责任方拥有。
- 增量引文收口在同一`authorQuotes`中保留仍被当前决议使用的原始查询与各批接纳来源，供原引文核验能力读取；聚合结果不把多次真实调用拼成一次回执。正文修订只取消业务请求实际改变的引文决议，未改项与原批次证据保留。局部重切后，原已接纳的取消决议在资料库、查询意图与原输入不变、范围未扩大且来源唯一时，由原引文组件只读解析到当前位置；非空原文不自动移用。状态、待查询任务及后续投影共用这一结果，原回执与生产者不改写。仅因既有决议未被识别而签发、且尚未写候选或启动查询的多余收口工作单，由普通next沿现有事务清理；已经开始的查询保留现场。没有新节点、候选身份或外部调用。
- 用户明确只重作已接纳P3中的指定历史引文时，System Control按Beat保存原引文摘要与本次意见，重新签发同一Author的引文收口工作单；新候选接纳前旧决议继续有效，接纳后只替换所选`authorQuotes`并通知真实读取该投影的下游。正文、导演计划、画面、相机、显示Cue和未选引文不变；进行中的其它P3任务或不同范围请求不能被覆盖。该入口不增加Workflow节点、查询服务或下游授权。

#### 正文与导演计划返工

未完成P3可显式指定正文单位插入创作或返工。System Control复用原`body-redesign`请求与`held-work`恢复：普通正文工作单、候选及临时锁先保留，所选单位先创作；请求收口后恢复业务输入仍匹配的原单。只读前序画面参考由原任务视图刷新，不改变工作单身份；真实相邻输入变化仍按原连续性处理。其它节点、已有修订及未知远端不能被覆盖；不新增节点、候选身份、恢复目录或外部调用。

- P3返工必须显式声明业务切片。公共正文重作使用`body-redesign`，保留既有Understanding与Visual Director结果；可以选择一个或多个Beat，按现行作者单位映射执行，连续模板运行组提供完整上下文但只修改实际受影响部分，未指定Beat时重做全部正文。已有`--revision-reason`可交接具体意见，保存在原请求reason并投递作者，普通next恢复同一范围与意见。未选正文与片头保留，仅在明确修改确实影响其内容时沿原责任链修正；原作者复用仍有效图片并只修正实际失效部分。已签发返工按原请求范围及必要依赖续接；用户明确放弃时沿原入口处理。已完成旧集与单纯查询不自动触发返工。

- 已接纳P3需要局部修改Beat边界、观看职责或模板归属时，System Control通过`next --stage p3 --revise-director --beat <ID> --revision-reason <意见>`建立原director节点的`director-revision`请求，使用同一工作单、候选与导演现行接纳链。Understanding和整集方向保留，Director只修改所选原Beat覆盖的cue、相关引用及紧邻下一页实际受影响的承接说明；范围外页面及独立运行组保持原样。结果接纳后按既有业务差异清理实际失效的Author结果与功能，保留其它正文、引文和生产来源，并沿普通P3入口补齐。首次创作仍整理顺序编号；已有导演计划的修订保留B／TR／RE身份，以数组和cue决定播放顺序，新对象取得未占用身份，不因局部拆合重编号整集。进行中的正文重作只有用户明确放弃该未接纳任务，并使用`--replace-body-redesign`时才能转入导演修订；持久化请求绑定被替代对象，普通next可恢复中断，不手工清理节目文件。不自动执行P4或新的外部调用。

用户明确撤销尚未接纳的导演局部修订时，`next --stage p3 --cancel-director-revision`通过原事务恢复机制清理该请求、所属工作单、候选和临时锁，保持已接纳成果，不恢复此前明确放弃的正文重作。修改进行中的范围或意见时，先明确撤销原修订再发起新范围，不手工删文件。取消不接纳任何设计，也不执行后续阶段。

### P4

P4默认由一位全新独立上下文原生子代理承担片头，主代理调度、接纳并完成最终压片。只有用户明确启用剧情视频时，才由片头与剧情视频两位独立作者执行以下并行交接。片头与视频选段、独立设计并行；视频涉及正文首幕时，仍在原V2消费已接纳片头核对接镜。视频作者在设计正式接纳后继续原video-assets节点，不另开第三位作者。正式视频生产等待片头与视频设计均已接纳。片头继承已接纳正文和P1片头文字；所选Template决定该句是否合成为片头旁白，documentary-opener保持无旁白，episode-opener、crossfire-opener、opposed-opener与glass-opener消费正式片头TTS。正文与片头仅在素材和渲染消费者内组成运行时投影，不写第二份完整故事板。Studio及P4直接消费正文、片头实图与剧情视频交付，不以P1文案或封面修订作为正文素材失效理由。纯技术重渲染不使文案或封面失效。

System Control以`status / next / accept --stage p4 --node <节点>`定位本阶段已有节点，工作单、唯一候选与其scratch材料分别归属`p4/_work/<节点>/`，返回请求仍归阶段根目录；不新增节点、阶段或正式成果。视频设计工作单保留完整正式正文与所选资源，并以正式片头引用交接并行尚未定稿的邻接输入；首幕接镜在片头接纳后由视频作者读取实际结果，不用聊天摘要替代，接纳程序保留当前真实片头依赖。原V2消费片头时由System Control的`packages/p4-opener-reference.mjs`返回完整正式输入，并在原scratch保存仅含来源与版本的依赖绑定；接纳与最终写入核对同一版本，变化只交回受影响接镜，不另建候选或质量报告。恢复、阶段重置与接纳事务覆盖各节点目录，彼此独立的候选不得覆盖。

#### 片头设计

`episode-opener`在P4直接消费已接纳的P1片头和正文进行画面创作，不再次核对正文事实或逐项回查来源对应。P1继续拥有文字事实核对；P4保留原句、素材权利、引用身份、文件和时长合同，正文引用只承接真实创作依赖。

- `author-bookend`在正文完成后执行节目配置已经确定的唯一片头Template，不改写片头口播。片头Template拥有专业创作，Module拥有候选提交和Engine返回；正式接纳结果只绑定P1片头、Understanding、整集进入方向、首Beat、模板实际消费的最小节目上下文和候选`bodyRefs`实际引用的正文结果。回忆画流模板通过既有`authorContextEntry`取得正式本集标题、节目方向、纪录片故事世界（如有）和本集创作范围；前五张从P3已完成Beat选择并保持原请求引用；未被视频覆盖时直接使用P3实图，被覆盖时使用实际视频在原请求出现Cue的定格，D06不得选择正文图，由同一片头作者依据这些节目正式设定为每期重新自由设计一张有本集来源支持的鸟瞰或俯视全景，其位置、角度和构图不按集数或固定序列预排，也不复用历集设计或成图。同一片头作者通过图片交接资源每集生成一张D06，P4直接消费五张正文画面与新增全景交付。不使用内置、其它节目或历集全景，不改变阶段和付费恢复边界，新生成的D06片头图在P4完成技术交付，复用图不重复观看。

`crossfire-opener`独立拥有三画面燃边、短字入场、交叉对冲与整幅展开，以及固定配乐和原创动作音效。P4作者依据P1原句与已接纳正文创作三张完整场景，按需要为中幅交付独立透明前景；图片交付沿原作者入口执行，背景要求由本模板图纸决定。固定动作与实际正文首镜共用同一展开几何，正文继续由原模板与媒体时钟呈现，不烘焙成片头替身图。正文首镜的预进入预算消费该节目所选交叉模板的时窗；片头标题由正式节目上下文补齐，旁白沿author-bookend原入口合成。

`opposed-opener`独立拥有逐段上下错层对冲、持续运镜、配乐与动作音效。P4作者按P1原文的自然语意设计分段，每段交付一张完整场景；author-bookend沿原配音入口为同一口播取得各段真实卡点。P4依次呈现各段，最后一段蓄力并沿左右原路弹开，露出真实正文首镜；片头时长由实际配音和动作共同决定。创作、素材与时间问题返回原责任方，不修改已有节目选择或其它模板。

`glass-opener`是独立可选的玻璃错层片头，沿原逐段创作及配音卡点入口，一段一图、一次对冲。模板拥有裂成上下两块的玻璃材质和分开运镜，动作音效与配乐沿用`opposed-opener`；最后一段蓄力后沿左右原路弹开，进入真实正文。配音原速完整保留，未指定时仍选择`opposed-opener`。

片头Template在片头内触发的音效可自然延续到正文，由原音轨与共享混音链消费；旁白、配乐及正文开始时间不随尾音改变。

#### 剧情视频设计与返工

- `author-video`与片头创作并行调用固定的`cinematic-video`剧情视频Template，审查已接纳正文中的连续完整全画幅Beat，交付`video-plan.yaml`。Template拥有高潮优先的全画幅选段、多镜头设计、前后接镜、单首图与必要接续安排及正文呈现；author-video通过原Visual插槽取得节目已选正片画风，供镜头和提示词创作。Module只拥有任务编排、候选提交和返回。设计不改写P3故事板，不占用讲解`templateRuns`，不改变字幕和旁白时间；`video-plan`是P4视频接管范围与镜头的唯一真源。P4像消费讲解连续段一样把成员合为一个视频片段，成员的原全画幅图片、相机、动作绑定和解说框不再执行。生成分段按所用模型的单次容量沿自然动作交接安排，镜头切换不产生独立首图；来源事实不足保持原正文。作者交付面向模型的场面表达及本次必要限制；完整Visual与事实边界供作者设计和接纳使用，动态请求沿首图或前次视频保持画风，不再拼入内部制作规范与全段禁令。

- 用户明确要求重做已接纳的视频设计时，System Control通过`next --stage p4 --revise-video`沿原video节点重新签发工作单，由同一Template从当前正文重新划段与设计。发起前须无冲突的进行中工作单；进行中的原video返工沿普通next续跑。新候选接纳前保留原设计，接纳后仅通知实际受影响的素材与成片消费者；P3、音频字幕、独立片头和P1发布内容保持各自交付，不自动执行视频生成或P4或再次付费。

#### 剧情视频生产与技术交付

`produce-video-assets`程序拥有唯一候选初始化、原节点续接、来源恢复、按既定时长剪接及完整clip归集；AI推进已授权生产和技术交付。原恢复程序对明确排队或生成的同一对象有界等待，在远端未知、失败或等待期限处交回，不因轮询扩大付费授权。已接纳video-plan为空时，原video-assets节点直接执行本包确定性入口并交付同一video-manifest，不签发AI工作单；有段任务仍由当前模型推进原生产入口并经原accept接纳。交付实际改变时沿原程序收口通知P4。

`produce-video-assets`的供应商调用由包内即梦画布CLI组件承担。原生产目录保存本集画布和每次生成的公开节点、上传资源及稳定提交身份；画布供查看和续作，不替代已接纳设计、唯一候选或正式视频交付。首组读取唯一首图，后组由原video-plan的可选connection表达接续或切镜及剪后参考理由，默认直接引用前组成功的原生成节点；只有作者明确要求从剪后结尾继续时才剪定并上传前组。普通链全部生成完成后下载原片，在一次编码中完成各组裁切和规格转换，再归集为原完整clip；按当前目录解析模型并通过报价执行已有付费授权，原对象只读恢复及本地下载沿同一组件完成。P4仍消费原video-manifest及本地MP4。

同一模块的原generate入口提供批次推进全部已选独立视频段的能力：各段当前可执行分次先提交或恢复，再统一有界等待，使独立远端生成重叠；同一段的后组等待前组原生成成功，再沿原节点引用续生；明确的剪后参考例外才等待本地剪定。唯一执行者在原整集锁内顺序维护唯一候选，到完成、未知、故障或等待期限交回各段结果；一段受阻不抹除或阻止其它独立段已授权的推进，不取得重投权。用户明确要求的单段编辑、局部查看和已授权替换仍由原定点入口承担。只有同段分次合为一个clip，各独立clip按原设计窗口交给P4，全部齐备后才接纳。

画面检查归用户。AI不打开源片、抽帧图、整合片或上下文预览，不判断动作、接续和观感，不主动发起质量返工。只有用户另行明确要求看片或编辑时，才由原inspect/apply/preview提供帧位材料、Cue投影与选择写入，沿同一候选及临时目录执行。已有有效cuts和完整视频保留，review不新填，已有真实记录不冒充本次观看。向P4仍交付完整MP4，不新增节点、候选或报告。首次首图使用及技术失败、远端恢复、再次付费沿现有边界处理；不因未看片或旧画面评论阻塞正常交付。正文图片的实图与最终运镜已由P3完成。

produce-video-assets在原片交付、单次编码剪定和新整合视频形成时完成各自首次技术验收。已完成视频恢复、P4接纳及P4消费检查交付文件存在且非空、当前设计与时窗及原分次身份，不重复扫描视频字节或重新探测媒体以防止事后文件替换。首帧与接续输入、真实远端替换链和首次技术失败仍由原生产者处理；观看文字不替代实际素材、剪辑身份或机器接纳证据，缺失或实际不能被渲染器消费的视频仍停止交付。

#### 剧情视频恢复、接入与定点重生

用户明确要求接入已经完成的外部视频时，produce-video-assets原generate入口读取实际提交记录，查询并恢复同一远端对象，在原生产回执保存真实请求及经批准编辑的首图来源。video-manifest可随clip交付实际首图与原AR001的关系；原作者的图片交付不被冒充改写。接入不提交生成、不取得再次付费权限，不改变设计、分次、取材、剪辑、正式接纳及P4消费完整视频的路线。

当前`video-assets`工作单内，用户明确授权重生后，`produce-video-assets/generate.mjs --regenerate-from <原分次请求摘要>`只替换同一设计下的一次生成。已知编号但结果未知的请求，按用户明确授权使用同一定点入口及再次付费标记；AGENTS中已授予的同类提交超时一次重试许可无需逐次询问，其余未知替换仍须具体批准。没有编号仍停止。原回执、原状态及媒体保留，替换关系由该包原生产回执保存；重复命令恢复同一次替换，不新开付费，旧请求迟到的结果不覆盖替换交付。接续请求绑定实际引用的前组原生成对象或剪定视频及原任务；前组重生影响其真实续接，剪辑改变只影响实际使用剪后参考的续接，不能自动再次付费。其它剧情段有效结果保留。接纳只读取当前替换链的交付。该入口不签发新工作单、不改变已接纳设计或图片，不自动修改已完成阶段或发布。

#### 成片与预览

HyperFrames Studio是同一渲染投影的交互预览入口，提供源码直接播放、正式旁白、字幕、定位与时间轴。整集、连续Beat、正文及片头窗口共用正式计划，不重编业务时间。P3候选默认直接播放，明确要求时才导出视频或静帧；P4仍沿原收尾边界。Studio编辑临时项目不代替正式候选，正式设计修订仍回所属模板作者。Studio不是Workflow节点，启动预览不写正式P4成果或接纳回执。

非HY的本地媒体处理继续复用render-video的进程监督与资源队列。HyperFrames拥有预演、捕获、原生导出及其缩略图、音频分析等任务的默认执行与生命周期；项目不覆写HY运行默认，不以自有进程采样、任务队列、媒体命令替身或导出工作进程接管它。Studio按输入版本保留准备目录，正文、片头窗口只依赖实际消费的已交付内容；项目继续拥有正式内容编译、子场景时间投影及最终音频封装。HY的执行失败沿原render-video入口返回，临时编辑不回写正式创作。

`render-video/runtime/plan.mjs`拥有渲染输入加载与计划构造，同目录`render-contracts.mjs`拥有计划直接消费的素材、时间表和输出合同校验；两者继承render-video责任，Studio与正式渲染继续消费同一计划入口。`compile.mjs`将该计划编译为HyperFrames主画布与模板子场景；模板renderer拥有场景建立、指定时刻求值及释放，公共字体、媒体、字幕与浏览器生命周期归render-video。原Cue轴同时驱动画面与音频；同一PCM混音供预览和最终封装，P4只在完整交付时编码音频。HyperFrames分段捕获与恢复属于渲染内部，不新增逐段正式成果或工作流节点。

全画幅作者在同一候选用相机入口查看实图路线及必要运动片段；讲解候选预演沿模板原入口。各预览复用正式计时与Renderer，不建立临时素材清单或另一条生成路线。

#### 正文视频、转场与音画衔接


`cinematic-video`在同一渲染计划中将选定连续Beat投影为一个正文模板片段，参加现有提前进入、退出和片尾转场；视频只有一个连续播放源，不在成员Beat边界重新开始。正文叙事转场消费视频首尾保留的真实连续活动，正文有效动作仍在原Cue窗口播放，保持原字幕与旁白；共享接缝时钟把段间Cue空隙计入前镜头退出，素材首组、末组的真实活动时窗由原视频设计、取材与交付链共同承接。视频交付时长按同源正文、段间时间和余量计算，由原接纳核对精确帧数。片头引用及讲解背景按正文偏移取得原有时刻。有效视频片段在成员全画幅渲染之前建立，不调用其A/B、相机、动作或注释布局；首图只由P4视频生产消费，P4直接读取视频交付。成员解说框取消，未覆盖前文已显示的框沿原生命周期结束。既有片头引用只解引用到原请求的Cue时刻，取实际视频定格，不调用原全画幅方法或补生原图；后续讲解背景继承实际播放的视频末态。Studio与成片读取同一正式视频交付，缺失或无效视频阻止交付。实际视频设计或文件变化只通知相应首帧、视频和渲染消费者，规则摘要变化不触发再次生成。

全画幅叙事画面之间的转场以相邻实际播放画面A→B为单位，由进入一侧保存一次，只允许叠化与闪黑；同Beat A→B及跨Beat共用语义方法和呈现。P3全画幅作者依据前后正式字幕、口播、观看职责及导演节奏，在原创作与复核中选择承接或收束再起。P4的cinematic-video替换全画幅后，只拥有实际改变的全画幅媒体外侧接缝；被覆盖成员内部不执行图片转场，也不回写P3。讲解段的进入、退出及讲解互接归vox-explainer原专用进出链，讲解作者不交通用叙事转场，讲解后的全画幅顶层入场为空；片头内部及正文入场归原片头模板。render-video按实际模板邻接分别执行全画幅作者选择或模板专用进出，不按关键词选型、不默认补叠化。全画幅边界固定活动余量独立于两种效果，原Cue轴、字幕、旁白和视频有效动作时间不移动。无新增作者、正式包、Feature或节点。转场参数不进入图片或视频生产投影，实际场面、镜头或提示改变仍通知真实生产消费者。共享AssetMedia由HyperFrames原生媒体统一读取视频，Studio、小样与成片使用同一实现；视频定格来自同一素材与取样时刻，FFmpeg负责素材加工和最终封装。

所有片头Template都必须交付一个非零的正文入场转场，使首个正文画面在片头遮挡或退出动作下预进入；`render-video`从该真实转场解析正文预进入窗口。启用`background-music`时，正文BGM在不早于该窗口且不超过自身淡入时长的范围内先于正文旁白开始渐入；正文旁白、字幕和Cue仍保持正式正文时间原点，片头Template不得改写。没有片头或没有正文BGM时不建立这项音画重叠。

#### 解说框、字幕与运镜交付

全画幅解说框由Template的callout包内组件统一拥有触发、内容、取证、生命周期、版式与注释显示；模板根编排其与相机及cue-sync。框身份不决定播放顺序，cue-sync按真实字幕时间整理绑定，Template分别约束具有专业前后依赖的动作。解说框按各自绑定和固定生命周期生成独立注释层，可跨Beat持续显示；时间重叠不构成拒绝或排队依据。render-video在全局时间线形成后调用同一Template的定位能力，消费框完整显示期间各张全画幅的相机几何，为新框避开尚未离场的框；已显示框的位置和各框时间保持不变。取景几何不冒充实图主体识别，也不证明其它模板或实际视频内容的遮挡安全；P3落实原画面构图与运镜，不检查字幕或解说框对实图内容的遮挡。渲染消费者报告实际候选位置冲突，不把有限候选无解当成任意位置都无法承载，不删除正文应有内容。

字幕显示继承render-video责任：固定排版由包内caption-style资源唯一提供，CaptionLayer执行显示；Visual提供字幕字体文件、完整字体描述和显示配色，System Control原样投影其字体属性供同源预览与成片消费。P2继续拥有字幕文字、分句和时间；其原inspect由程序读取当前节目Visual字体，调用render-video的同源字幕组件与测量能力，向作者提供实际折行及溢出结果。作者据此选择语义断点，不复制P4显示容量数值作为作者规则。

全画幅每图的方向、运动方式与速度变化由P3在原联合设计中确定并随motion交付，实图落实和P4呈现沿用同一选择；整个实际运镜窗口持续运动，速度保留下限且不设统一上限，初始预算不预定具体速度。行程不足由P3联合调整构图、取景与路线，不以停镜填充时窗。该速度只影响运行行程与实际取景，不进入静态图片生产投影；画面、构图和路线的实际变化仍由原素材消费者处理。范围与计算由模板合同及相机组件拥有，不增加工作流步骤或后置选速。

### P1文案、封面及成片交付

#### P1作者交付

P1的两个互斥作者Module统一拥有正文、片头、三平台文案与横竖封面构思。解说在三路成稿前共同交接平台调查与所选Cover，每路一次交齐完整方案，择优后直接进入事实核对；纪录片仍在正文与片头选定后由原作者同会话补齐发布内容。结果都随唯一候选接纳；创作、整稿选择与事实核对沿上文P1及各作者包方法。AGY是全部文字和封面构思的唯一作者，Codex负责材料、必要平台调查、整稿选择与事实核对，不代写、拼改或润色。两类节目保留各自故事、取材、重构与纠错方法。

author-narration拥有两类作者共用的发布内容方法与确定性交接资源。平台方法拥有内容理解、调查、表达、标签与作者收束；封面方法拥有本集可见文字及场面语义。平台标题、封面与简介各自承担观看入口和检索信息；YouTube标题不强制话题尾缀，相关可见话题按需放简介末尾；后台tags与可见话题分别承担检索用途。解说普通／full的三路作者共读当前作者任务、平台调查、发布方法及所选片头与Cover资源；纪录片仍在选定后读取发布方法与所选Cover。供应商参数、生成代码及未选资源不成为AGY输入。调查直接用于当次创作，不增加独立调查成果、热词库或候选池；Codex按实际平台、受众和调查目的直接选择搜索结果并打开原页核对，AGY据此创作文案。

同一候选含正文、片头与publication。Engine分别接纳为原正文文件、原片头文件和`制作/p1/release-main/publication.yaml`，并在同一接纳事务导出`output/publication.txt`；局部文案修订保持正文及其生产记录，不重做P2。发布文案不会混入TTS。发布内容定点修订沿现行P1原作者会话与固定材料执行，逐字锁定正文和片头；正文与片头修订共用发布内容交接和一次事实核对，只修实际受影响的内容，未改交付保留。

#### 封面职责与交付

P1的独立程序Module `produce-covers`直接消费已接纳publication，拥有横竖两张完整封面的生成、恢复、交付与回执；回执只登记两张图片；publication.txt由作者接纳事务独立交付。它不创作文案，也不重写publication.txt。P1阶段授权包含首次必要横竖双封面。原模块装配当前完整提示与参考，Director同批并发调用自带imagegen工具，工具结果交回原模块做技术归一与回执交付。双图齐备才算P1完成；技术完成不冒充用户满意。用户另行明确开始P2时仍只消费正式正文。

`program.yaml#seriesTitle`是系列展示名唯一真源，由P0投影给P1作者。P1按本集观看理由分别选择横竖封面的文字和场面，可用短语或短句，不强制系列名、集号或A/B分段；需要系列识别时沿用正式系列名，不另造第二个系列身份。横竖表达同一内容承诺，允许分别措辞；每幅可见原字按阅读顺序交付，生成器不自动补字。已有成图的局部编辑保留未获准改变的文字与布局。Cover唯一拥有文字层级、材质、配色、版式、安全区及配图的视觉强弱，样图提供文字优先的图文关系，不提供本集事实、场面或字体；Visual的cover-image提供人物、器物和环境画法，并提供该包封面字体与字形约束。封面生成、换字和字体修正均消费同一字体投影，Cover参考控制文字呈现、版式及配图的明暗对比和细节分配，不覆盖Visual画法与字体。生成器分别装配两类参考，按已接纳原文与构思完整图文生成，不生产底图后叠字，也不裁切双槽母图。字符、画幅、提示词和恢复细节归作者合同、Cover及produce-covers，不在本图复制。

#### 文案、封面修订与恢复

System Control原next支持P1文案、封面内容或两者联合修订；联合修订一次签发、一次原作者创作与接纳，不串行两张局部单。点名平台字段或visibleText时只改所选字段，程序继承锁定内容；已成图换字通过coverTextEdit绑定当前图，只编辑文字，保留场景、构图与画法。尚未成图时修正构思，不虚构源图绑定；纯平台文案变化沿coverReuse免费复用已交付图片。各画幅仅按真实内容、实际包选择和明确返工身份处理变化，规则摘要变化本身不触发生图。

原封面恢复能力归produce-covers：自带工具已开始但结果未交回时，只找回同次工具结果，不重复调用。一个画幅未知仍保存另一幅实际结果，全部待交付图片通过原技术检查后才替换正式图片并收口回执。用户明确要求替换失败或未知记录时，新对象沿自带生图交接，保留原记录和有效另一幅。旧供应商回执只供真实来源核对；历史API调用只保留原结果导入与来源核验，不再提供提交入口。明确接受原封面并取消待办重生时，只清理原请求，保留正式成果与远端证据。

Cover登记的finalExample仍可在用户明确选择后沿P1原作者内容修订对齐visibleText，再由produce-covers本地规格化交付双图及package-example回执；不调用远端、不付费、不伪造未知任务成功。所选包、版本、样图身份及原文必须与当前装配一致。技术交付只证明文件、尺寸、摘要和任务合同；完成后不安排例行视觉验收或主动重生，也不转移给P4，用户明确要求查看或修改时再执行。

用户明确指定本地横竖成图时，System Control在原P1封面内容修订入口固定实际文件、摘要和可见文字，交给原作者同步封面内容，保留正文、片头和平台文案。produce-covers沿原节点本地规格化双图，在原cover-receipt如实记为user-provided来源；不增加Workflow节点、正式成果或远端副作用。

#### 开源制作终点与本机发布

开源Video Workflow以P4的render节点交付final.mp4结束，没有P5、publish-platform节点或publish命令。P1文案与双封面仍是本集的独立内容交付，可交给仓库外的个人video-publish Skill。该Skill只发布既有成片，不负责压片；原账号、单次提交、未知结果恢复和回执边界由私有工具拥有，不在公开制作系统重复实现。System Control仅在P1返工前只读该工具的原发布状态，以保留已提交、未知和已发布交付；没有该状态不妨碍正常制作，不要求安装个人Skill。

## 六、装配与资源选择

### 装配与资源角色

模块通过清单声明插槽；模板、功能和视觉包通过`implements`接入真实消费者。Engine只从正式清单、Workflow和节目当前选择生成`resolvedAssembly`。

资源按消费者最小披露：公共Module输入只含所有实现都成立的内容；Template／Feature私有上下文只投递给当前所选包。`copyRules / authorRules / assetContractRules / renderRules`分别服务直接消费者；图片合同入口由当前作者的图片交接程序和渲染消费者调用；实图及最终相机保存在原作者结果中，Studio与P4直接消费。确定性入口不把源码正文展开给人工智能。Schema可以作为结果合同投递；Validator只向工作单保留登记身份与摘要并由Engine执行，人工智能入口不得要求阅读其源码。

### 作者上下文与确定性补齐

P3/P4 的 AI 只交专业创作与选择；原接纳链先调用当前责任方 Validator 的可选 `completeCandidate`，从正式输入补齐确定字段，再按原合同校验并投影。Author 拥有按当前素材来源和作者单位 Cue 派生修辞禁造边界的语义投影；原作者图片入口消费该投影，将已有 Understanding 边界合入生产请求，不写回作者候选或正式设计。引文的来源判断归作者，实际取得的来源正文、原始查询、来源标题与摘要由程序绑定；不以返回表格格式或文字差异代替语义判断。Understanding 的来源身份由生产记录承担，不另输出口播哈希。片头实际消费的原句或标题由所选模板补齐；纪录片原句只留在创作输入。P1发布内容局部返工的未改基线与封面复用身份由原作者模块补齐，保持已有接纳与真实下游复用关系。

Author任务视图对现行规则和合同只投递原文件路径与摘要，作者在首次使用、资源变化或上下文缺失时完整读取原文；模型任务视图省略仅供程序使用的资源描述，签发工作单保持完整。全画幅上下文资源只对作者明确仍完整持有的同版全片及前序参考省略副本，变化与新增材料完整投递，恢复从原视图取得全文；不建立持久阅读记录或第二输入。全画幅的解说框组件形成判断、取证和内容，模板根调用`cue-sync`并统一校验、锁定完整结果。上一末张的观看任务与场景原文由现有上下文投影只读提供，场景是否延续由当前作者结合首张设计判断，程序不以时空文字相等代替语义判断。同场景依赖绑定实际读取的末张场景；相机参考由模板现行上下文入口读取并核对原工作单的前序身份，不要求候选先锁定骨架，也不另写披露记录。合法返工直接修改同一完整候选，由原测量及解说框入口确认实际修改和仍有效的内容。

author-beat的原B2提交由包内`submit.mjs`执行当前候选Preflight并返回交付路径；主代理沿Engine串行Accept、Status，成功接纳后结束使用本章作者，再按P3分工为下一章新建独立上下文作者。全画幅与讲解共用此链，最多三章并行，公开命令、Workflow、候选和失败归属不变。

### 教材投递

开源教材只登记现行源码、说明、图例及实际需要的输入资源，不登记成品视频或生图调用记录。动态预览由已有示例构建入口在本机生成；原视频只留本机，不成为公开装配依赖。开发决策与旧交接档案原样留在本机，不进入公开跟踪或安装。

Template在既有`examples`角色登记作者教学材料，System Control只交付已选Template的现行教材路径，不为装配读取教材正文或图片计算SHA-256，也不把教材摘要列入成果的规则记录。教材维护由现有能力保护边界负责；作者在方法点名处按需读取图文，已签发P3工作单通过原任务视图取得同一已选Template的现行教材目录。教材可引用已有共享能力所有者的图例；共享图片由所有者在`runtimeResources`登记，装载只保留路径与字节摘要，不解码为规则正文。教学图片不自动交给素材生成；例子服务方法，不提供节目事实或替代正式样式真源。

P3作者视图可把同一Template教材目录表达为共同base与完整相对文件列表；展开后仍是原现行清单的全部路径，正式工作单和程序资源合同不变。

### 装配失败边界

硬边界：

1. 未选择包不得进入工作单、摘要或运行时；P0选择目录只能取得必要的最小描述。
2. 插槽为空、基数错误、版本不符或实现不存在时失败。
3. Workflow不保存包目录；静态装配不成为第二份业务依赖图。
4. 包内字段、参数和行为由包清单、合同、校验器和消费者拥有。

### 节目级选择

`program.yaml#visualPackage`是由Visual提供的节目画风选择唯一真源；vox-explainer的画风由本包画法、插画参考及地图样式确定，本段实际颜色与字体由treatment.appearance交付。`request.yaml#visualPackage`只是P0偏好。

`program.yaml#coverPackage`是封面设计组合选择唯一真源；`request.yaml#coverPackage`也只是P0首次偏好。P0分别从当前Visual与实现横版插槽的Cover目录选择，两者不能互相代替。P1作者与produce-covers的`cover-design`插槽消费节目选择；`vertical-cover-design`通过`program-cover-vertical`消费所选Cover清单的`verticalCoverPackageId`，供抖音和小红书共用，不增加P0选择字段。封面目录统一为`type-first-editorial`，同包拥有横竖设计并声明配对自身，按画幅使用所登记样图；各题材共用文字优先、满幅暗色配图的设计关系，画法与字体继续接各自Visual。本集可见文字由P1作者拥有，皮肤不补写系列信息。撤下的旧包不保留别名或自动迁移；旧节目要使用现行封面包时沿正式P0修订选择，维护不直接改写节目或重生已交付封面。更换节目Cover只影响尚需按新设计生产且实际选择改变的封面，不重做平台文字、正片分镜、素材或成片；已交付封面不因规则摘要变化自动失效，只有节目实际选择变化或用户明确返工才沿P1封面入口处理。

`program.yaml#openerTemplate`是节目级片头选择唯一真源，与节目形式独立；P0从正式片头包清单取得最小选择目录，首次策划没有用户指定时选择`opposed-opener`，`episode-opener`、`documentary-opener`、`crossfire-opener`和`glass-opener`继续作为可选片头，均可用于纪录片或解说。委托中的`openerTemplate`只用于首次选择，后续通过现有P0修订接纳节目配置；未明确更换时保留现行选择。P1的片头文案插槽与P4的片头作者插槽消费同一节目选择，P4继续消费已接纳模板结果。更换只影响实际不再满足当前模板的片头与其素材、渲染消费者，不因选择变化重做正文、配音或正文画面；已有片头文字仍满足当前合同则保留，否则由现有P1片头定点返工处理。

Director从正文目录选择`fullframe-narrative / vox-explainer`；Author、Compile与Render只装入实际所选模板，旧合同不兼容、不迁移。

## 七、版本、失效与外部副作用

讲解旁图由各自Template在P3同一treatment内交付设计、必要实图与编排，P4通过原Renderer直接消费；不另交素材计划或图片清单。整屏标题、摆放与出现时序仍由同一treatment交付，这些显示变化不使未改图片失效。图片有效性以保存的实际绘图输入、外观和实际引用原图为依据；来源编号本身及方法代码摘要不触发重生。图片准备、接纳与渲染投影共同消费Author已有的修辞边界派生，渲染只投递当前图件真正继承的要求，不展开整份Understanding，也不写回正式作者设计。无实际消费者的地理引用字段退出，来源登记及对象原图仍由原来源与图片入口承担。图片或设计修订返回原P3作者，只重做实际失效部分并保留有效交付；恢复、付费与阶段权限仍按原规则执行。没有图片需求时保留空的图片蓝图数组，纯矢量进入同一渲染消费者。

剧情视频接镜设计实际消费成员画面及紧邻正文画面的场景、构图与时序；这些业务内容或邻接讲解运行组发生变化，由System Control沿原p4/video请求交回设计责任方复核。视频从正文首Beat开始时，实际片头设计变化同样通知接镜复核。远处独立画面和单纯生产摘要变化不扩大视频返工。

原video返工工作单由System Control通过已有video-plan读取角色投递当前正式方案，author-video与cinematic-video据当前输入和返工范围续作，只修实际失效部分。首次创作和完整阶段重跑不以旧方案作为基线；明确重新划段仍执行V1。返工基线不代表本次已接纳，视频生成仍等待原video接纳；方案未改的生产内容保留有效素材和视频，不因复核重新生成。

人工智能工作单保留签发时输入、规则、装配、合同和写入范围的完整快照。各阶段运行期间获准的系统修复可在协调停止执行后直接修改当前工作区；执行者按当前正式规则继续，原快照只记录签发身份，不覆盖新规则。同一业务任务的next和Accept保留原工作单、候选及步骤锁；只有真实业务输入、选择、写入范围变化或现行合同证明成果不合格时才处理实际受影响部分，不因开发改动自动重签、清空或整集重跑。真实上游输入变化使未接纳工作不再适用时，原工作单、候选保存在该阶段`_work/held-work/`，临时目录保留，再签发当前任务；只有实际输入、选择与写入范围仍匹配的保留工作才能恢复。代码摘要变化本身不代表节目污染或授权失效；只看用户业务输入、生产目标、阶段、实际选择和远端对象是否真实变化。

正式接纳只表示当前版本可用，不表示冻结。明确修订只处理真实受到业务内容或实际选择变化影响的消费者；不自动删除、重做、付费或发布。同级独立区块不扩大范围，有问题的部分经原责任方修正。正文接纳分别比较片头实际引用与进入方向、素材编译输入、成片投影及下一作者实际读取的承接状态，按对应消费者产生原有返工请求；单纯弹窗修改不通知素材或相邻相机作者。

P3失效沿真实读取关系传播：Understanding影响Director；Director的`albumPlan.intent / openingState / progression / endingState`变化影响全部正文作者，`recurringElements`只影响实际引用所变元素的Beat或运行组，Beat合同、模板归属和运行组变化只影响真实读取它们的作者单元与功能。片头只绑定`albumPlan.intent / openingState`、首Beat和其`bodyRefs`实际引用的正文结果。正文变化使当前单元自己的媒体交付与P4投影失效；相邻Author只在其结果明确声明`continue / motivated-reverse / visual-match`读取上一相机状态，或其物理连续性实际读取上一时空、主体、道具末态时失效。`reset`且没有物理继承的下一单元不因上一相机变化失效；更远结果只在中间业务结果真实改变并继续声明读取关系时传播，不能按正文位置全尾连坐。未修改成果保留原内容和记录，不为了通过状态查询换写生产身份；已有结果的哈希或规则差异不触发自动返工。

## 八、维护与证据边界

治理程序检查明确登记的机械关系，不按资源扩展名或文件名推断专业职责；职责归属由维护者结合实际内容和消费者判断。

维护停止与整改授权由[治理入口](ai-responsibility/README.md)规定：只暂停依赖阻塞条件的操作，同一任务内仍有效的具体批准无需重复取得。受保护能力的特定授权、有效义务保全及失效义务取消由[能力保护标准](ai-responsibility/capability-protection.md)唯一规定；笼统整理、相邻授权或机械放行不取得改变能力的权限。

System Control通过`AGENTS.md`规定测试维护授权：已授权功能修复包含直接受影响的既有测试同步更新；既有证据不足以关闭具体故障时，最小必要的回归测试也在授权内。无关测试扩张或新增生产检查仍须单独批准，不得为通过检查削弱故障检测。

人工智能责任包的维护由实际模型消费关系触发，唯一入口是`development/ai-responsibility/README.md`。该入口按任务路由责任包合同、内部流程、内部能力、成熟能力保护和验证标准；本图不复制维护方法。System Control的`development/documentary-design.md`向纪录片P0/P1维护者解释该路线的创作理念与取舍，由AGENTS按任务引入，不作为生产作者输入或第二执行合同。

开放判断的复核责任由现行Workflow与责任包拥有，维护标准不得据此另设复核者；验证标准按实际执行义务变化确定证据要求，不因文件形式替代行为判断。

跨模板选段方法唯一位于`packages/modules/direct-episode/references/template-selection-method.md`，由Director拥有；vox-explainer统一拥有讲解、空间局势与军事推演的专业创作能力和目录说明。能力扩展先于适用范围开放，维护顺序唯一由人工智能责任包[专项维护规则](ai-responsibility/template-capability-protection.md#讲解能力与适用判定的配套维护)规定，不另设生产步骤或能力注册表。

结构不变的包内维护不修改本图；改变身份、位置、责任方、消费者、真源、公共接口、Workflow、失效或授权边界时，必须先按`AGENTS.md`写明目标结构并获准，再施工和验证。
