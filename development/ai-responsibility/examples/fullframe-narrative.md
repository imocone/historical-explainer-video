# 经典案例：全画幅责任包

本案例说明全画幅怎样联合创作，又怎样保留真实交接边界。执行规则只见[模板根](../../../packages/templates/fullframe-narrative/AUTHOR.md)及其方法、合同和消费者，不以本案例建立第二套流程。

## 从真实依赖决定边界

```text
当前口播、导演安排、来源及相邻镜头参考
→ 联合形成场面、构图、Cue、运镜与转场，测量并复核
→ P3当前作者取得实图并落实最终镜头
→ 根据定稿画面完成解说框与显示Cue
→ author-beat预检及接纳
→ P4呈现
```

人物调度、机位、构图和运动互相影响，观看职责与合法Cue也可能在创作中调整，所以这些内容在同一候选里共同形成，不先锁一个不许动的骨架。理解先于手法，是作者的思考方法，不因此增加一次程序交付。

解说框的锚点、出现时刻与位置依赖定稿画面，仍由后续组件完成。取得真实图片后，当前作者必须落实实图判断；设计成立不能代替成图验收。整片收尾检查连续表达和实际相邻关系，未变局部沿用逐图复核。

## 同一候选支持局部修改

模板根拥有最终`treatment + featureResults`、编排与失败处置。修改画面时可以保留框内容和Cue，测量入口接受完整候选；作者核对实际影响，只改失效部分。最终设计锁与解说框锁仍绑定当前结果，刷新原锁不要求重新创作有效内容。来源、时序和几何失败仍回真实责任方，不以简化流程放松合同。

上一镜参考通过现行任务视图直接提供。模板上下文入口从正式前序恢复相机并核对工作单记录的身份，不改写签发工作单，也不另存披露回执。参考不能扩大当前来源、观看任务或写入权限；相邻物理连续性和相机依赖仍按原实际选择核验。

## 方法、程序与组件各做什么

| 对象 | 责任及直接消费者 |
|---|---|
| 场面、观看规划、构图方法 | 帮作者形成同一联合设计；分文件用于按需学习，不代表独立交付步骤 |
| `camera/`组件 | 拥有相机方法、测量、接镜及运行时，由模板根与P4消费 |
| `callout/`组件 | 拥有触发判断、取证、内容、生命周期和定位，由模板根编排并交渲染消费 |
| 测量、锁及几何程序 | 计算或确认已定输入，不代替作者判断画面表达 |
| `fullframe-narrative`模板 | 正式包，拥有创作结果、接纳、失效及跨阶段交接 |

组件不能改排父流程、驱动兄弟组件或自行接纳整包。方法独立存放也不因此升级成组件或正式包。

维护时沿上述链路核对有效义务和失败返回，按[能力保护](../capability-protection.md)与[验证标准](../verification.md)证明保全。边界来自真实输入和消费者，不来自固定步数、文件数量或锁数量；结构接通、入口实跑和正式作品的观看质量须分别说明。
